**Deterministic Password** پاس ورڈ صرف محفوظ ہی نہیں کرتا بلکہ ان کا حساب لگاتا ہے۔ کسی سائٹ کا
پاس ورڈ آپ کے ماسٹر پاس ورڈ، سائٹ، صارف نام اور ورژن نمبر سے Argon2id اور HMAC-SHA-256 کے ذریعے
اخذ کیا جاتا ہے۔ اگر ڈیٹا بیس فائل کھو جائے تو وہی معلومات کسی بھی کمپیوٹر پر دوبارہ وہی پاس ورڈ
دیتی ہیں — فائل کھونا اب ڈراؤنا نہیں رہا۔ کسی سائٹ کا پاس ورڈ بدلنے کے لیے ورژن بڑھا دیں۔ یہ کیسے
کام کرتا ہے: "[اخذ شدہ پاس ورڈ](#اخذ-شدہ-پاس-ورڈ)"۔

ساتھ ہی یہ KeePass کا ایک مکمل پاس ورڈ مینیجر بھی ہے: یہ عام `.kdbx` فائلیں (KDBX 4، AES-256،
Argon2id) کھولتا، ان میں ترمیم کرتا اور انہیں محفوظ کرتا ہے، اس لیے وہی ڈیٹا بیس KeePassXC، KeePass
یا KeeWeb میں بھی کام کرتا رہتا ہے۔ اخذ شدہ پاس ورڈ اندراج میں کسی بھی دوسرے پاس ورڈ کی طرح محفوظ
ہوتا ہے، اور KeePass کی دوسری ایپس بھی اسے اسی طرح دکھاتی ہیں۔

سب کچھ آف لائن کام کرتا ہے: نہ کوئی اکاؤنٹ، نہ کلاؤڈ، نہ کوئی نیٹ ورک درخواست۔ پوری ایپ ایک واحد،
خود مختار HTML فائل ہے؛ ڈیٹا بیس صفحے کی میموری میں ڈی کرپٹ ہوتا ہے اور براہ راست ڈسک پر واپس
محفوظ ہوتا ہے، اور ماسٹر پاس ورڈ کبھی صفحے سے باہر نہیں جاتا۔ یہی صفحہ ایک
[Chrome ایکسٹینشن](#chrome-ایکسٹینشن) بھی ہے جو ساتھ والے ٹیب میں لاگ ان بھرتی ہے —
**[اسے Chrome Web Store سے انسٹال کریں](https://chromewebstore.google.com/detail/hiahfdknjchamepclnokcalkcjcfhahf)**۔

**[آن لائن ورژن](https://password.marketkernel.com/)** — یہی صفحہ
PWA (Progressive Web App) کی صورت میں: اسے سسٹم میں انسٹال کیا جا سکتا ہے، پھر یہ اپنی ونڈو اور
آئیکن کے ساتھ ایک الگ ایپ کی طرح چلتا ہے، اور آف لائن بھی کام کرتا ہے۔ کمپیوٹر پر Chrome، Edge اور
Arc میں ایڈریس بار کا انسٹال بٹن استعمال کریں؛ Android پر Chrome کا ⋮ مینو ← ایپ انسٹال کریں؛ iOS پر،
Safari یا Chrome میں، شیئر ← ہوم اسکرین میں شامل کریں۔ وہاں بھی ڈیٹا بیس آپ کی ڈسک پر ہی رہتا
ہے — دیکھیں "[GitHub Pages](#github-pages)"۔

## استعمال کا طریقہ

1. `build/password-manager.html` بنائیں (دیکھیں "[بلڈ](#بلڈ)") اور اسے براؤزر میں کھولیں —
   براہ راست ڈسک سے کھولنا بھی ٹھیک ہے۔
2. "فائل کھولیں" ← کوئی `.kdbx` ڈیٹا بیس منتخب کریں، یا اسے ونڈو میں گھسیٹ کر لائیں۔
3. ماسٹر پاس ورڈ درج کریں (اور اگر ڈیٹا بیس کی کلیدی فائل ہے تو اسے بھی منتخب کریں) ← "ان لاک کریں"۔

Chrome، Edge اور Arc میں فائل File System Access API کے ذریعے کھلتی ہے: تبدیلیاں اسی فائل میں
واپس لکھی جاتی ہیں — اگر خودکار محفوظ کاری آن ہو تو ہر ترمیم کے ایک لمحے بعد — اور اگلی بار آنے پر
وہی فائل دوبارہ پیش کی جاتی ہے؛ صرف اس کا ہینڈل یاد رکھا جاتا ہے، اس کا مواد یا پاس ورڈ کبھی نہیں۔
Safari اور Firefox میں فائل صرف پڑھنے کے لیے کھلتی ہے، اور "محفوظ کریں" ڈیٹا بیس کی تازہ کاپی
ڈاؤن لوڈ کرتا ہے — اور فونز پر بھی یہی ہوتا ہے: Android پر Chrome میں File System Access نہیں
ہے، اور iOS پر ہر براؤزر، Chrome سمیت، Safari کے انجن پر چلتا ہے۔ iOS پر "محفوظ کریں" اس کے بجائے
کاپی شیئر مینو کو دیتا ہے — دیکھیں "[فون پر](#فون-پر)"۔

"نیا ڈیٹا بیس" ایک خالی KDBX 4 ڈیٹا بیس بناتا ہے جو AES-256 اور Argon2id سے انکرپٹ ہوتا ہے
(64 MiB، 10 پاسز — KeePassXC کی پہلے سے طے شدہ قدریں، براؤزر میں تقریباً آدھا سیکنڈ)۔

### فون پر

900 پکسل چوڑائی تک — یعنی فون پر، یا سیدھا پکڑے ہوئے ٹیبلیٹ پر — صفحہ ایک وقت میں ایک ہی چیز
دکھاتا ہے۔ اندراجات کی فہرست پوری اسکرین بھرتی ہے؛ کسی اندراج پر ٹیپ کرنے سے وہ اپنی الگ اسکرین پر
کھلتا ہے، اور ٹول بار میں ‹، سسٹم کا واپس والا بٹن یا پیچھے کی طرف سوائپ فہرست پر واپس لے آتے ہیں۔
واپس جاتے ہوئے ترمیم برقرار رہتی ہے، جیسے کمپیوٹر پر کوئی دوسرا اندراج منتخب کرنے سے برقرار رہتی
ہے؛ خالی چھوڑا گیا نیا اندراج ہٹا دیا جاتا ہے۔ ☰ گروپس، ٹیگز اور ری سائیکل بن کو فہرست کے اوپر سرکا
لاتا ہے۔ مینو، جنریٹر اور ترتیبات اسکرین کے نیچے سے اوپر آتے ہیں؛ واپس کا بٹن پہلے انہیں بند کرتا ہے،
اور ڈائیلاگ کو منسوخ کرتا ہے۔ جنریٹر، ترتیبات اور لاک ٹول بار کے ⋯ مینو میں ہیں۔

ٹچ اسکرین پر نہ رائٹ کلک ہوتا ہے نہ گھسیٹنا: گروپ کے ساتھ والا ⋯ وہی مینو کھولتا ہے جو کمپیوٹر پر
رائٹ کلک کھولتا ہے، اور اس کا "گروپ میں منتقل کریں…" وہی کام کرتا ہے جو گھسیٹنا کرتا ہے۔ اندراج کا
مینو اندراج کی اسکرین پر اس کا ⋯ ہے۔

فائل صرف پڑھنے کے لیے کھلتی ہے۔ iOS پر "محفوظ کریں" تازہ ڈیٹا بیس شیئر مینو کو دیتا ہے، جہاں
"فائلز میں محفوظ کریں" اسے اصل فائل کی جگہ رکھ سکتا ہے؛ مینو بند کر دینے سے تبدیلیاں غیر محفوظ رہ
جاتی ہیں۔ Android پر Chrome صرف تصاویر، آواز، ویڈیو اور متن شیئر کرتا ہے، اس لیے وہاں "محفوظ کریں"
کاپی ڈاؤن لوڈ کرتا ہے۔

اس سے زیادہ چوڑائی پر، اور ٹیبلیٹ پر، تینوں پین ویسے ہی رہتے ہیں جیسے کمپیوٹر پر؛ کسی بھی سائز کی
ٹچ اسکرین کو بڑے بٹن اور گروپس کے ساتھ ⋯ ملتے ہیں۔

## Chrome ایکسٹینشن

**[Chrome Web Store سے انسٹال کریں](https://chromewebstore.google.com/detail/hiahfdknjchamepclnokcalkcjcfhahf)**

`npm run build` ساتھ ہی `build/extension/` بھی لکھتا ہے: یہی ایپ Chrome ایکسٹینشن کی صورت میں، اور
Chrome Web Store کے لیے اس کی `build/password-manager-extension-<version>.zip`۔ اپنا بنایا ہوا بلڈ
آزمانے کے لیے: `chrome://extensions` → Developer mode → Load unpacked → `build/extension`۔

ٹول بار کا آئیکن ایک مختصر پاپ اپ کھولتا ہے: ٹیب کی سائٹ کے اندراجات، جن میں سے کسی ایک پر کلک
کرنے سے وہ بھر جاتا ہے، اس کا صارف نام، پاس ورڈ یا ون ٹائم کوڈ کاپی کرنے کے بٹن، اور پورے ڈیٹا
بیس میں تلاش۔ اس کے نیچے **مکمل موڈ** ایپ کو Chrome کے سائیڈ پینل میں، صفحے کے ساتھ، کھولتا ہے —
فون والی ترتیب میں، کیونکہ پینل تنگ ہوتا ہے — جہاں یہ ٹیب بدلنے پر بھی کھلی رہتی ہے۔ وہاں سب کچھ
ویسے ہی کام کرتا ہے جیسے فائل میں؛ ایکسٹینشن جو چیز شامل کرتی ہے وہ لاگ ان بھرنا ہے:

- **پاپ اپ** صرف ماسٹر پاس ورڈ سے وہ فائل ان لاک کرتا ہے جو پینل نے آخری بار کھولی تھی: فائلیں اور
  کلیدی فائلیں پینل منتخب کرتا ہے، اور ہر تبدیلی بھی وہی کرتا ہے۔ جس سائٹ کا کوئی اندراج نہ ہو، وہاں
  اس کا **نیا پاس ورڈ** پینل کو جنریٹر پر کھولتا ہے، جیسے مینو میں "بھریں" کرتا ہے۔
- صفحے کے کانٹیکسٹ مینو (صفحے پر یا کسی خانے میں رائٹ کلک) میں **بھریں** ٹیب کی سائٹ کے اندراج کا
  صارف نام اور پاس ورڈ بھرتا ہے — یا سائن ان کے اس مرحلے پر جو ون ٹائم کوڈ مانگے، اس کا ون ٹائم
  کوڈ۔ سائٹ کا ایک ہی اندراج ہو تو یہ فوراً بھر دیتا ہے، پینل کھلا ہو یا نہیں؛ کئی ہوں، کوئی نہ ہو،
  یا ڈیٹا بیس لاک ہو، تو یہ پینل کھولتا ہے تاکہ ایک اندراج منتخب کیا جائے، پاس ورڈ بنایا جائے، یا
  ان لاک کیا جائے — اور پھر وہیں سے آگے بڑھتا ہے۔ دو مرحلوں والا سائن ان (Google، Microsoft) پہلے
  مرحلے پر صارف نام اور دوسرے پر پاس ورڈ لیتا ہے: ٹیب کے لیے منتخب کیا گیا اندراج یاد رکھا جاتا ہے۔
  پینل میں کسی اندراج کا **بھریں** بٹن وہی اندراج ٹیب میں بھر دیتا ہے۔
- پینل بند ہونے پر بھی **ڈیٹا بیس کھلا رہتا ہے**، جب تک لاک نہ ہو: ترتیبات میں مقرر غیر فعالی کے
  وقت کے بعد، جب کمپیوٹر کی اسکرین لاک ہو، پینل سے، پاپ اپ سے، یا ٹول بار آئیکن کے مینو میں
  **لاک کریں** سے۔ دوبارہ کھولنے پر پینل اسے پاس ورڈ کے بغیر سنبھال لیتا ہے، اور پاپ اپ اسے فوراً
  دکھاتا ہے۔
- گروپ پینل کے اوپر **اس سائٹ کے لیے** ٹیب کی سائٹ کے اندراجات دکھاتا ہے، اور فہرست اسی پر کھلتی
  ہے؛ یہ ٹیب کے ساتھ ساتھ بدلتا ہے۔
- **صفحے کے لیے نیا پاس ورڈ۔** جس سائٹ کا کوئی اندراج نہ ہو، وہاں "بھریں" ٹیب کی سائٹ اور صفحے پر
  لکھے صارف نام کے ساتھ "اخذ شدہ v3" جنریٹر کھولتا ہے۔ اس کا "بھریں" بٹن پاس ورڈ بھر دیتا ہے —
  رجسٹریشن فارم کے دونوں خانوں میں — اور اسے ایک عام اندراج کے طور پر رکھ لیتا ہے۔

کوئی اندراج ٹیب کے موافق تب ہوتا ہے جب اس کی ویب سائٹ بالکل ٹیب کی سائٹ ہی ہو: دونوں پتے جنریٹر 3
کے `siteOf()` سے گزرتے ہیں — نہ اسکیم، نہ پورٹ، نہ پاتھ، نہ `www.`، اور IDN پنی کوڈ میں۔ `google.com`
والا اندراج `accounts.google.com` کے موافق نہیں، اور نہ `mail.site.com` والا `site.com` کے۔ `https://`
والا، یا بغیر اسکیم والا اندراج کبھی `http://` صفحے میں نہیں بھرا جاتا: جو سائٹ http پر استعمال ہوتی
ہو، اس کی ویب سائٹ میں `http://` ہونا چاہیے۔ ری سائیکل بن کے اندراجات پیش نہیں کیے جاتے، اور کسی
دوسری سائٹ کے لیے ہاتھ سے منتخب کیا گیا اندراج صرف ایک انتباہ کے بعد بھرا جاتا ہے جس میں دونوں
سائٹوں کے نام ہوتے ہیں۔

**یہ کیسے بنا ہے۔** پینل خود وہی صفحہ ہے: `panel.html`، جس کا اسکرپٹ `panel.js` میں ہے، جیسا کہ
Manifest V3 چاہتا ہے۔ ہر ان لاک اور ہر بار محفوظ کرنے پر یہ فائل اور اس کی کلید — `ProtectedValue`
میں پاس ورڈ، اور کلیدی فائل — ایک offscreen دستاویز کو دیتا ہے، جو انہیں، اور ان سے ڈی کرپٹ کی گئی
ڈیٹا بیس کی صرف پڑھنے والی کاپی کو، لاک ہونے تک میموری میں رکھتی ہے؛ لاک کرنے سے یہ دستاویز بند ہو
جاتی ہے، اور کلید بھی اس کے ساتھ چلی جاتی ہے۔ کہیں کچھ نہیں لکھا جاتا۔ مینو service worker کے پاس
ہیں۔ "بھریں" پر کلک پینل کو صرف تبھی کھول سکتا ہے جب ابھی کسی چیز کا انتظار نہ کیا گیا ہو، اس لیے
worker کو فوراً معلوم ہونا چاہیے کہ وہ بھر سکتا ہے یا نہیں: وہ اندراجات کی ویب سائٹیں — نہ نام، نہ
پاس ورڈ — اپنے پاس رکھتا ہے، جیسے جیسے offscreen دستاویز انہیں بھیجتی ہے، اور offscreen دستاویز
اسے چلتا رکھتی ہے۔ پاپ اپ (`popup.html`، `popup.js`) کچھ بھی ڈی کرپٹ نہیں کرتا: یہ offscreen دستاویز
سے ٹیب کے موافق عنوان اور صارف نام مانگتا ہے، پھر صرف اس ایک اندراج کو جس پر کلک ہوا؛ لاک ہونے کی
صورت میں یہ حالیہ فائل پڑھ کر اسے، پاس ورڈ کے ساتھ، کھولنے کے لیے اسی دستاویز کو دے دیتا ہے۔

**صفحے تک کیا پہنچتا ہے۔**

- صرف وہی جو کلک مانگے، اور صرف ایک اندراج کی قدریں۔ کہیں بھی کوئی content script نہیں چلتا:
  کلک پر `chrome.scripting.executeScript` پہلے ٹیب کے ہر فریم سے پوچھتا ہے کہ وہ کہاں ہے اور اس میں
  لاگ ان کے کون سے خانے ہیں، کوئی قدر بھیجے بغیر؛ پھر صرف اندراج کی سائٹ کے فریموں کو قدریں ملتی
  ہیں، اور فنکشن ٹائپ کرنے سے پہلے اپنا پتہ دوبارہ جانچتا ہے۔ اسی صفحے پر کسی دوسری سائٹ کے فریم کو
  کچھ نہیں ملتا۔
- صرف وہی خانے بھرے جاتے ہیں جو انسان کو نظر آ سکیں: دکھائی دینے والے، فعال، قابل تحریر، کچھ نہ
  کچھ سائز والے، ونڈو کے اندر۔ جال کے طور پر چھپایا گیا خانہ خالی رہتا ہے۔
- قدریں ایکسٹینشن کی isolated world سے سیٹ کی جاتی ہیں، اس setter کو بائی پاس کرتے ہوئے جو صفحہ
  اپنے inputs پر لگائے، اور `input` اور `change` events React، Vue یا Angular کو خبر دیتے ہیں۔
- ماسٹر پاس ورڈ، دوسرے اندراجات اور سائٹوں کی فہرست کبھی کسی صفحے تک نہیں جاتے۔

**اجازتیں۔** ہر سائٹ کے بجائے `activeTab`: آئیکن یا "بھریں" پر کلک ایکسٹینشن کو وہی ایک ٹیب دیتا
ہے۔ اسی لیے پینل پاپ اپ یا مینو سے کھلتا ہے، کبھی Chrome کی اپنی ترتیب (`openPanelOnActionClick`) سے
نہیں: اس طرح کھلے پینل کو کوئی ٹیب ملتا ہی نہیں۔ پینل میں کسی ایسے ٹیب پر "بھریں" جو اسے نہیں دیا
گیا، اندراج کی سائٹ کے لیے ایک بار اجازت مانگتا ہے (`optional_host_permissions`)۔ اوپر والی چیزوں
کے لیے `contextMenus`، `scripting` اور `sidePanel`، دستاویز کے لیے `offscreen`، اسکرین لاک کے لیے
`idle`، اور پینل بند ہونے پر کاپی کیا گیا راز مٹانے کے لیے `clipboardWrite`۔ کوئی
`externally_connectable` نہیں: ایکسٹینشن کے حصے `chrome.runtime` کے ذریعے بات کرتے ہیں، اور ہر حصہ
صرف ایکسٹینشن کے اپنے صفحات سے پیغامات لیتا ہے۔ اس کے صفحات میں `connect-src 'none'` ہے، جیسے فائل
میں؛ بلڈ اس کی جانچ کرتا ہے، اور یہ بھی کہ کسی صفحے میں inline اسکرپٹ یا کوئی بیرونی پتہ نہ ہو۔

فائل سے ایک فرق: دوبارہ کھولنے پر پینل ڈیٹا بیس کو اپنی جگہ پر صرف تب لکھتا ہے جب Chrome اب بھی اس
کی اجازت دے؛ ورنہ اسٹیٹس بار یہ بتاتا ہے، اور پہلی بار "محفوظ کریں" پر اجازت مانگی جاتی ہے۔

## سیکیورٹی

- **صفحے سے کچھ باہر نہیں جاتا۔** فائل میں موجود Content-Security-Policy ہر نیٹ ورک درخواست، فارم
  بھیجنے اور بیرونی وسیلے کو ممنوع کرتی ہے؛ اگر پالیسی غائب ہو جائے یا کوئی بیرونی حوالہ آ جائے تو
  بلڈ ناکام ہو جاتا ہے۔ PWA والی کاپی تین چیزوں کی مزید اجازت دیتی ہے، سب اس کے اپنے origin سے:
  manifest، service worker اور آئیکنز — `connect-src` بدستور `'none'` رہتا ہے۔
- فارمیٹ کا کوڈ [kdbxweb](https://github.com/keeweb/kdbxweb) ہے، وہ لائبریری جس پر KeeWeb بنا ہے؛
  Argon2 کے لیے [hash-wasm](https://github.com/Daninet/hash-wasm) کا WebAssembly ہے، جو فائل میں ہی
  شامل ہے۔
- تحفظ شدہ فیلڈز میموری میں XOR ماسک کے ساتھ رکھی جاتی ہیں (kdbxweb کا `ProtectedValue`) اور اسکرین
  پر تب تک چھپی رہتی ہیں جب تک دکھائی نہ جائیں۔ تلاش کبھی تحفظ شدہ فیلڈز میں نہیں دیکھتی۔
- **کسی بھی زبان میں پاس ورڈ۔** جب براؤزر کسی خانے کو پاس ورڈ کا خانہ سمجھتا ہے، تو macOS Secure
  Input آن کر دیتا ہے اور لاطینی کی بورڈ لے آؤٹ لازمی کر دیتا ہے، اس لیے سیریلک ماسٹر پاس ورڈ ٹائپ
  نہیں ہو سکتا۔ Chrome صرف `type=password` کو ہی پاس ورڈ نہیں سمجھتا بلکہ اندازوں (heuristics) سے ہر
  اس خانے کو بھی جو `-webkit-text-security` سے اسٹائل کیا گیا ہو یا جس میں نقطوں والی قدر ہو — اور
  ایک بار ایسا سمجھ لے تو سمجھتا ہی رہتا ہے۔ یہاں خفیہ خانے ایسا کوئی اشارہ نہیں دیتے: یہ شفاف متن
  والے سادہ text inputs ہیں، اور ان کے اوپر نقطوں کی ایک تہہ بنائی جاتی ہے (monospace فونٹ میں، تاکہ
  کرسر اپنی جگہ رہے)۔ ایک بیج بتاتا ہے کہ چھپا ہوا متن سیریلک (РУС) میں ٹائپ ہو رہا ہے یا لاطینی
  (ENG) میں۔ اس کی قیمت یہ ہے کہ Secure Input، جو کی اسٹروکس کو دوسری ایپس سے بھی چھپاتا ہے، کبھی
  فعال نہیں ہوتا۔
- کاپی کیا گیا راز 30 سیکنڈ بعد اور لاک ہونے پر کلپ بورڈ سے مٹا دیا جاتا ہے۔
- ڈیٹا بیس 15 منٹ غیر فعال رہنے پر، اور `⌘L` پر، لاک ہو جاتا ہے۔ لاک کرنے سے ڈی کرپٹ شدہ ڈیٹا بیس
  میموری سے ہٹ جاتا ہے؛ اگر ایسی غیر محفوظ تبدیلیاں ہوں جو لکھی نہ جا سکیں تو لاک انہیں ضائع کرنے کے
  بجائے انتظار کرتا ہے۔
- اندراجات میں لنکس صرف `http`، `https`، `ftp` اور `mailto` کے لیے، `noopener` کے ساتھ کھلتے ہیں۔
- پاس ورڈ `crypto.getRandomValues` اور rejection sampling سے بنائے جاتے ہیں: ہر حرف کا امکان برابر
  ہوتا ہے۔

## خصوصیات

- **گروپس**: سمیٹنے کے قابل درخت، کانٹیکسٹ مینو سے بنانا، نام تبدیل کرنا اور حذف کرنا، گھسیٹ کر
  منتقل کرنا (اندراجات اور گروپس دونوں)، ایسا پینل جس کا سائز بدلا اور جسے چھپایا جا سکتا ہے (`⌘\`)۔
- **اندراجات**: عنوان، صارف نام، پاس ورڈ، ویب سائٹ، نوٹس، حسب ضرورت فیلڈز (سادہ یا تحفظ شدہ)،
  ٹیگز، میعاد ختم ہونے کی تاریخ، منسلکات۔ عنوان، صارف نام، ویب سائٹ اور تاریخوں کے لحاظ سے ترتیب۔
- **ون ٹائم کوڈ** (TOTP): `otp` فیلڈ سے (`otpauth://` URL یا صرف راز، جیسے KeePassXC اور KeeWeb اسے
  محفوظ کرتے ہیں)، KeePass کی `TimeOtp-*` فیلڈز سے، یا TrayTOTP کی `TOTP Seed` سے۔ SHA-1، SHA-256،
  SHA-512؛ کوڈ الٹی گنتی کے ساتھ تازہ ہوتا ہے۔ ایڈیٹر میں **+ ون ٹائم کوڈ** وہ سیٹ اپ کلید لیتا ہے
  جو سائٹ اپنے QR کوڈ کے ساتھ دکھاتی ہے (یا کوئی `otpauth://` لنک) اور فوراً کوڈ دکھاتا ہے، تاکہ اسے
  سائٹ پر تصدیق کیا جا سکے؛ اکیلی کلید `otpauth://` لنک کی صورت میں محفوظ کی جاتی ہے، اس شکل میں جسے
  KeePassXC پڑھتا ہے۔
- **ترمیم** ایک مسودے پر ہوتی ہے: "محفوظ کریں" پہلے سابقہ حالت کو اندراج کی ہسٹری میں رکھتا ہے، جیسے
  KeePass کرتا ہے؛ "منسوخ کریں" مسودہ رد کر دیتا ہے۔ پرانے ورژن دیکھے اور بحال کیے جا سکتے ہیں۔
- **ری سائیکل بن**: حذف کرنے سے چیز بن میں چلی جاتی ہے؛ وہاں سے — بحال کریں یا مستقل طور پر حذف
  کریں۔
- **تلاش** عنوان، صارف نام، ویب سائٹ، نوٹس، ٹیگز، حسب ضرورت فیلڈز اور منسلکات کے ناموں میں؛ تلاش کے
  ہر لفظ کا ملنا ضروری ہے۔

## اخذ شدہ پاس ورڈ

جنریٹر میں **اخذ شدہ v3** پاس ورڈ کا حساب ان سے لگاتا ہے:

- ڈیٹا بیس کا ماسٹر پاس ورڈ (کلیدی فائل، اگر ہو، شامل نہیں کی جاتی)، یا وہیں لکھا گیا کوئی دوسرا
  پاس ورڈ،
- صارف نام،
- سائٹ — وہ ڈومین جس پر اکاؤنٹ ہے (`https://www.github.com/login` → `github.com`)،
- ورژن — 1، 2، … 2³² − 1 تک؛ "+1" اسی اکاؤنٹ کو نیا پاس ورڈ دیتا ہے۔

یہ چاروں مل کر 32 بائٹ اینٹروپی بناتے ہیں۔ شرائط — لمبائی، حروف کے مجموعے، ملتے جلتے حروف — ان
بائٹس کو صرف حروف کی شکل دیتی ہیں: انہیں بدلنے سے اینٹروپی نہیں بدلتی۔ **استعمال کریں** نتیجے کو
اندراج میں ایک عام محفوظ شدہ پاس ورڈ کے طور پر رکھ دیتا ہے۔ یہ کیسے بنا، اس کا کچھ بھی محفوظ نہیں
کیا جاتا: اندراج کسی بھی دوسرے اندراج جیسا ہوتا ہے، اور KeePass کی دوسری ایپس بھی وہی پاس ورڈ
دکھاتی ہیں۔ اگر فائل کھو جائے تو وہی ماسٹر پاس ورڈ، صارف نام، سائٹ، ورژن اور شرائط کسی بھی مشین پر
وہی پاس ورڈ دیتے ہیں۔ پہلے سے طے شدہ قدریں ہیں: 20 حروف، چاروں حروف کے مجموعے، ملتے جلتے حروف کے
بغیر؛ دوسری شرائط سے بنے پاس ورڈ کے لیے وہ شرائط بھی یاد رکھنی ہوں گی۔

جنریٹر پہلے صارف نام مانگتا ہے — اندراج سے کھولا جائے تو اسی اندراج کا: وہاں جو لکھا جائے وہ فارم
میں بھی نظر آتا ہے — پھر سائٹ؛ دونوں ضروری ہیں، اور ان سے بننے والا پاس ورڈ سب سے نیچے،
**استعمال کریں** کے اوپر ہوتا ہے۔

- جو صارف نام ای میل پتہ ہو وہ اپنی سائٹ خود بتاتا ہے: `test@site.com` سے `site.com` بھر جاتا ہے،
  اور اندراج کی ویب سائٹ جیسی ہے ویسی رہتی ہے — وہ `mail.site.com` بھی ہو سکتی ہے۔ مگر ایک ہی پتہ
  کئی سائٹوں میں سائن ان کرتا ہے، اور جنریٹر خانے کے نیچے یہ بات بتاتا ہے: `test@gmail.com` کے ساتھ
  GitHub کے لیے، اس کے ڈالے ہوئے `gmail.com` کی جگہ `github.com` لکھیں۔
- کسی بھی دوسرے صارف نام کے لیے سائٹ لکھنی پڑتی ہے، اور اندراج سے کھولا جائے تو جو لکھا جائے وہی اس
  کی ویب سائٹ بھی بن جاتا ہے۔ شروع میں اندراج کی موجودہ ویب سائٹ بھری ہوتی ہے۔

سائٹ کے طور پر جو لکھا جائے، اس میں اسکیم، پاتھ، پورٹ اور شروع کا `www.` اہمیت نہیں رکھتے؛ سب ڈومین
اہمیت رکھتا ہے — `login.github.com` اور `github.com` دو الگ سائٹیں ہیں۔ جو سائٹ URL نہ ہو
("میرا بینک") وہ جیسی ہے ویسی استعمال ہوتی ہے۔ ٹول بار سے کھولنے پر جنریٹر اسی طرح کام کرتا ہے، اپنے
الگ خانوں کے ساتھ، اور نتیجہ کاپی کرتا ہے۔

"ڈیٹا بیس کا ماسٹر پاس ورڈ استعمال کریں" ہر بار جنریٹر کھلنے پر نشان زدہ ہوتا ہے۔ کسی دوسرے ماسٹر
پاس ورڈ سے اخذ کرنے کے لیے نشان ہٹائیں؛ وہ پاس ورڈ وہیں لکھا جاتا ہے اور کہیں محفوظ نہیں ہوتا — کسی
دوسرے ڈیٹا بیس میں، یا ماسٹر پاس ورڈ تبدیل ہونے سے پہلے بنایا گیا پاس ورڈ بحال کرنے کے لیے۔ ماسٹر
پاس ورڈ تبدیل کرنے سے فائل میں موجود پاس ورڈ جیسے ہیں ویسے رہتے ہیں؛ صرف وہ مختلف ہوتا ہے جو جنریٹر
اس کے بعد حساب کرے۔

### الگورتھم: جنریٹر 3

نیچے دی گئی ہر چیز منجمد ہے: کسی بھی مستقل قدر کو بدلنے سے اس سے بنا ہر پاس ورڈ دوبارہ حساب کرنا
ناممکن ہو جائے گا۔ مستقبل کا کوئی جنریٹر فہرست میں نئی قسم کے طور پر آئے گا اور اسے ویسا ہی چھوڑ
دے گا۔ کوڈ `src/core/derived.ts` میں ہے؛ `npm test` اسے مقررہ ویکٹرز سے، اور اس تفصیل کی بنیاد پر
Node کے اپنے `crypto` سے لکھے گئے ایک آزاد نفاذ سے جانچتا ہے۔ بنیادی اجزاء معیاری ہیں — SHA-256،
HMAC-SHA-256، Argon2id — اس لیے الگورتھم کسی بھی زبان میں دوبارہ بنایا جا سکتا ہے۔

یہ دو مرحلوں میں چلتا ہے: راز 32 بائٹ اینٹروپی بنتے ہیں، پھر شرائط ان بائٹس سے حروف تراشتی ہیں۔

**مرحلہ 1 — اینٹروپی۔**

1. *ان پٹ کو معمول پر لانا۔* تمام اسٹرنگز UTF-8 میں ہیں۔
   - `site` — سائٹ کے طور پر لکھی گئی چیز کا host: متن کو WHATWG URL کے طور پر پارس کیا جاتا ہے
     (جب متن میں `scheme://` نہ ہو تو آگے `https://` لگایا جاتا ہے): چھوٹے حروف، IDN پنی کوڈ میں، نہ
     پورٹ، نہ صارف نام یا پاس ورڈ، شروع کا `www.` ہٹا دیا جاتا ہے؛ جو متن URL کے طور پر پارس نہ ہو وہ
     جیسا ہے ویسا استعمال ہوتا ہے۔ پھر کناروں سے خالی جگہ ہٹائی جاتی ہے، NFC نارملائز اور چھوٹے
     حروف میں کیا جاتا ہے۔
   - `user` — صارف نام، کناروں سے خالی جگہ ہٹا کر اور NFC نارملائز کر کے؛ حروف کا چھوٹا بڑا ہونا
     برقرار رہتا ہے۔
   - `master` — ماسٹر پاس ورڈ، NFC نارملائز کیا ہوا، کچھ بھی ہٹایا نہیں جاتا۔ ایک حرف کے طور پر لکھا
     گیا "é" اور "e" کے ساتھ جوڑنے والا اعراب، دونوں ایک ہی پاس ورڈ دیتے ہیں۔
2. *سالٹ۔*
   ```
   salt = SHA-256( "html-password-manager/derived/v3" ‖ 0x00
                   ‖ u32be(byte length of site) ‖ site
                   ‖ u32be(byte length of user) ‖ user
                   ‖ u32be(version) )
   ```
   لمبائی کے سابقے `ab` + `c` اور `a` + `bc` کو الگ رکھتے ہیں؛ لیبل ان بائٹس کو انہی ان پٹس کے کسی
   بھی دوسرے استعمال سے الگ رکھتا ہے۔ `u32be` ایک 4 بائٹ کا big-endian عدد صحیح ہے۔
3. *کھینچنا (stretch)۔*
   ```
   entropy = Argon2id(password = master, salt, memory = 64 MiB, passes = 3,
                      lanes = 1, version 0x13, output = 32 bytes)
   ```
   Argon2id ماسٹر پاس ورڈ کے ہر اندازے پر 64 MiB میموری خرچ کرواتا ہے، اور یہی چیز GPUs اور ASICs
   کو سست کرتی ہے۔ چونکہ سائٹ، صارف نام اور ورژن سالٹ میں ہیں، ہر اکاؤنٹ کا اپنا سالٹ ہوتا ہے: کوئی
   جدول پہلے سے حساب نہیں کی جا سکتی، اور ہر اکاؤنٹ پر الگ سے حملہ کرنا پڑتا ہے۔

**مرحلہ 2 — شکل دینا۔** شرائط صرف یہیں استعمال ہوتی ہیں، اس لیے وہ پاس ورڈ کی شکل بدلتی ہیں، اس کے
پیچھے کی اینٹروپی نہیں۔

4. *بے ترتیب بائٹس کی ایک دھار*، جتنی لمبی ضرورت ہو — لمبے پاس ورڈ اور اس کی شفلنگ کے لیے 32 بائٹ
   کافی نہیں:
   ```
   block(i) = HMAC-SHA-256(key = entropy, "hpm-v3-stream" ‖ u32be(i)),  i = 0, 1, 2, …
   ```
5. *n سے کم ایک غیر جانبدار عدد۔* دھار کے اگلے 4 بائٹ big-endian u32 `x` کے طور پر لیں۔ اگر
   `x ≥ 2³² − (2³² mod n)` ہو تو اسے چھوڑ کر اگلا لیں؛ ورنہ نتیجہ `x mod n` ہے۔ (صرف `x mod n`
   حروف تہجی کے شروع والے حصے کو ترجیح دے گا۔)
6. *حروف۔* مجموعے، اسی ترتیب میں، ہر ایک صرف اگر منتخب ہو:
   ```
   A–Z      ABCDEFGHIJKLMNOPQRSTUVWXYZ
   a–z      abcdefghijklmnopqrstuvwxyz
   0–9      0123456789
   symbols  !#$%&*+-=?@^_~.,:;()[]{}<>/|
   ```
   ملتے جلتے حروف کے بغیر، ان میں سے `O 0 o I l 1 |` ہٹا دیے جاتے ہیں۔ پھر:
   ```
   chars = []
   for each chosen set:            chars.push(set[draw(|set|)])      # every set is present
   while |chars| < length:         chars.push(all[draw(|all|)])      # all = the sets joined
   for i = length − 1 down to 1:   j = draw(i + 1); swap chars[i], chars[j]   # Fisher–Yates
   password = chars joined
   ```
   لمبائی 4 سے 128 تک ہے۔ پہلے ہر مجموعے سے ایک حرف لینا ہی اس بات کی ضمانت دیتا ہے کہ "ایک ہندسہ
   ہو" اور "ایک علامت ہو"؛ شفلنگ چھپا دیتی ہے کہ وہ حروف کہاں گئے۔

**ٹیسٹ ویکٹر۔** ماسٹر پاس ورڈ `Тестовый пароль`، سائٹ `https://www.github.com/login`
(`github.com`)، صارف نام `me@example.com`، ورژن 1، پہلے سے طے شدہ شرائط
(20 حروف، چاروں مجموعے، ملتے جلتے حروف کے بغیر):

```
password  A6qVXXF]7<%a)aa<x7*U
```

اسی اینٹروپی سے 12 حروف اور علامات کے بغیر `yaM6VJaJFYUQ` بنتا ہے؛ پہلے سے طے شدہ شرائط کے ساتھ
ورژن 2 سے `3q_bwppbE8P2+ufKr:P6` بنتا ہے۔

### یہ کتنا مضبوط ہے

- اخذ شدہ پاس ورڈ میں زیادہ سے زیادہ 256 بٹس اینٹروپی ہوتی ہے (32 بائٹ)؛ ملتے جلتے حروف کے بغیر
  چاروں مجموعوں سے 20 حروف تقریباً 128 بٹس ہیں۔ عملی طور پر حد ماسٹر پاس ورڈ ہی ہوتا ہے۔
- **اخذ شدہ پاس ورڈ کے کسی بھی طریقے کی کمزوری:** کسی ایک سائٹ سے لیک ہونے والا پاس ورڈ حملہ آور کو
  ماسٹر پاس ورڈ کا آف لائن اندازہ لگانے دیتا ہے، کیونکہ سائٹ اور صارف نام معلوم ہوتے ہیں۔ ہر اندازے
  پر 64 MiB پر Argon2id کا ایک رن خرچ ہوتا ہے — براؤزر میں تقریباً 0.15–0.4 سیکنڈ، مخصوص ہارڈویئر
  پر اس سے کم۔ چھوٹا یا عام ماسٹر پاس ورڈ ڈھونڈ لیا جائے گا؛ لمبا پاس فریز نہیں۔ بے ترتیب پاس ورڈز
  میں یہ کمزوری نہیں ہوتی، اسی لیے جنریٹر میں دونوں ہیں۔
- جب تک ماسٹر پاس ورڈ محفوظ ہے، لیک ہونے والا پاس ورڈ دوسری سائٹوں یا ورژنز کے بارے میں کچھ ظاہر
  نہیں کرتا: وہ دوسرے سالٹس سے، یعنی Argon2 کے دوسرے رنز سے آتے ہیں۔

ڈیٹا بیس کھلا رہنے تک ماسٹر پاس ورڈ میموری میں XOR ماسک کے ساتھ رکھا جاتا ہے، اب تک حساب کی گئی
اینٹروپی کے ساتھ؛ لاک کرنے سے دونوں ہٹ جاتے ہیں۔

## پرانے الگورتھم

دو پرانے Windows پروگرام خفیہ فقروں سے پاس ورڈ حساب کرتے تھے؛ جنریٹر میں **اخذ شدہ v1** (لیگیسی 1)
اور **اخذ شدہ v2** (لیگیسی 2) انہیں بالکل ہو بہو دہراتے ہیں، تاکہ ان سے بنے پاس ورڈ بحال کیے جا سکیں۔
یہ کیلکولیٹر ہیں: ان میں لکھی گئی کوئی چیز محفوظ نہیں ہوتی، جنریٹر بند ہونے پر فقرے مٹ جاتے ہیں، اور
**استعمال کریں** نتیجے کو اندراج میں ایک عام محفوظ شدہ پاس ورڈ کے طور پر رکھ دیتا ہے۔ ترتیبات ←
"پرانے پاس ورڈ الگورتھم دکھائیں" انہیں ظاہر کرتا ہے۔

اندراج سے کھولے جائیں تو دونوں شناخت کنندہ تجویز کرتے ہیں: جو صارف نام پہلے ہی اپنی سائٹ بتاتا ہو
(`mail@site.com`) وہ جیسا ہے ویسا، ورنہ صارف نام، `@` اور `www.` کے بغیر سائٹ
(`dmytro@github.com`)؛ اسے بدلا جا سکتا ہے۔ ہر فقرے — ماسٹر کلید اور ثانوی کلید، بنیادی اور ثانوی
خفیہ فقرہ — کا اپنا "ڈیٹا بیس لاک ہونے تک یاد رکھیں" چیک باکس ہے: نشان زدہ فقرہ صفحے کی میموری میں
XOR ماسک کے ساتھ رکھا جاتا ہے اور اگلی بار بھر دیا جاتا ہے؛ پہلا فقرہ یاد رکھا گیا ہو تو کلید فوراً
حساب ہو جاتی ہے۔ دونوں ڈیٹا بیس کا اپنا ماسٹر پاس ورڈ — جس سے اسے ان لاک کیا گیا — اپنے پہلے فقرے
کے طور پر بھی لے سکتے ہیں، یعنی لیگیسی 1 کی ماسٹر کلید یا لیگیسی 2 کا بنیادی خفیہ فقرہ
("ڈیٹا بیس کا ماسٹر پاس ورڈ استعمال کریں"، جو ترتیبات میں ہر ایک کے لیے الگ یاد رکھا جاتا ہے): تب وہ
خانہ اور اس کا چیک باکس بند ہو جاتے ہیں۔ اس میں سے کچھ بھی ڈسک پر نہیں لکھا جاتا؛ لاک کرنے، ڈیٹا
بیس بند کرنے یا پرانے الگورتھم بند کرنے سے یہ سب مٹ جاتا ہے۔ کوڈ `src/core/legacy.ts` میں ہے؛
`npm test` اسے اصل .NET پروگراموں سے حساب کیے گئے ویکٹرز سے جانچتا ہے۔

**لیگیسی 1** — ماسٹر کلید، شناخت کنندہ، بنیادی کلید، ثانوی کلید، نتیجہ:

```
short(bytes) = Base64(bytes) without "=", "/", "+", first 10 characters
primary key  = short(SHA-1 applied 1 000 000 times to UTF-8(master key ‖ identifier))
result       = short(SHA-1(UTF-8(primary key ‖ secondary key)))
```

بنیادی کلید شناخت کنندہ سے منسلک ہے اور اسے الگ (کاغذ پر) رکھا جا سکتا ہے، اس لیے ماسٹر کلید کہیں
لکھنے کی ضرورت نہیں: بنیادی کلید براہ راست درج کی جا سکتی ہے۔ ثانوی کلید چوری شدہ نوٹ کو اکیلے
بے کار رکھتی ہے۔

**لیگیسی 2** (Password.Generator 1.0) — بنیادی تحفظ: شناخت کنندہ، بنیادی خفیہ فقرہ، کلید کی لمبائی،
حروف کے مجموعے؛ ثانوی تحفظ: کلید، ثانوی خفیہ فقرہ، پاس ورڈ کا ورژن، پاس ورڈ کی لمبائی، حروف کے
مجموعے:

```
digest(a, b, v, n) = SHA-1 applied n times to UTF-8(a) ‖ UTF-8(b) ‖ (v > 0 ? u32le(v) : nothing)
key                = select(digest(identifier, primary phrase, 1, 100 000), key length + 2)
password           = select(digest(key, secondary phrase, version, 1), password length + 2)
```

`select` ڈائجسٹ کو پانچ little-endian u32 کے طور پر پڑھتا ہے، ہر ایک کا سب سے اوپر والا بٹ سیٹ کرتا
ہے، اسے حروف تہجی کی بنیاد N میں لکھتا ہے — `!#$%&'()+,-.` (اگر منتخب ہو)، ہندسے (ہمیشہ)، A–Z، a–z
(اگر منتخب ہوں) — سب سے کم اہم ہندسہ پہلے، ہر ایک کے 5 حروف رکھتا ہے اور لمبائی (1–18) تک کاٹ دیتا
ہے۔ پہلے دو حروف ایک دستخط ہیں جسے آنکھ سے اس دستخط سے ملایا جاتا ہے جو پروگرام دکھاتا تھا؛ باقی
کلید یا پاس ورڈ ہے۔ کلید کا ورژن ہمیشہ 1 ہوتا ہے: پروگرام میں اس کا کوئی خانہ نہیں۔ شناخت کنندہ `1`،
فقرہ `1`، لمبائی 10، ہندسے اور حروف سے کلید `E8 8pgYm9fZha` بنتی ہے۔

دونوں ورژن 3 سے کہیں زیادہ کمزور ہیں: فقروں کا ایک اندازہ حملہ آور کو 64 MiB پر Argon2id کے ایک رن
کے بجائے SHA-1 کے چند رنز کا پڑتا ہے، اور لیگیسی 1 کا نتیجہ 10 حروف کا ہے، تقریباً 60 بٹس۔ انہیں
پرانے پاس ورڈ بحال کرنے کے لیے استعمال کریں، نئے پاس ورڈز کے لیے نہیں۔

## ترجمے

انگریزی متن کوڈ میں ہی رہتا ہے: `t('menu', 'Delete')`، `tn('status', '{count} entry', '{count} entries', n)`،
اور ٹیمپلیٹ میں `data-i18n="context"` / `data-i18n-attr="context"`۔ پہلا آرگیومنٹ سیاق (context) ہے —
انٹرفیس کا وہ حصہ جس سے کوئی اسٹرنگ تعلق رکھتی ہے، تاکہ ایک ہی انگریزی لفظ کا دو جگہوں پر مختلف
ترجمہ ہو سکے۔ ایک لغت، `src/locales/<code>.json`، سیاق ← انگریزی متن ← ترجمہ کو آپس میں جوڑتی ہے:

```json
{
  "menu": { "Delete": "Удалить" },
  "status": { "{count} entries": { "one": "{count} запись", "few": "{count} записи", "many": "{count} записей", "other": "{count} записи" } }
}
```

جو اسٹرنگ لغت میں نہ ہو وہ انگریزی میں دکھائی جاتی ہے۔ عدد والے متن کی، زبان کی ہر جمع کی قسم
(`Intl.PluralRules`) کے لیے ایک شکل ہوتی ہے، جس کی کلید انگریزی کی جمع والی شکل ہوتی ہے۔
`npm run i18n` ہر زبان کے لیے وہ اسٹرنگز دکھاتا ہے جن کا ابھی ترجمہ نہیں ہوا اور وہ جو اب استعمال
نہیں ہوتیں؛ `npm test` جانچتا ہے کہ ہر ترجمہ انگریزی placeholders برقرار رکھے اور اس میں جمع کی تمام
شکلیں ہوں۔

Chrome ایکسٹینشن کے بارے میں جو کچھ خود دکھاتا ہے — اس کا نام اور تفصیل، ٹول بار بٹن کا عنوان — وہ
پینل کی نہیں بلکہ براؤزر کی زبان کی پیروی کرتا ہے، `chrome.i18n` کے ذریعے۔ یہ متن
`src/extension/manifest.json` میں انگریزی والے ہیں، جن کا ترجمہ انہی لغات میں سیاق `manifest` کے تحت
ہوتا ہے؛ بلڈ انہیں `_locales/<code>/messages.json` میں لکھتا ہے اور manifest میں `__MSG_appName__`
وغیرہ ڈالتا ہے۔ Chrome کے اپنے کوڈز ہیں اور باقی کو نظرانداز کرتا ہے: `pt` سے `pt_BR` اور `pt_PT`
بنتے ہیں، `zh` سے `zh_CN`، اور اردو کا کوئی کوڈ نہیں، اس لیے وہاں Chrome ایکسٹینشن کا نام انگریزی میں
دکھاتا ہے۔ بلڈ 75 حروف سے لمبے نام یا 132 حروف سے لمبی تفصیل پر رک جاتا ہے۔

یہ README بھی ترجمہ کیا گیا ہے: `docs/readme/README.<code>.md`، ہر زبان کے لیے ایک، ہر ایک کے اوپر
زبانوں کی فہرست کے ساتھ۔ یہاں کی گئی تبدیلی ترجموں میں بھی ہونی چاہیے۔

## بلڈ

```sh
./build.sh         # installs the dependencies if needed, then builds build/password-manager.html
npm install
npm run build      # -> build/password-manager.html
npm run watch      # rebuild on changes in src/
npm run typecheck  # tsc --noEmit
npm test           # opening, editing and saving .kdbx files, the generator, TOTP, derived passwords, matching tabs, the dictionaries
npm run test:browser  # the built page and the extension in headless Chrome
npm run i18n       # strings each dictionary lacks or no longer needs
npm run check      # typecheck, test, build and test:browser in a row
npm run shots -- shots/after  # build, then screenshots of the main screens into shots/after
```

`build.mjs`، esbuild کے ذریعے `src/app/main.ts` کو ایک IIFE میں بنڈل کرتا ہے اور اسے، اسٹائلز اور
آئیکن (ایک data URI) کے ساتھ، `src/app/template.html` میں رکھ دیتا ہے۔ Node کے لیے kdbxweb کے متبادل
(`crypto`، `@xmldom/xmldom`) خالی stubs سے بدل دیے جاتے ہیں — براؤزر میں `crypto.subtle` اور
`DOMParser` موجود ہیں۔ نتیجہ `build/password-manager.html` ہے، تقریباً 500 KB، جس کا ایک چوتھائی حصہ
لغات ہیں۔

اسی رن میں `build/pages/` بھی لکھا جاتا ہے: وہی صفحہ ایک انسٹال ہونے والی PWA کے طور پر — manifest
لنک اور service worker کی رجسٹریشن کے ساتھ `index.html`، `manifest.webmanifest`، آئیکنز اور `sw.js`،
جو صفحے کو کیش کرتا ہے تاکہ یہ آف لائن کھلے۔ `build/password-manager.html` خود ایک واحد فائل ہی رہتی
ہے جس میں کوئی بیرونی حوالہ نہیں۔

اور `build/extension/`: `panel.html` وہی ٹیمپلیٹ ہے جس کا اسکرپٹ `panel.js` میں ہے — وہی
`src/app/main.ts`، مگر `src/app/platform.ts` کی جگہ، جس کے hooks فائل میں کچھ نہیں کرتے،
`src/extension/extension.ts` کے ساتھ — اور اس کے ساتھ `popup.html` (صفحے کے اسٹائلز اور `popup.css`
کے ساتھ) اور `popup.js`، `background.js`، `offscreen.html` اور `offscreen.js`، آئیکنز اور
`manifest.json`، جس کا ورژن `package.json` والا ہے۔ `build/password-manager-extension-<version>.zip`
میں یہی فائلیں ہیں، مقررہ تاریخوں کے ساتھ: ایک جیسے سورسز سے ایک جیسے بائٹس بنتے ہیں۔

`tests/extension.mjs` اس ایکسٹینشن کو DevTools پروٹوکول کے ذریعے headless Chrome میں لوڈ کرتا ہے
(pipe پر `Extensions.loadUnpacked`؛ `--load-extension` ورژن 137 سے Chrome سے ہٹا دیا گیا ہے) اور ایک
مقامی سرور پر ٹیسٹ سائٹس بھرتا ہے: ایک سادہ فارم، ایک React جیسا فارم، ون ٹائم کوڈ کے ساتھ تین
مرحلوں والا سائن ان، سائٹ کے اپنے اور کسی دوسری سائٹ کے فریم، جال کے طور پر چھپائے گئے خانے، https
اندراج کے لیے ایک http صفحہ، اخذ شدہ v3 پاس ورڈ سے بھری گئی رجسٹریشن — پینل بند ہونے کی حالت میں،
اور لاک کے بعد؛ اور پاپ اپ، جو ان لاک کرتا ہے، بھرتا ہے، تلاش کرتا ہے، کاپی کرتا ہے اور لاک کرتا ہے۔
کانٹیکسٹ مینو پر DevTools سے کلک نہیں کیا جا سکتا، اس لیے ٹیسٹ worker کا `onClicked` خود چلاتا ہے؛
حقیقی کلک کے بغیر Chrome کوئی `activeTab` نہیں دیتا، اس لیے زیر ٹیسٹ کاپی host permissions کے طور
پر ٹیسٹ سائٹس، `*.test`، تک پہنچ سکتی ہے۔ ٹول بار آئیکن پر DevTools سے کلک کیا جا سکتا ہے
(`Extensions.triggerAction`): ایک الگ Chrome، ویسی ہی بلڈ شدہ ایکسٹینشن کے ساتھ، جانچتا ہے کہ کلک
پاپ اپ کو ٹیب دیتا ہے۔ Headless Chrome 153 اس کلک پر کریش ہو جاتا ہے، ایکسٹینشن چاہے کوئی بھی ہو،
اور تب یہ جانچ چھوڑ دی جاتی ہے؛ Chrome for Testing اسے چلاتا ہے
(`CHROME=/path/to/chrome-for-testing npm run test:browser`)۔

`tests/fixtures/Database.kdbx` ٹیسٹوں کے لیے ایک نمونہ ڈیٹا بیس ہے؛ اس کا پاس ورڈ `Тестовый пароль` ہے۔

## ورژن اور ریلیز

ورژن ایک ہی جگہ لکھا جاتا ہے، `package.json` میں۔ بلڈ اسے صفحے میں (ان لاک اسکرین کے نیچے کی
لائن، ترتیبات کا نچلا حصہ)، ایکسٹینشن کے `manifest.json` میں اور PWA کے کیش کے نام میں ڈالتا ہے۔
`v<version>` ٹیگ والے commit کا بلڈ اسے جیسا ہے ویسا دکھاتا ہے؛ کوئی بھی دوسرا بلڈ اس کے ساتھ اپنا
commit جوڑتا ہے، `0.8.0+1a2b3c4`، تاکہ GitHub Pages پر `main` کا صفحہ ریلیز نہ سمجھا جائے۔ Chrome
کے `version` میں صرف اعداد ہوتے ہیں، اس لیے وہاں commit `version_name` میں جاتا ہے۔

```sh
npm version minor           # 0.7.2 -> 0.8.0: package.json, package-lock.json, a commit and the tag v0.8.0
git push --follow-tags      # the tag starts .github/workflows/release.yml
```

اگر ٹیگ اور `package.json` میں فرق ہو تو ریلیز ورک فلو رک جاتا ہے، ورنہ
`password-manager-<tag>.html`، `password-manager-extension-<tag>.zip` اور `SHA256SUMS.txt` منسلک کرتا ہے۔

کھولی گئی کاپی والوں سے الگ۔

ہر ڈیپلائے `sw.js` میں کیش کا نام بدل دیتا ہے، اس لیے براؤزر نیا ورژن خود ہی لے لیتا ہے؛ کھلی ونڈو

لیے، کسی ریلیز سے `password-manager-<tag>.html` لیں اور اسے `SHA256SUMS.txt` سے ملائیں۔

`npm run test:browser` `build/pages/` کو بھی کھولتا ہے: service worker صفحہ سنبھال لیتا ہے، Chrome
manifest کو انسٹال کے قابل پاتا ہے، اور سرور بند ہونے کے بعد بھی صفحہ لوڈ ہوتا ہے اور نمونہ ڈیٹا بیس
