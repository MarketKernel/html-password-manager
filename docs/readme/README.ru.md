**Deterministic Password** вычисляет пароли, а не только хранит их. Пароль для сайта
получается из мастер-пароля, сайта, имени пользователя и номера версии — через Argon2id и
HMAC-SHA-256. Если файл базы потерян, те же пароли вычисляются заново из тех же данных, на
любом компьютере, — терять файл больше не страшно. Чтобы сменить пароль на сайте, достаточно
поднять версию. Как это устроено — в разделе «[Вычисляемые пароли](#вычисляемые-пароли)».

При этом это полноценный менеджер паролей KeePass: он открывает, редактирует и сохраняет
обычные файлы `.kdbx` (KDBX 4, AES-256, Argon2id), так что ту же базу можно и дальше
открывать в KeePassXC, KeePass или KeeWeb. Вычисленный пароль сохраняется в записи как
обычный, и другие приложения KeePass показывают его так же.

Всё работает без сети: ни учётной записи, ни облака, ни сетевых запросов. Приложение целиком
умещается в одном HTML-файле; база расшифровывается в памяти страницы и сохраняется прямо
обратно на диск, а мастер-пароль никуда со страницы не уходит. Эта же страница — ещё и
[расширение для Chrome](#расширение-для-chrome), которое заполняет логины во вкладке рядом, —
**[установите его из Chrome Web Store](https://chromewebstore.google.com/detail/hiahfdknjchamepclnokcalkcjcfhahf)**.

**[Онлайн-версия](https://marketkernel.github.io/html-password-manager/)** — та же страница
в виде PWA (Progressive Web App): её можно установить в систему, и тогда она работает как
отдельное приложение, со своим окном и значком, и без сети. На компьютере в Chrome, Edge и
Arc нажмите кнопку установки в адресной строке; на Android — меню ⋮ в Chrome → «Установить
приложение»; на iOS — «Поделиться» → «На экран „Домой“» в Safari или в Chrome. База и там
остаётся на вашем диске — см. «[GitHub Pages](#github-pages)».

## Как пользоваться

1. Соберите `build/password-manager.html` (см. «[Сборка](#сборка)») и откройте его в
   браузере — можно прямо с диска.
2. «Открыть файл» → выберите базу `.kdbx` или перетащите её в окно.
3. Введите мастер-пароль (и выберите файл-ключ, если он у базы есть) → «Открыть».

В Chrome, Edge и Arc файл открывается через File System Access API: изменения записываются
обратно в тот же файл — через мгновение после каждой правки, если включено автосохранение, —
а при следующем визите файл предлагается снова; запоминается только его дескриптор, но не
содержимое и не пароль. В Safari и Firefox файл открывается только для чтения, а «Сохранить»
скачивает обновлённую копию базы — так же и на телефонах: в Chrome на Android нет File System
Access, а все браузеры на iOS, включая Chrome, работают на движке Safari. На iOS «Сохранить»
вместо этого передаёт копию в меню «Поделиться» — см. «[На телефоне](#на-телефоне)».

«Новая база» создаёт пустую базу KDBX 4, зашифрованную AES-256 и Argon2id
(64 МиБ, 10 проходов — значения по умолчанию KeePassXC, около полсекунды в браузере).

### На телефоне

При ширине до 900 пикселей — на телефоне или на планшете, который держат вертикально, —
страница показывает что-то одно. Список записей занимает весь экран; касание открывает запись
на отдельном экране, а ‹ на панели инструментов, системная кнопка «Назад» или свайп назад
возвращают к списку. Правка при возврате сохраняется — так же, как на компьютере, когда
выбираешь другую запись; новая запись, оставленная пустой, отбрасывается. ☰ выдвигает поверх
списка группы, метки и корзину. Меню, генератор и настройки поднимаются снизу экрана; «Назад»
сначала закрывает их и отменяет диалог. Генератор, настройки и блокировка находятся в меню ⋯
на панели инструментов.

На сенсорном экране нет ни правого клика, ни перетаскивания: ⋯ рядом с группой открывает то
меню, которое на компьютере открывается правым кликом, а его пункт «Переместить в группу…»
делает то же, что перетаскивание. Меню записи — это её ⋯ на экране записи.

Файл открывается только для чтения. На iOS «Сохранить» передаёт обновлённую базу в меню
«Поделиться», где «Сохранить в Файлы» может записать её на место исходной; если закрыть меню,
изменения останутся несохранёнными. Chrome на Android умеет делиться только картинками, звуком,
видео и текстом, поэтому там «Сохранить» скачивает копию.

На более широком экране и на планшете три панели остаются такими же, как на компьютере; на
сенсорном экране любого размера кнопки крупнее, а рядом с группами есть ⋯.

## Расширение для Chrome

**[Установить из Chrome Web Store](https://chromewebstore.google.com/detail/hiahfdknjchamepclnokcalkcjcfhahf)**

`npm run build` также создаёт `build/extension/`: то же приложение в виде расширения для
Chrome, и его архив `build/password-manager-extension-<version>.zip` для Chrome Web Store.
Чтобы попробовать собственную сборку: `chrome://extensions` → «Режим разработчика» →
«Загрузить распакованное расширение» → `build/extension`.

Значок на панели инструментов открывает компактное всплывающее окно: записи для сайта вкладки
(клик по записи заполняет её), кнопки, копирующие имя пользователя, пароль или одноразовый
код, и поиск по всей базе. **«Полный режим»** внизу открывает приложение в боковой панели
Chrome, рядом со страницей, — в телефонной раскладке, раз панель узкая, — и там оно остаётся
при переходе между вкладками. Всё работает там так же, как в файле; расширение добавляет
заполнение логинов:

- **Всплывающее окно** открывает одним мастер-паролем тот файл, который панель открывала
  последним: выбирает файлы и файлы-ключи и вносит все изменения панель. На сайте, для
  которого нет записи, его кнопка **«Новый пароль»** открывает панель на генераторе — как
  «Заполнить» в меню.
- **«Заполнить»** в контекстном меню страницы (правый клик на странице или в поле) вписывает
  имя пользователя и пароль записи для сайта вкладки — или её одноразовый код, на том шаге
  входа, где его просят. Если запись для сайта одна, заполнение происходит сразу, открыта
  панель или нет; если их несколько, ни одной или база заблокирована, открывается панель —
  чтобы выбрать запись, создать пароль или разблокировать базу, — и дальше всё продолжается
  оттуда. Вход в два шага (Google, Microsoft) получает имя пользователя на первом шаге и
  пароль на втором: выбранная для вкладки запись запоминается. Кнопка **«Заполнить»** у записи
  в панели вписывает эту запись во вкладку.
- **База остаётся открытой**, когда панель закрывается, — до блокировки: по истечении времени
  простоя из настроек, при блокировке экрана компьютера, из панели, из всплывающего окна или
  пунктом **«Заблокировать»** в меню значка на панели инструментов. Открытая снова, панель
  подхватывает базу без пароля, а всплывающее окно сразу её показывает.
- **«Для этого сайта»** вверху панели групп показывает записи сайта вкладки, и список
  открывается именно на нём; он следует за вкладкой.
- **Новый пароль для страницы.** На сайте, для которого нет записи, «Заполнить» открывает
  генератор «Вычисляемый v3» с сайтом вкладки и именем пользователя, введённым на странице.
  Его кнопка «Заполнить» вписывает пароль — в оба поля формы регистрации — и сохраняет его как
  обычную запись.

Запись подходит вкладке, когда её сайт в точности совпадает с сайтом вкладки: оба адреса
проходят через `siteOf()` генератора 3 — без схемы, порта, пути и `www.`, IDN в punycode.
`google.com` не подходит для `accounts.google.com`, а `mail.site.com` — для `site.com`.
Запись с `https://` или вовсе без схемы никогда не вписывается в страницу `http://`: для
сайта, которым пользуются по http, в поле «Сайт» нужен `http://`. Записи из корзины не
предлагаются, а запись, выбранная вручную для другого сайта, вписывается только после
предупреждения, где названы оба сайта.

**Как это устроено.** Панель — это сама страница: `panel.html`, а её скрипт — в `panel.js`,
как требует Manifest V3. При каждом открытии базы и сохранении она передаёт файл и его ключ —
пароль в `ProtectedValue`, файл-ключ — offscreen-документу, который хранит их, а также
расшифрованную из них копию базы только для чтения, в памяти до блокировки; блокировка
закрывает его, и ключ исчезает вместе с ним. Ничего никуда не записывается. Меню принадлежат
service worker'у. Клик по «Заполнить» может открыть панель, только пока ещё ничего не ожидалось,
поэтому worker должен сразу знать, может ли он заполнить: он хранит сайты
записей — без названий и паролей, — которые ему присылает offscreen-документ, а
offscreen-документ поддерживает его в рабочем состоянии. Всплывающее окно (`popup.html`,
`popup.js`) ничего не расшифровывает: оно запрашивает у offscreen-документа названия и имена
пользователей, подходящие вкладке, а затем — одну запись, по которой кликнули; если база
заблокирована, оно читает недавний файл и передаёт его вместе с паролем этому документу,
чтобы тот его открыл.

**Что попадает на страницу.**

- Только то, что запрошено кликом, и только значения одной записи. Никакие content scripts
  нигде не работают: при клике `chrome.scripting.executeScript` сначала спрашивает каждый
  фрейм вкладки, где он находится и какие у него поля входа, не передавая никаких значений;
  затем значения получают только фреймы сайта записи, а функция перед вводом ещё раз проверяет
  собственный адрес. Фрейм другого сайта на той же странице не получает ничего.
- Заполняются только поля, которые человек может увидеть: показанные, включённые, доступные
  для записи, ненулевого размера, в пределах окна. Поле, спрятанное в качестве ловушки,
  остаётся пустым.
- Значения выставляются из изолированного мира расширения, в обход любых сеттеров, которые
  страница повесила на свои поля ввода, а события `input` и `change` сообщают о них React,
  Vue или Angular.
- Мастер-пароль, другие записи и список сайтов на страницу никогда не попадают.

**Разрешения.** `activeTab` вместо доступа ко всем сайтам: клик по значку или по «Заполнить»
даёт расширению именно эту вкладку. Поэтому панель открывается из всплывающего окна или из
меню, а не собственной настройкой Chrome (`openPanelOnActionClick`): панель, открытая таким
способом, не получает вкладку вовсе. «Заполнить» в панели на вкладке, которая расширению не
была дана, один раз запрашивает доступ к сайту записи (`optional_host_permissions`).
`contextMenus`, `scripting` и `sidePanel` — для описанного выше, `offscreen` — для документа,
`idle` — для блокировки экрана, `clipboardWrite` — чтобы стереть скопированный секрет при
закрытой панели. `externally_connectable` нет: части расширения общаются через
`chrome.runtime`, и каждая принимает сообщения только от собственных страниц расширения. У его
страниц `connect-src 'none'`, как и у файла; сборка проверяет это, а также что ни на одной
странице нет встроенного скрипта или внешнего адреса.

Одно отличие от файла: открытая снова, панель записывает базу на место, только если Chrome
всё ещё это позволяет; иначе об этом сообщает строка состояния, и первое «Сохранить»
запрашивает разрешение.

## Безопасность

- **Ничто не покидает страницу.** Content-Security-Policy в файле запрещает любые сетевые
  запросы, отправку форм и внешние ресурсы; сборка завершается ошибкой, если политика
  пропала или появилась внешняя ссылка. Копия для PWA пропускает ещё три вещи, все со своего
  же источника: манифест, service worker и значки, — `connect-src` остаётся `'none'`.
- Код формата — [kdbxweb](https://github.com/keeweb/kdbxweb), библиотека, на которой построен
  KeeWeb; Argon2 — это WebAssembly из [hash-wasm](https://github.com/Daninet/hash-wasm),
  который тоже встроен в файл.
- Защищённые поля хранятся в памяти замаскированными XOR (`ProtectedValue` из kdbxweb) и
  скрыты на экране, пока их не покажут. Поиск никогда не заглядывает в защищённые поля.
- **Пароли на любом языке.** Когда браузер принимает поле за поле пароля, macOS включает
  Secure Input и принудительно переключает раскладку на латинскую, так что мастер-пароль
  кириллицей ввести нельзя. Chrome принимает за пароль не только `type=password`, но, по
  эвристикам, и любое поле со стилем `-webkit-text-security` или со значением из точек — и,
  однажды решив так, продолжает так считать. Секретные поля здесь таких подсказок не дают:
  это обычные текстовые поля с прозрачным текстом, поверх которых рисуется слой точек
  (моноширинным шрифтом, чтобы каретка оставалась на месте). Значок показывает, чем набирается
  скрытый текст — кириллицей (РУС) или латиницей (ENG). Цена этого: Secure Input, который к
  тому же скрывает нажатия клавиш от других приложений, не включается никогда.
- Скопированный секрет стирается из буфера обмена через 30 секунд и при блокировке.
- База блокируется после 15 минут простоя и по `⌘L`. Блокировка удаляет расшифрованную базу
  из памяти; если есть несохранённые изменения, которые нельзя записать, блокировка ждёт, а не
  выбрасывает их.
- Ссылки в записях открываются только для `http`, `https`, `ftp` и `mailto`, с `noopener`.
- Пароли генерируются с помощью `crypto.getRandomValues` и выборки с отклонением: все символы
  равновероятны.

## Возможности

- **Группы**: сворачиваемое дерево, создание, переименование и удаление через контекстное
  меню, перемещение перетаскиванием (записей и групп), панель, которую можно растягивать и
  скрывать (`⌘\`).
- **Записи**: название, имя пользователя, пароль, сайт, заметки, свои поля (открытые или
  защищённые), метки, дата окончания срока, вложения. Сортировка по названию, имени
  пользователя, сайту, датам.
- **Одноразовые коды** (TOTP): из поля `otp` (URL `otpauth://` или просто секрет — так их
  хранят KeePassXC и KeeWeb), из полей `TimeOtp-*` KeePass или из `TOTP Seed` TrayTOTP.
  SHA-1, SHA-256, SHA-512; код обновляется с обратным отсчётом. **«+ Одноразовый код»** в
  редакторе принимает ключ настройки, который сайт показывает рядом с QR-кодом (или ссылку
  `otpauth://`), и сразу показывает код, чтобы подтвердить его на сайте; голый ключ
  сохраняется как ссылка `otpauth://` — в том виде, который читает KeePassXC.
- **Редактирование** идёт над черновиком: «Сохранить» сначала кладёт прежнее состояние в
  историю записи, как это делает KeePass; «Отмена» отбрасывает черновик. Прежние версии можно
  просматривать и восстанавливать.
- **Корзина**: удаление перемещает в корзину; оттуда — восстановить или удалить навсегда.
- **Поиск** по названию, имени пользователя, сайту, заметкам, меткам, своим полям и именам
  вложений; совпасть должно каждое слово запроса.
- **Генератор паролей** (кубик, `⌘G`) создаёт пароль того типа, который выбран в его списке,
  — новейшие способы вычисления первыми; последний выбор запоминается:
  - **«Вычисляемый v3»** — вычисляется из мастер-пароля, имени пользователя, сайта и версии,
    поэтому его можно вычислить снова и без файла — см.
    «[Вычисляемые пароли](#вычисляемые-пароли)»;
  - **«Вычисляемый v2»** и **«Вычисляемый v1»** — калькуляторы двух старых программ (legacy 2
    и legacy 1), показываются, когда включено «Настройки» → «Показывать устаревшие алгоритмы
    вычисления паролей», — см. «[Устаревшие алгоритмы](#устаревшие-алгоритмы)»;
  - **«Случайный»** — длина, наборы символов, похожие символы, оценка энтропии.

  Индикатор надёжности для введённых вручную паролей.
- **База**: переименование, смена мастер-пароля и файла-ключа, сохранение копии.
- **Языки**: English, 中文, हिन्दी, Español, Français, العربية, বাংলা, Português, Русский,
  اردو, Bahasa Indonesia, Deutsch, 日本語, मराठी, తెలుగు, Türkçe — шестнадцать самых
  распространённых — и Українська. Выбирается в настройках или берётся из браузера; для
  арабского и урду окно раскладывается справа налево.
- **Тема**: как в системе, светлая, тёмная — в настройках. Язык, тема, ширина панелей,
  сортировка, параметры генератора и свёрнутые группы запоминаются.

## Вычисляемые пароли

**«Вычисляемый v3»** в генераторе вычисляет пароль из

- мастер-пароля базы (файл-ключ, если он есть, не участвует) или другого, введённого там же,
- имени пользователя,
- сайта — домена, на котором находится учётная запись (`https://www.github.com/login` →
  `github.com`),
- версии — 1, 2, … вплоть до 2³² − 1; «+1» даёт той же учётной записи новый пароль.

Из этих четырёх получаются 32 байта энтропии. Требования — длина, наборы символов, похожие
символы — лишь превращают эти байты в символы: их изменение энтропию не меняет. **«Вставить»**
помещает результат в запись как обычный сохранённый пароль. О том, как он получен, ничего не
хранится: запись такая же, как любая другая, и другие приложения KeePass показывают тот же
пароль. Если файл потеряется, тот же мастер-пароль, имя пользователя, сайт, версия и требования
дадут тот же пароль на любом компьютере. По умолчанию — 20 символов, все четыре набора, без
похожих символов; для пароля, созданного с другими требованиями, их тоже нужно помнить.

Генератор сначала спрашивает имя пользователя — если он открыт из записи, то имя из самой
записи: введённое там отображается и в форме, — затем сайт; оба обязательны, а пароль, который
они дают, показан внизу, над **«Вставить»**.

- Имя пользователя, которое является адресом электронной почты, само называет свой сайт:
  `test@site.com` подставляет `site.com`, а поле «Сайт» записи остаётся как есть — там вполне
  может быть `mail.site.com`. Но с одним и тем же адресом входят на многие сайты, и генератор
  напоминает об этом под полем: для GitHub с `test@gmail.com` впишите `github.com` поверх
  подставленного `gmail.com`.
- Для любого другого имени пользователя сайт нужно ввести, и если генератор открыт из записи,
  введённое становится и её сайтом. Сначала подставляется сайт, который у записи уже есть.

В том, что введено как сайт, схема, путь, порт и начальное `www.` значения не имеют; поддомен
имеет — `login.github.com` и `github.com` — два разных сайта. Сайт, который не является URL
(«Мой банк»), используется как есть. С панели инструментов генератор работает так же, со
своими полями, и копирует результат.

Флажок «Использовать мастер-пароль базы» ставится при каждом открытии генератора. Снимите его,
чтобы вычислять от другого мастер-пароля, введённого там же и нигде не сохраняемого, — чтобы
восстановить пароль, созданный в другой базе или до смены мастер-пароля. Смена мастер-пароля
не трогает пароли в файле; меняется лишь то, что генератор вычисляет с этого момента.

### Алгоритм: генератор 3

Всё, что ниже, заморожено: изменение любой константы сделало бы невозможным повторное
вычисление каждого созданного с её помощью пароля. Будущий генератор появится как новый тип в
списке, а этот останется как есть. Код — `src/core/derived.ts`; `npm test` проверяет его на
фиксированных векторах и на независимой реализации, написанной по этому описанию на
собственном `crypto` Node. Примитивы стандартные — SHA-256, HMAC-SHA-256, Argon2id, — так что
алгоритм можно воспроизвести на любом языке.

Он работает в два этапа: секреты превращаются в 32 байта энтропии, затем требования
вырезают из этих байтов символы.

**Этап 1 — энтропия.**

1. *Нормализация входных данных.* Все строки — UTF-8.
   - `site` — хост того, что введено как сайт: текст разбирается как WHATWG URL
     (если в тексте нет `scheme://`, впереди ставится `https://`): нижний регистр, IDN в
     punycode, без порта, без имени пользователя и пароля, начальное `www.` отбрасывается;
     текст, который не разбирается как URL, используется как есть. Затем — обрезка пробелов,
     нормализация NFC, приведение к нижнему регистру.
   - `user` — имя пользователя, с обрезанными пробелами и нормализацией NFC; регистр
     сохраняется.
   - `master` — мастер-пароль, нормализация NFC, ничего не обрезается. «é», набранное одним
     символом или как «e» плюс комбинируемое ударение, даёт один и тот же пароль.
2. *Соль.*
   ```
   salt = SHA-256( "html-password-manager/derived/v3" ‖ 0x00
                   ‖ u32be(byte length of site) ‖ site
                   ‖ u32be(byte length of user) ‖ user
                   ‖ u32be(version) )
   ```
   Префиксы длины не дают спутать `ab` + `c` и `a` + `bc`; метка отделяет эти байты от любого
   другого использования тех же входных данных. `u32be` — 4-байтовое целое big-endian.
3. *Растяжение.*
   ```
   entropy = Argon2id(password = master, salt, memory = 64 MiB, passes = 3,
                      lanes = 1, version 0x13, output = 32 bytes)
   ```
   Argon2id заставляет каждую попытку угадать мастер-пароль стоить 64 МиБ памяти — именно это
   замедляет GPU и ASIC. Поскольку сайт, имя пользователя и версия входят в соль, у каждой
   учётной записи она своя: никакую таблицу нельзя вычислить заранее, и каждую учётную запись
   приходится атаковать отдельно.

**Этап 2 — формирование.** Требования используются только здесь, поэтому они меняют вид
пароля, а не энтропию за ним.

4. *Поток случайных байтов* нужной длины — 32 байтов не хватает для длинного пароля и его
   перемешивания:
   ```
   block(i) = HMAC-SHA-256(key = entropy, "hpm-v3-stream" ‖ u32be(i)),  i = 0, 1, 2, …
   ```
5. *Несмещённое число меньше n.* Возьмите следующие 4 байта потока как u32 big-endian `x`.
   Если `x ≥ 2³² − (2³² mod n)`, отбросьте его и возьмите следующие; иначе результат —
   `x mod n`. (Простое `x mod n` давало бы преимущество началу алфавита.)
6. *Символы.* Наборы, в таком порядке, каждый — только если выбран:
   ```
   A–Z      ABCDEFGHIJKLMNOPQRSTUVWXYZ
   a–z      abcdefghijklmnopqrstuvwxyz
   0–9      0123456789
   symbols  !#$%&*+-=?@^_~.,:;()[]{}<>/|
   ```
   Без похожих символов из них удаляются `O 0 o I l 1 |`. Затем:
   ```
   chars = []
   for each chosen set:            chars.push(set[draw(|set|)])      # каждый набор представлен
   while |chars| < length:         chars.push(all[draw(|all|)])      # all = все наборы вместе
   for i = length − 1 down to 1:   j = draw(i + 1); swap chars[i], chars[j]   # Фишер–Йейтс
   password = chars joined
   ```
   Длина — от 4 до 128. Именно то, что сначала берётся по символу из каждого набора,
   гарантирует «есть цифра» и «есть символ»; перемешивание скрывает, куда эти символы попали.

**Тестовый вектор.** Мастер-пароль `Тестовый пароль`, сайт `https://www.github.com/login`
(`github.com`), имя пользователя `me@example.com`, версия 1, требования по умолчанию
(20 символов, все четыре набора, без похожих символов):

```
password  A6qVXXF]7<%a)aa<x7*U
```

Та же энтропия с 12 символами и без символов-знаков даёт `yaM6VJaJFYUQ`; версия 2 с
требованиями по умолчанию даёт `3q_bwppbE8P2+ufKr:P6`.

### Насколько он надёжен

- У вычисляемого пароля не больше 256 бит энтропии (те самые 32 байта); 20 символов из всех
  четырёх наборов без похожих символов — это около 128 бит. На практике потолок задаёт
  мастер-пароль.
- **Слабое место любой схемы вычисляемых паролей:** пароль, утёкший с одного сайта, позволяет
  атакующему подбирать мастер-пароль офлайн, ведь сайт и имя пользователя известны. Каждая
  попытка стоит одного прогона Argon2id на 64 МиБ — около 0,15–0,4 с в браузере, меньше на
  специализированном оборудовании. Короткий или распространённый мастер-пароль будет найден;
  длинная парольная фраза — нет. У случайных паролей этой слабости нет, поэтому в генераторе
  есть и те, и другие.
- Пока мастер-пароль держится, утёкший пароль ничего не говорит о других сайтах или версиях:
  они получены из других солей, а значит, из других прогонов Argon2.

Пока база открыта, мастер-пароль хранится в памяти замаскированным XOR вместе с уже
вычисленной энтропией; блокировка удаляет и то, и другое.

## Устаревшие алгоритмы

Две старые программы для Windows вычисляли пароли из секретных фраз; **«Вычисляемый v1»**
(legacy 1) и **«Вычисляемый v2»** (legacy 2) в генераторе в точности повторяют их, так что
созданные ими пароли можно восстановить. Это калькуляторы: ничего из введённого в них не
сохраняется, фразы исчезают при закрытии генератора, а **«Вставить»** помещает результат в
запись как обычный сохранённый пароль. Чтобы они появились, включите «Настройки» →
«Показывать устаревшие алгоритмы вычисления паролей».

Если они открыты из записи, оба предлагают идентификатор: имя пользователя, которое уже
называет свой сайт (`mail@site.com`), — как есть, иначе имя пользователя, `@` и сайт без
`www.` (`dmytro@github.com`); его можно изменить. У каждой фразы — мастер-ключа и вторичного
ключа, первичной и вторичной секретной фразы — есть свой флажок «Помнить до блокировки базы»:
отмеченная фраза хранится в памяти страницы, замаскированная XOR, и подставляется в следующий
раз; если сохранена первая фраза, ключ вычисляется сразу. Оба алгоритма могут также брать в
качестве первой фразы — мастер-ключа legacy 1 или первичной секретной фразы legacy 2 —
собственный мастер-пароль базы, тот, которым она открыта («Использовать мастер-пароль базы»;
этот выбор запоминается в настройках для каждого из них): тогда это поле и его флажок
отключаются. Ничего из этого не записывается на диск; блокировка, закрытие базы или
выключение устаревших алгоритмов стирают всё. Код —
`src/core/legacy.ts`; `npm test` проверяет его на векторах, вычисленных исходными программами на .NET.

**Legacy 1** — мастер-ключ, идентификатор, первичный ключ, вторичный ключ, результат:

```
short(bytes) = Base64(bytes) without "=", "/", "+", first 10 characters
primary key  = short(SHA-1 applied 1 000 000 times to UTF-8(master key ‖ identifier))
result       = short(SHA-1(UTF-8(primary key ‖ secondary key)))
```

Первичный ключ привязан к идентификатору и может храниться отдельно (на бумаге), так что
мастер-ключ не нужно нигде вводить: первичный ключ можно ввести напрямую. Вторичный ключ
делает украденную записку бесполезной самой по себе.

**Legacy 2** (Password.Generator 1.0) — первичная защита: идентификатор, первичная секретная
фраза, длина ключа, наборы символов; вторичная защита: ключ, вторичная секретная фраза, версия
пароля, длина пароля, наборы символов:

```
digest(a, b, v, n) = SHA-1 applied n times to UTF-8(a) ‖ UTF-8(b) ‖ (v > 0 ? u32le(v) : nothing)
key                = select(digest(identifier, primary phrase, 1, 100 000), key length + 2)
password           = select(digest(key, secondary phrase, version, 1), password length + 2)
```

`select` читает дайджест как пять u32 little-endian, выставляет у каждого старший бит,
записывает его в системе счисления с основанием N алфавита — `!#$%&'()+,-.` (если выбраны),
цифры (всегда), A–Z, a–z (если выбраны) — начиная с младшего разряда, оставляет по 5 символов
от каждого и обрезает до нужной длины (1–18). Первые два символа — подпись, которую можно
сверить на глаз с той, что показывала программа; остальное — ключ или пароль. Версия ключа
всегда 1: в программе для неё нет поля. Идентификатор `1`, фраза `1`, длина 10, цифры и буквы
дают ключ `E8 8pgYm9fZha`.

Оба намного слабее версии 3: попытка подобрать фразы стоит атакующему нескольких прогонов
SHA-1 вместо прогона Argon2id на 64 МиБ, а результат Legacy 1 — это 10 символов, около 60 бит.
Используйте их, чтобы восстановить старые пароли, а не для новых.

## Переводы

Английский текст остаётся в коде: `t('menu', 'Delete')`, `tn('status', '{count} entry',
'{count} entries', n)`, а в шаблоне — `data-i18n="context"` / `data-i18n-attr="context"`.
Первый аргумент — контекст, часть интерфейса, к которой относится строка, чтобы одно и то же
английское слово можно было перевести по-разному в двух местах. Словарь
`src/locales/<code>.json` сопоставляет контекст → английский текст → перевод:

```json
{
  "menu": { "Delete": "Удалить" },
  "status": { "{count} entries": { "one": "{count} запись", "few": "{count} записи", "many": "{count} записей", "other": "{count} записи" } }
}
```

Строка, которой нет в словаре, показывается по-английски. У текста с числом есть по одной
форме на каждую категорию множественного числа языка (`Intl.PluralRules`), а ключом служит
английская форма множественного числа. `npm run i18n` показывает для каждого языка ещё не
переведённые строки и те, что больше не используются; `npm test` проверяет, что каждый
перевод сохраняет английские подстановки и содержит все формы множественного числа.

То, что Chrome показывает о самом расширении, — его название и описание, подсказку кнопки на
панели инструментов, — следует языку браузера, а не панели, через `chrome.i18n`. Эти тексты —
английские из `src/extension/manifest.json`, переведённые в тех же словарях в контексте
`manifest`; сборка записывает их в `_locales/<code>/messages.json` и подставляет в манифест
`__MSG_appName__` и подобное. У Chrome свои коды, а остальные он игнорирует: `pt` становится
`pt_BR` и `pt_PT`, `zh` — `zh_CN`, а для урду кода нет, поэтому там Chrome называет расширение
по-английски. Сборка останавливается, если название длиннее 75 символов или описание длиннее 132.

Этот README тоже переведён: `docs/readme/README.<code>.md`, по одному на язык, со списком
языков вверху каждого. Изменение здесь нужно внести и в переводы.

## Сборка

```sh
./build.sh         # при необходимости ставит зависимости, затем собирает build/password-manager.html
npm install
npm run build      # -> build/password-manager.html
npm run watch      # пересборка при изменениях в src/
npm run typecheck  # tsc --noEmit
npm test           # открытие, правка и сохранение .kdbx, генератор, TOTP, вычисляемые пароли, подбор вкладок, словари
npm run test:browser  # собранная страница и расширение в headless Chrome
npm run i18n       # строки, которых не хватает каждому словарю или которые ему больше не нужны
```

`build.mjs` собирает `src/app/main.ts` с помощью esbuild в IIFE и подставляет его вместе со
стилями и значком (data URI) в `src/app/template.html`. Запасные варианты kdbxweb для Node
(`crypto`, `@xmldom/xmldom`) заменяются пустыми заглушками — в браузере есть `crypto.subtle`
и `DOMParser`. Результат — `build/password-manager.html`, около 500 КБ, четверть которых
приходится на словари.

Тот же запуск создаёт `build/pages/`: эту страницу в виде устанавливаемого PWA — `index.html`
со ссылкой на манифест и регистрацией service worker'а, `manifest.webmanifest`, значки и
`sw.js`, который кэширует страницу, чтобы она открывалась без сети. Сам
`build/password-manager.html` остаётся единым файлом без внешних ссылок.

А также `build/extension/`: `panel.html` — это шаблон со скриптом в `panel.js` (тот же
`src/app/main.ts`, где на месте `src/app/platform.ts`, чьи хуки в файле ничего не делают, стоит
`src/extension/extension.ts`), рядом с `popup.html` (со стилями страницы и `popup.css`) и
`popup.js`, `background.js`, `offscreen.html` и `offscreen.js`, значками и `manifest.json`,
версия в котором берётся из `package.json`. `build/password-manager-extension-<version>.zip`
содержит те же файлы с фиксированными датами: одни и те же исходники дают одни и те же байты.

`tests/extension.mjs` загружает это расширение в headless Chrome через протокол DevTools
(`Extensions.loadUnpacked` через pipe; `--load-extension` убран из Chrome начиная с версии
137) и заполняет тестовые сайты на локальном сервере: простую форму, форму в стиле React,
вход в три шага с одноразовым кодом, фреймы своего сайта и чужого, поля-ловушки, страницу
http для записи https, регистрацию с паролем «Вычисляемый v3» — при закрытой панели и после
блокировки; а также всплывающее окно, которое открывает базу, заполняет, ищет, копирует и
блокирует. Кликнуть по контекстному меню из DevTools нельзя, поэтому тест сам вызывает
`onClicked` worker'а; без настоящего клика Chrome не даёт `activeTab`, поэтому тестируемая
копия может обращаться к тестовым сайтам `*.test` по разрешениям на хосты. По значку на панели
инструментов кликнуть из DevTools можно (`Extensions.triggerAction`): отдельный Chrome с
расширением в собранном виде проверяет, что клик даёт всплывающему окну вкладку. Headless
Chrome 153 падает на этом клике, каким бы ни было расширение, и тогда проверка пропускается;
в Chrome for Testing она выполняется (`CHROME=/path/to/chrome-for-testing npm run test:browser`).

`tests/fixtures/Database.kdbx` — пример базы для тестов; её пароль — `Тестовый пароль`.

## Версии и релизы

Версия записана в одном месте — в `package.json`. Сборка вписывает её в страницу (строка под
экраном входа, низ настроек), в `manifest.json` расширения и в имя кэша PWA. Сборка коммита с
тегом `v<version>` показывает её как есть; любая другая добавляет свой коммит, `0.8.0+1a2b3c4`,
чтобы страницу из `main` на GitHub Pages не приняли за релиз. В `version` Chrome допускаются
только числа, поэтому там коммит попадает в `version_name`.

```sh
npm version minor           # 0.7.2 -> 0.8.0: package.json, package-lock.json, коммит и тег v0.8.0
git push --follow-tags      # тег запускает .github/workflows/release.yml
```

Workflow релиза останавливается, если тег и `package.json` расходятся, а затем прикрепляет
`password-manager-<tag>.html`, `password-manager-extension-<tag>.zip` и `SHA256SUMS.txt`.

## GitHub Pages

`.github/workflows/pages.yml` собирает и тестирует каждый push в `main` и разворачивает
`build/pages/` на GitHub Pages (Settings → Pages → Source: GitHub Actions) по адресу
<https://marketkernel.github.io/html-password-manager/>. Файлы открываются так же, как в
едином файле; недавние файлы, настройки и запомненные дескрипторы принадлежат этому адресу —
отдельно от тех, что у копии, открытой с диска.

Каждое развёртывание меняет имя кэша в `sw.js`, поэтому браузер сам подхватывает новую
версию; открытое окно переключается на неё при следующей перезагрузке. В этом же и цена:
установленное PWA запускает то, что туда положило последнее развёртывание, а скачанный файл
остаётся той версией, какой он был. Для версии, зафиксированной на диске, возьмите
`password-manager-<tag>.html` из релиза и сверьте его с `SHA256SUMS.txt`.

`npm run test:browser` открывает и `build/pages/`: service worker берёт страницу под свой
контроль, Chrome признаёт манифест пригодным для установки, а после остановки сервера страница
всё равно загружается и открывает пример базы.

  template.html       разметка с подстановками __STYLES__/__APP__/__ICON__, CSP; а также panel.html расширения
  styles.css          палитра, светлая и тёмная темы, три панели; на телефоне — один экран за раз
  main.ts             экран входа, открытие, сохранение, блокировка, панель инструментов, клавиши, настройки
  files.ts            File System Access API, перетаскивание, выбор файла; недавние файлы
  groups.ts           дерево групп, метки и корзина в левой панели
  list.ts             список записей
  details.ts          одна запись: просмотр, правка над черновиком, история, вложения, TOTP
  search.ts           поиск, сортировка, безопасные ссылки
  genpanel.ts         всплывающий генератор: случайный, версия 3, legacy 1 и 2
  clipboard.ts        копирование со стиранием по таймеру
  avatar.ts           значки записей: свои значки из базы или цветная буква

## Ограничения

- Поддерживаются KDBX 3.1 и 4.x; файлы, зашифрованные Twofish, и файлы KeePass 1 (`.kdb`) —
  нет.
- Нет синхронизации, автонабора и слияния изменённых копий.
- Расширение работает только в Chrome, и в нём нет подсказок в полях, сохранения пароля при
  отправке формы, горячей клавиши, а у записи может быть только один сайт.
- Записывать файл на место умеют только браузеры на основе Chromium.
