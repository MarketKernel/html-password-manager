**Deterministic Password** обчислює паролі, а не лише зберігає їх. Пароль сайту обчислюється
з майстер-пароля, сайту, імені користувача й номера версії — за допомогою Argon2id
і HMAC-SHA-256. Якщо файл бази загубиться, ті самі вхідні дані знову дадуть ті самі паролі
на будь-якому комп’ютері, — тож утрата файлу вже не страшна. Щоб змінити пароль сайту, досить
збільшити версію. Як це працює — у розділі «[Обчислювані паролі](#обчислювані-паролі)».

Водночас це повноцінний менеджер паролів KeePass: він відкриває, редагує й зберігає звичайні
файли `.kdbx` (KDBX 4, AES-256, Argon2id), тож ту саму базу й далі можна відкривати в KeePassXC,
KeePass чи KeeWeb. Обчислений пароль зберігається в записі як будь-який інший, тому інші
застосунки KeePass показують його так само.

Усе працює без мережі: жодного облікового запису, жодної хмари, жодних мережевих запитів.
Застосунок цілком уміщено в одному самодостатньому HTML-файлі; база розшифровується в пам’яті
сторінки й зберігається просто назад на диск, а майстер-пароль не виходить за межі сторінки.
Та сама сторінка — це ще й [розширення для Chrome](#розширення-для-chrome), яке заповнює дані
для входу у вкладці поруч, —
**[встановіть його з Chrome Web Store](https://chromewebstore.google.com/detail/hiahfdknjchamepclnokcalkcjcfhahf)**.

**[Онлайн-версія](https://marketkernel.github.io/html-password-manager/)** — та сама сторінка
як PWA (Progressive Web App): її можна встановити в систему, і тоді вона працює як окремий
застосунок, із власним вікном і значком, а також без мережі. На комп’ютері в Chrome, Edge
і Arc скористайтеся кнопкою встановлення в адресному рядку; на Android — меню ⋮ у Chrome →
«Установити додаток»; на iOS — «Поширити» → «На Початковий екран», у Safari або в Chrome. База
й тут лишається на вашому диску — див. «[GitHub Pages](#github-pages)».

## Як користуватися

1. Зберіть `build/password-manager.html` (див. «[Збирання](#збирання)») і відкрийте його в браузері —
   можна просто з диска.
2. «Відкрити файл» → виберіть базу `.kdbx` або перетягніть її у вікно.
3. Введіть майстер-пароль (і виберіть файл-ключ, якщо він у бази є) → «Відкрити».

У Chrome, Edge і Arc файл відкривається через File System Access API: зміни записуються назад
у той самий файл — за мить після кожної правки, якщо ввімкнено автозбереження, — а під час
наступного відвідування файл пропонується знову: запам’ятовується лише його дескриптор, ніколи
не вміст і не пароль. У Safari і Firefox файл відкривається лише для читання, а «Зберегти»
завантажує оновлену копію бази — так само й на телефонах: Chrome на Android не має File System
Access, а всі браузери на iOS, зокрема й Chrome, працюють на рушії Safari. На iOS «Зберегти»
натомість передає копію в меню «Поширити» — див. «[На телефоні](#на-телефоні)».

«Нова база» створює порожню базу KDBX 4, зашифровану AES-256 і Argon2id
(64 MiB, 10 проходів — типові параметри KeePassXC, близько пів секунди в браузері).

### На телефоні

До 900 пікселів завширшки — на телефоні або на планшеті у вертикальному положенні — сторінка
показує щось одне за раз. Список записів займає весь екран; дотик відкриває запис на окремому
екрані, а ‹ на панелі інструментів, системна кнопка «Назад» або жест назад повертають до списку.
Правка на зворотному шляху не втрачається — так само, як на комп’ютері, коли вибрати інший запис;
новий запис, залишений порожнім, відкидається. ☰ висуває поверх списку групи, мітки й кошик.
Меню, генератор і налаштування виринають знизу екрана; «Назад» спершу закриває їх, а діалог —
скасовує. Генератор, налаштування й блокування — у меню ⋯ на панелі інструментів.

На сенсорному екрані немає ні правого клацання, ні перетягування: ⋯ біля групи відкриває меню,
яке на комп’ютері відкриває праве клацання, а його пункт «Перемістити до групи…» робить те саме,
що й перетягування. Меню запису — це його ⋯ на екрані запису.

Файл відкривається лише для читання. На iOS «Зберегти» передає оновлену базу в меню «Поширити»,
де «Зберегти у Файли» може покласти її на місце оригіналу; якщо закрити меню, зміни лишаться
незбереженими. Chrome на Android поширює лише зображення, звук, відео й текст, тому там
«Зберегти» завантажує копію.

На ширшому екрані, а також на планшеті, три панелі лишаються такими, як на комп’ютері; сенсорний
екран будь-якого розміру отримує більші кнопки й ⋯ біля груп.

## Розширення для Chrome

**[Встановити з Chrome Web Store](https://chromewebstore.google.com/detail/hiahfdknjchamepclnokcalkcjcfhahf)**

`npm run build` також записує `build/extension/`: той самий застосунок як розширення для Chrome,
а також його архів `build/password-manager-extension-<version>.zip` для Chrome Web Store. Щоб
спробувати власну збірку: `chrome://extensions` → «Режим розробника» → «Завантажити розпаковане
розширення» → `build/extension`.

Значок на панелі інструментів відкриває компактне спливне вікно: записи для сайту вкладки
(клацання по запису його заповнює), кнопки для копіювання імені користувача, пароля чи
одноразового коду і пошук по всій базі. **Повний режим** унизу вікна відкриває застосунок
у бічній панелі Chrome, поруч зі сторінкою, — у телефонній розкладці, бо панель вузька, — і там
він лишається, хоч би як перемикалися вкладки. Усе працює там так само, як у файлі; розширення
додає заповнення даних для входу:

- **Спливне вікно** відкриває лише майстер-паролем той файл, який панель відкривала останнім:
  файли й файли-ключі вибирає панель, і всі зміни вносить теж вона. На сайті, для якого немає
  запису, його кнопка **Новий пароль** відкриває панель на генераторі, як це робить «Заповнити»
  в меню.
- **Заповнити** в контекстному меню сторінки (праве клацання на сторінці або в полі) вписує ім’я
  користувача й пароль запису для сайту вкладки — або його одноразовий код, на тому кроці входу,
  де його просять. Якщо для сайту є один запис, заповнення відбувається одразу, хоч би панель
  була відкрита, хоч ні; якщо їх кілька, жодного або базу заблоковано, відкривається панель, щоб
  вибрати запис, створити пароль або розблокувати базу, — і далі все продовжується звідти. Вхід
  у два кроки (Google, Microsoft) приймає ім’я користувача на першому кроці, а пароль — на
  другому: запис, вибраний для вкладки, запам’ятовується. Кнопка **Заповнити** запису в панелі
  заповнює цей запис у вкладку.
- **База лишається відкритою**, коли панель закривається, — доки не заблокується: після часу
  простою, заданого в налаштуваннях, коли блокується екран комп’ютера, з панелі, зі спливного
  вікна або через **Заблокувати** в меню значка на панелі інструментів. Відкрита знову, панель
  підхоплює базу без пароля, а спливне вікно показує її одразу.
- **Для цього сайту** вгорі панелі груп показує записи сайту вкладки, і список відкривається
  саме на ньому; він стежить за вкладкою.
- **Новий пароль для сторінки.** На сайті, для якого немає запису, «Заповнити» відкриває
  генератор «Обчислюваний v3» із сайтом вкладки та ім’ям користувача, введеним на сторінці. Його
  кнопка «Заповнити» вписує пароль — в обидва поля реєстраційної форми — і зберігає його як
  звичайний запис.

Запис підходить до вкладки, коли його поле «Сайт» точно називає сайт вкладки: обидві адреси
проходять через `siteOf()` генератора 3 — без схеми, порту, шляху й `www.`, IDN у punycode.
`google.com` не підходить до `accounts.google.com`, а `mail.site.com` — до `site.com`. Запис
із `https://` або без схеми ніколи не заповнюється на сторінці `http://`: для сайту, яким
користуються через http, у полі «Сайт» має стояти `http://`. Записи з кошика не пропонуються,
а запис, вибраний вручну для іншого сайту, заповнюється лише після попередження, де названо обидва.

**Як це влаштовано.** Панель — це сама сторінка: `panel.html`, а її скрипт — у `panel.js`, як того
вимагає Manifest V3. Під час кожного розблокування й збереження вона передає файл і його ключ —
пароль у `ProtectedValue`, файл-ключ — offscreen-документу, який тримає їх у пам’яті разом
із розшифрованою з них копією бази лише для читання аж до блокування; блокування закриває
цей документ, а разом із ним зникає й ключ. Нічого ніде не записується. Меню належать service
worker. Клацання по «Заповнити» може відкрити панель, лише поки ще нічого не очікувалося (await),
тому service worker має одразу знати, чи може він заповнити: він тримає адреси сайтів записів —
без назв, без паролів, — які йому надсилає offscreen-документ, а offscreen-документ не дає йому
зупинитися. Спливне вікно (`popup.html`, `popup.js`) нічого не розшифровує: воно запитує
в offscreen-документа назви й імена користувачів, що підходять до вкладки, а потім — той один
запис, по якому клацнули; коли базу заблоковано, воно читає нещодавній файл і передає його
разом із паролем цьому документу, щоб той його відкрив.

**Що потрапляє на сторінку.**

- Лише те, чого вимагає клацання, і лише значення одного запису. Жоден content script ніде не
  працює: під час клацання `chrome.scripting.executeScript` спершу питає кожен фрейм вкладки,
  де він розташований і які поля для входу має, не надсилаючи жодних значень; потім їх
  отримують лише фрейми сайту запису, а функція ще раз перевіряє власну адресу, перш ніж
  вводити. Фрейм іншого сайту на тій самій сторінці не отримує нічого.
- Заповнюються лише поля, які людина може побачити: показані, увімкнені, доступні для запису,
  ненульового розміру, у межах вікна. Поле, сховане як пастка, лишається порожнім.
- Значення встановлюються з ізольованого світу розширення, в обхід будь-яких сеттерів, які
  сторінка навішує на свої поля введення, а події `input` і `change` повідомляють про це React,
  Vue чи Angular.
- Майстер-пароль, інші записи й список сайтів ніколи не потрапляють на сторінку.

**Дозволи.** `activeTab` замість доступу до всіх сайтів: клацання по значку або по «Заповнити»
дає розширенню цю одну вкладку. Тому панель відкривається зі спливного вікна або з меню, а не
власним налаштуванням Chrome (`openPanelOnActionClick`): панель, відкрита так, не отримує
жодної вкладки. «Заповнити» в панелі на вкладці, яку їй не надали, один раз запитує дозвіл для
сайту запису (`optional_host_permissions`). `contextMenus`, `scripting` і `sidePanel` — для
описаного вище, `offscreen` — для документа, `idle` — для блокування екрана, `clipboardWrite` —
щоб стерти скопійований секрет, коли панель закрита. `externally_connectable` немає: частини
розширення спілкуються через `chrome.runtime`, і кожна приймає повідомлення лише від власних
сторінок розширення. Його сторінки мають `connect-src 'none'`, як і файл; збирання перевіряє
це, а також те, що жодна сторінка не містить вбудованого скрипту чи зовнішньої адреси.

Одна відмінність від файлу: відкрита знову, панель записує базу на місце, лише якщо Chrome досі
це дозволяє; інакше про це повідомляє рядок стану, а перше «Зберегти» запитує дозвіл.

## Безпека

- **Ніщо не залишає сторінку.** Content-Security-Policy у файлі забороняє будь-які мережеві
  запити, надсилання форм і зовнішні ресурси; збирання завершується помилкою, якщо політика
  зникне або з’явиться зовнішнє посилання. Копія для PWA пропускає ще три речі, усі з власного
  джерела: маніфест, service worker і значки — `connect-src` лишається `'none'`.
- Код формату — [kdbxweb](https://github.com/keeweb/kdbxweb), бібліотека, на якій побудовано
  KeeWeb; Argon2 — це WebAssembly з [hash-wasm](https://github.com/Daninet/hash-wasm), який
  також вбудовано у файл.
- Захищені поля зберігаються в пам’яті замаскованими XOR (`ProtectedValue` з kdbxweb), а на
  екрані приховані, доки їх не показати. Пошук ніколи не заглядає в захищені поля.
- **Паролі будь-якою мовою.** Коли браузер вважає поле паролем, macOS вмикає Secure Input
  і примусово перемикає розкладку на латинську, тож майстер-пароль кирилицею ввести неможливо.
  Chrome вважає паролем не лише `type=password`, а й — за евристиками — будь-яке поле, оформлене
  через `-webkit-text-security` або зі значенням із крапок, — і, вирішивши так одного разу, далі
  від цього не відступає. Секретні поля тут такої підказки не дають: це звичайні текстові поля
  з прозорим текстом, поверх яких намальовано шар крапок (моноширинним шрифтом, щоб курсор
  лишався на місці). Позначка показує, чим вводиться прихований текст — кирилицею (РУС) чи
  латиницею (ENG). Ціна цього: Secure Input, який до того ж ховає натискання клавіш від інших
  застосунків, не вмикається ніколи.
- Скопійований секрет стирається з буфера обміну через 30 секунд і під час блокування.
- База блокується після 15 хвилин простою, а також за `⌘L`. Блокування прибирає розшифровану
  базу з пам’яті; блокування з незбереженими змінами, які неможливо записати, чекає, а не
  викидає ці зміни.
- Посилання в записах відкриваються лише для `http`, `https`, `ftp` і `mailto`, з `noopener`.
- Паролі генеруються за допомогою `crypto.getRandomValues` і вибірки з відхиленням: кожен
  символ однаково ймовірний.

## Можливості

- **Групи**: дерево, що згортається; створення, перейменування, видалення через контекстне меню;
  переміщення перетягуванням (записів і груп); панель, розмір якої можна змінювати і яку можна
  сховати (`⌘\`).
- **Записи**: назва, ім’я користувача, пароль, сайт, нотатки, власні поля (відкриті або
  захищені), мітки, дата закінчення терміну дії, вкладення. Сортування за назвою, ім’ям
  користувача, сайтом, датами.
- **Одноразові коди** (TOTP): з поля `otp` (URL `otpauth://` або просто секрет, як їх зберігають
  KeePassXC і KeeWeb), з полів KeePass `TimeOtp-*` або з `TOTP Seed` плагіна TrayTOTP. SHA-1,
  SHA-256, SHA-512; код оновлюється зі зворотним відліком. **+ Одноразовий код** у редакторі
  приймає ключ налаштування, який сайт показує поруч зі своїм QR-кодом (або посилання
  `otpauth://`), і одразу показує код, щоб його можна було підтвердити на сайті; голий ключ
  зберігається як посилання `otpauth://` — у формі, яку читає KeePassXC.
- **Редагування** відбувається в чернетці: «Зберегти» спершу кладе попередній стан в історію
  запису, як це робить KeePass; «Скасувати» відкидає чернетку. Попередні версії можна
  переглядати й відновлювати.
- **Кошик**: видалення переміщує запис до кошика; звідти його можна відновити або видалити
  назавжди.
- **Пошук** за назвою, ім’ям користувача, сайтом, нотатками, мітками, власними полями й назвами
  вкладень; збігтися має кожне слово запиту.
- **Генератор паролів** (кубик, `⌘G`) створює пароль того типу, що вибрано в його списку, —
  найновіший спосіб обчислення стоїть першим; останній вибір запам’ятовується:
  - **Обчислюваний v3** — обчислюється з майстер-пароля, імені користувача, сайту й версії, тож
    його можна обчислити знову й без файлу — див. «[Обчислювані паролі](#обчислювані-паролі)»;
  - **Обчислюваний v2** і **Обчислюваний v1** — обчислювачі двох старіших програм (застарілий
    алгоритм 2 і застарілий алгоритм 1), що з’являються в списку, коли ввімкнено «Налаштування» →
    «Показувати застарілі алгоритми обчислення паролів», — див.
    «[Застарілі алгоритми](#застарілі-алгоритми)»;
  - **Випадковий** — довжина, набори символів, схожі символи, оцінка ентропії.

  Індикатор надійності для введених вручну паролів.
- **База**: перейменування, зміна майстер-пароля й файлу-ключа, збереження копії.
- **Мови**: English, 中文, हिन्दी, Español, Français, العربية, বাংলা, Português, Русский,
  اردو, Bahasa Indonesia, Deutsch, 日本語, मराठी, తెలుగు, Türkçe — шістнадцять найпоширеніших —
  і Українська. Мова вибирається в налаштуваннях або береться з браузера; для арабської та урду
  вікно вибудовується справа наліво.
- **Тема**: як у системі, світла, темна — у налаштуваннях. Мова, тема, ширина панелей,
  сортування, параметри генератора й згорнуті групи запам’ятовуються.

## Обчислювані паролі

**Обчислюваний v3** у генераторі обчислює пароль із

- майстер-пароля бази (файл-ключ, якщо він є, не враховується) або іншого, введеного там же,
- імені користувача,
- сайту — домену, на якому заведено обліковий запис (`https://www.github.com/login` → `github.com`),
- версії — 1, 2, … до 2³² − 1; «+1» дає тому самому обліковому запису новий пароль.

Ці чотири складники дають 32 байти ентропії. Вимоги — довжина, набори символів, схожі символи —
лише перетворюють ці байти на символи: їхня зміна не змінює ентропії. **Використати** кладе
результат у запис як звичайний збережений пароль. Нічого про те, як його отримано, не
зберігається: запис такий самий, як будь-який інший, і інші застосунки KeePass показують той
самий пароль. Якщо файл буде втрачено, той самий майстер-пароль, ім’я користувача, сайт, версія
й вимоги дадуть той самий пароль на будь-якому пристрої. Типові значення — 20 символів, усі
чотири набори, без схожих символів; для пароля, створеного з іншими, їх теж треба пам’ятати.

Генератор спершу запитує ім’я користувача — якщо його відкрито із запису, то ім’я самого запису:
те, що вписано там, з’являється й у формі, — а потім сайт; обидва поля обов’язкові, а пароль,
який вони дають, — унизу, над **Використати**.

- Ім’я користувача, яке є адресою e-mail, саме називає свій сайт: `test@site.com` підставляє
  `site.com`, а поле «Сайт» запису лишається як є — там цілком може бути `mail.site.com`. Проте
  з тією самою адресою входять на багато сайтів, і генератор нагадує про це під полем: для GitHub
  з `test@gmail.com` впишіть `github.com` замість підставленого `gmail.com`.
- Для будь-якого іншого імені користувача сайт треба вписати, і, якщо генератор відкрито
  із запису, вписане стає ще й полем «Сайт» цього запису. Спочатку туди підставляється сайт,
  який у запису вже є.

У тому, що вписано як сайт, не мають значення схема, шлях, порт і `www.` на початку; піддомен
має — `login.github.com` і `github.com` — це два різні сайти. Сайт, який не є URL («Мій банк»),
використовується як є. З панелі інструментів генератор працює так само, з власними полями,
і копіює результат.

«Використовувати майстер-пароль бази» позначено щоразу, коли відкривається генератор. Зніміть
позначку, щоб обчислювати з іншого майстер-пароля, введеного там і ніде не збереженого, — щоб
відновити пароль, створений в іншій базі або до зміни майстер-пароля. Його зміна лишає паролі
у файлі як є; відрізнятиметься лише те, що генератор обчислюватиме відтоді.

### Алгоритм: генератор 3

Усе, що описано нижче, заморожено: зміна будь-якої константи унеможливила б повторне обчислення
кожного пароля, створеного з нею. Майбутній генератор з’явиться як новий тип у списку, а цей
лишиться як є. Код — `src/core/derived.ts`; `npm test` перевіряє його на фіксованих векторах
і на незалежній реалізації, написаній за цим описом за допомогою вбудованого в Node модуля
`crypto`. Примітиви стандартні — SHA-256, HMAC-SHA-256, Argon2id, — тож алгоритм можна
відтворити будь-якою мовою.

Він працює у два етапи: секрети перетворюються на 32 байти ентропії, а потім вимоги вирізають
із цих байтів символи.

**Етап 1 — ентропія.**

1. *Нормалізація вхідних даних.* Усі рядки — у UTF-8.
   - `site` — хост того, що вписано як сайт: текст розбирається як WHATWG URL
     (якщо в тексті немає `scheme://`, спереду додається `https://`): нижній регістр, IDN
     у punycode, без порту, без імені користувача й пароля, `www.` на початку відкидається; текст,
     який не розбирається як URL, використовується як є. Потім — обрізання пробілів, нормалізація
     NFC, переведення в нижній регістр.
   - `user` — ім’я користувача з обрізаними пробілами, нормалізоване NFC; регістр зберігається.
   - `master` — майстер-пароль, нормалізований NFC, нічого не обрізається. «é», введене одним
     символом або як «e» плюс комбінований наголос, дає той самий пароль.
2. *Сіль.*
   ```
   salt = SHA-256( "html-password-manager/derived/v3" ‖ 0x00
                   ‖ u32be(byte length of site) ‖ site
                   ‖ u32be(byte length of user) ‖ user
                   ‖ u32be(version) )
   ```
   Префікси довжини розрізняють `ab` + `c` і `a` + `bc`; мітка відокремлює ці байти від будь-якого
   іншого використання тих самих вхідних даних. `u32be` — 4-байтове ціле число в порядку big-endian.
3. *Розтягування.*
   ```
   entropy = Argon2id(password = master, salt, memory = 64 MiB, passes = 3,
                      lanes = 1, version 0x13, output = 32 bytes)
   ```
   Argon2id змушує кожну спробу вгадати майстер-пароль коштувати 64 MiB пам’яті — саме це
   сповільнює GPU та ASIC. Оскільки сайт, ім’я користувача й версія входять у сіль, кожен обліковий
   запис має власну сіль: жодної таблиці не можна обчислити заздалегідь, і кожен обліковий запис
   доводиться атакувати окремо.

**Етап 2 — формування.** Вимоги використовуються лише тут, тож вони змінюють вигляд пароля,
а не ентропію, що стоїть за ним.

4. *Потік випадкових байтів* потрібної довжини — 32 байтів не вистачає для довгого пароля та
   його перемішування:
   ```
   block(i) = HMAC-SHA-256(key = entropy, "hpm-v3-stream" ‖ u32be(i)),  i = 0, 1, 2, …
   ```
5. *Незміщене число, менше за n.* Візьміть наступні 4 байти потоку як u32 `x` у порядку
   big-endian. Якщо `x ≥ 2³² − (2³² mod n)`, відкиньте його й візьміть наступне; інакше результат —
   `x mod n`. (Просте `x mod n` надавало б перевагу початку алфавіту.)
6. *Символи.* Набори в такому порядку, кожен — лише якщо його вибрано:
   ```
   A–Z      ABCDEFGHIJKLMNOPQRSTUVWXYZ
   a–z      abcdefghijklmnopqrstuvwxyz
   0–9      0123456789
   symbols  !#$%&*+-=?@^_~.,:;()[]{}<>/|
   ```
   Без схожих символів із наборів прибираються `O 0 o I l 1 |`. Далі:
   ```
   chars = []
   for each chosen set:            chars.push(set[draw(|set|)])      # every set is present
   while |chars| < length:         chars.push(all[draw(|all|)])      # all = the sets joined
   for i = length − 1 down to 1:   j = draw(i + 1); swap chars[i], chars[j]   # Fisher–Yates
   password = chars joined
   ```
   Довжина — від 4 до 128. Саме те, що спершу береться по одному символу з кожного набору,
   гарантує «є цифра» і «є спецсимвол»; перемішування ховає, куди ці символи потрапили.

**Тестовий вектор.** Майстер-пароль `Тестовый пароль`, сайт `https://www.github.com/login`
(`github.com`), ім’я користувача `me@example.com`, версія 1, типові вимоги
(20 символів, усі чотири набори, без схожих символів):

```
password  A6qVXXF]7<%a)aa<x7*U
```

Та сама ентропія з 12 символами й без спецсимволів дає `yaM6VJaJFYUQ`; версія 2 з типовими
вимогами дає `3q_bwppbE8P2+ufKr:P6`.

### Наскільки він надійний

- Обчислюваний пароль має щонайбільше 256 біт ентропії (ті самі 32 байти); 20 символів з усіх
  чотирьох наборів без схожих символів — це близько 128 біт. На практиці стелею є майстер-пароль.
- **Слабке місце будь-якої схеми обчислюваних паролів:** пароль, що витік з одного сайту, дає
  зловмисникові змогу підбирати майстер-пароль офлайн, адже сайт та ім’я користувача відомі.
  Кожна спроба коштує одного запуску Argon2id на 64 MiB — близько 0,15–0,4 с у браузері, менше
  на спеціалізованому обладнанні. Короткий або поширений майстер-пароль буде знайдено; довгу
  парольну фразу — ні. Випадкові паролі такої вразливості не мають, тому в генераторі є обидва типи.
- Доки майстер-пароль тримається, пароль, що витік, нічого не розкриває про інші сайти чи
  версії: вони походять з інших солей, а отже, з інших запусків Argon2.

Поки база відкрита, майстер-пароль зберігається в пам’яті замаскованим XOR разом з уже обчисленою
ентропією; блокування прибирає і те, й інше.

## Застарілі алгоритми

Дві старіші програми для Windows обчислювали паролі із секретних фраз; **Обчислюваний v1**
(застарілий алгоритм 1) і **Обчислюваний v2** (застарілий алгоритм 2) у генераторі точно їх
повторюють, тож створені ними паролі можна відновити. Це обчислювачі: нічого з того, що в них
введено, не зберігається, фрази зникають, коли генератор закривається, а **Використати** кладе
результат у запис як звичайний збережений пароль. Щоб вони з’явилися, увімкніть «Налаштування» →
«Показувати застарілі алгоритми обчислення паролів».

Відкриті із запису, обидва пропонують ідентифікатор: ім’я користувача, яке вже називає свій сайт
(`mail@site.com`), — як є, інакше ім’я користувача, `@` і сайт без `www.`
(`dmytro@github.com`); його можна змінити. Кожна фраза — майстер-ключ і вторинний ключ, первинна
й вторинна секретні фрази — має власний прапорець «Пам’ятати до блокування бази»: позначена
фраза зберігається в пам’яті сторінки, замаскована XOR, і підставляється наступного разу; якщо
збережено першу фразу, ключ обчислюється одразу. Обидва алгоритми можуть також узяти як першу
фразу власний майстер-пароль бази — той, яким її відкрито, — як майстер-ключ застарілого
алгоритму 1 або первинну секретну фразу застарілого алгоритму 2 («Використовувати майстер-пароль
бази», запам’ятовується в налаштуваннях для кожного з них): тоді це поле та його прапорець
вимикаються. Нічого з цього не записується на диск; блокування, закриття бази або вимкнення
застарілих алгоритмів стирає все. Код — `src/core/legacy.ts`; `npm test` перевіряє його на
векторах, обчислених оригінальними програмами .NET.

**Застарілий алгоритм 1** — майстер-ключ, ідентифікатор, первинний ключ, вторинний ключ, результат:

```
short(bytes) = Base64(bytes) without "=", "/", "+", first 10 characters
primary key  = short(SHA-1 applied 1 000 000 times to UTF-8(master key ‖ identifier))
result       = short(SHA-1(UTF-8(primary key ‖ secondary key)))
```

Первинний ключ прив’язаний до ідентифікатора, і його можна зберігати окремо (на папері), тож
майстер-ключ не доводиться ніде вводити: первинний ключ можна ввести безпосередньо. Вторинний
ключ робить викрадений папірець марним сам по собі.

**Застарілий алгоритм 2** (Password.Generator 1.0) — первинний захист: ідентифікатор, первинна
секретна фраза, довжина ключа, набори символів; вторинний захист: ключ, вторинна секретна фраза,
версія пароля, довжина пароля, набори символів:

```
digest(a, b, v, n) = SHA-1 applied n times to UTF-8(a) ‖ UTF-8(b) ‖ (v > 0 ? u32le(v) : nothing)
key                = select(digest(identifier, primary phrase, 1, 100 000), key length + 2)
password           = select(digest(key, secondary phrase, version, 1), password length + 2)
```

`select` читає дайджест як п’ять u32 у порядку little-endian, встановлює старший біт кожного,
записує його в системі числення з основою N за алфавітом — `!#$%&'()+,-.` (якщо вибрано),
цифри (завжди), A–Z, a–z (якщо вибрано), — молодшим розрядом уперед, лишає з кожного 5 символів
і обрізає до потрібної довжини (1–18). Перші два символи — підпис, який треба звірити на око з тим,
що показувала програма; решта — ключ або пароль. Версія ключа завжди 1: у програмі немає для
неї поля. Ідентифікатор `1`, фраза `1`, довжина 10, цифри й літери дають ключ `E8 8pgYm9fZha`.

Обидва значно слабші за версію 3: спроба вгадати фрази коштує зловмисникові кількох запусків
SHA-1 замість запуску Argon2id на 64 MiB, а результат застарілого алгоритму 1 — це 10 символів,
близько 60 біт. Використовуйте їх, щоб відновлювати старі паролі, а не для нових.

## Переклади

Англійський текст лишається в коді: `t('menu', 'Delete')`, `tn('status', '{count} entry',
'{count} entries', n)`, а також `data-i18n="context"` / `data-i18n-attr="context"` у шаблоні.
Перший аргумент — контекст, тобто частина інтерфейсу, до якої належить рядок, щоб те саме
англійське слово можна було перекласти по-різному у двох місцях. Словник
`src/locales/<code>.json` зіставляє контекст → англійський текст → переклад:

```json
{
  "menu": { "Delete": "Удалить" },
  "status": { "{count} entries": { "one": "{count} запись", "few": "{count} записи", "many": "{count} записей", "other": "{count} записи" } }
}
```

Рядок, якого немає в словнику, показується англійською. Текст із числом має по одній формі на
кожну категорію множини мови (`Intl.PluralRules`), а ключем слугує англійська форма множини.
`npm run i18n` показує для кожної мови рядки, ще не перекладені, і ті, що більше не
використовуються; `npm test` перевіряє, що кожен переклад зберігає англійські заповнювачі й має
всі форми множини.

Те, що Chrome показує про саме розширення, — його назву й опис, підказку кнопки на панелі
інструментів, — відповідає мові браузера, а не панелі, через `chrome.i18n`. Ці тексти — англійські
в `src/extension/manifest.json`, перекладені в тих самих словниках у контексті `manifest`; збирання
записує їх у `_locales/<code>/messages.json` і ставить у маніфест `__MSG_appName__` тощо.
Chrome має власні коди мов і ігнорує решту: `pt` стає `pt_BR` і `pt_PT`, `zh` — `zh_CN`, а для
урду коду немає, тож там Chrome називає розширення англійською. Збирання зупиняється, якщо назва
довша за 75 символів або опис — за 132.

Цей README теж перекладено: `docs/readme/README.<code>.md`, по одному на мову, зі списком мов
угорі кожного. Зміну, внесену тут, треба внести й у переклади.

## Збирання

```sh
./build.sh         # installs the dependencies if needed, then builds build/password-manager.html
npm install
npm run build      # -> build/password-manager.html
npm run watch      # rebuild on changes in src/
npm run typecheck  # tsc --noEmit
npm test           # opening, editing and saving .kdbx files, the generator, TOTP, derived passwords, matching tabs, the dictionaries
npm run test:browser  # the built page and the extension in headless Chrome
npm run i18n       # strings each dictionary lacks or no longer needs
```

`build.mjs` збирає `src/app/main.ts` за допомогою esbuild в IIFE і підставляє його разом зі стилями
та значком (data URI) у `src/app/template.html`. Запасні варіанти kdbxweb для Node (`crypto`,
`@xmldom/xmldom`) замінюються порожніми заглушками — у браузері є `crypto.subtle`
і `DOMParser`. Результат — `build/password-manager.html`, близько 500 KB, чверть яких припадає на словники.

Той самий запуск записує `build/pages/`: цю сторінку як PWA, яку можна встановити, — `index.html`
із посиланням на маніфест і реєстрацією service worker, `manifest.webmanifest`, значки та
`sw.js`, який кешує сторінку, щоб вона відкривалася без мережі. Сам `build/password-manager.html`
лишається одним файлом без зовнішніх посилань.

А також `build/extension/`: `panel.html` — це шаблон зі скриптом у `panel.js` (той самий
`src/app/main.ts`, де замість `src/app/platform.ts`, чиї хуки у файлі нічого не роблять,
стоїть `src/extension/extension.ts`), поруч — `popup.html` (зі стилями сторінки та `popup.css`)
і `popup.js`, `background.js`, `offscreen.html` і `offscreen.js`, значки та
`manifest.json`, версія якого береться з `package.json`. `build/password-manager-extension-<version>.zip`
містить ті самі файли з фіксованими датами: ті самі вихідні коди дають ті самі байти.

`tests/extension.mjs` завантажує це розширення в headless Chrome через протокол DevTools
(`Extensions.loadUnpacked` через pipe; `--load-extension` прибрано з Chrome, починаючи
з версії 137) і заповнює тестові сайти на локальному сервері: звичайну форму, форму на кшталт
React, вхід у три кроки з одноразовим кодом, фрейми власного сайту й іншого сайту, поля, сховані
як пастки, сторінку http для запису https, реєстрацію, заповнену паролем «Обчислюваний v3», — із
закритою панеллю і після блокування; а також спливне вікно, яке розблоковує, заповнює, шукає,
копіює й блокує. Клацнути контекстне меню з DevTools неможливо, тому тест сам викликає
`onClicked` service worker; без справжнього клацання Chrome не надає `activeTab`, тож копія, яку
тестують, може мати доступ до тестових сайтів `*.test` як host permissions.
Значок на панелі інструментів можна клацнути з DevTools (`Extensions.triggerAction`): окремий
екземпляр Chrome із розширенням у тому вигляді, як його зібрано, перевіряє, що клацання дає
спливному вікну вкладку. Headless Chrome 153 аварійно завершується від цього клацання, хоч би
яким було розширення, і тоді перевірку пропускають; Chrome for Testing її виконує
(`CHROME=/path/to/chrome-for-testing npm run test:browser`).

`tests/fixtures/Database.kdbx` — зразок бази для тестів; її пароль — `Тестовый пароль`.

## Версії та релізи

Версію записано в одному місці — `package.json`. Збирання вставляє її в сторінку (рядок під
екраном входу, низ налаштувань), у `manifest.json` розширення та в назву кешу PWA. Збірка
коміту з тегом `v<version>` показує її як є; будь-яка інша додає свій коміт, `0.8.0+1a2b3c4`,
щоб сторінку з `main` на GitHub Pages не сприйняли за реліз. `version` у Chrome містить лише
числа, тож там коміт іде у `version_name`.

```sh
npm version minor           # 0.7.2 -> 0.8.0: package.json, package-lock.json, a commit and the tag v0.8.0
git push --follow-tags      # the tag starts .github/workflows/release.yml
```

Workflow релізу зупиняється, якщо тег і `package.json` не збігаються, а потім додає до релізу
`password-manager-<tag>.html`, `password-manager-extension-<tag>.zip` і `SHA256SUMS.txt`.

## GitHub Pages

`.github/workflows/pages.yml` збирає й тестує кожен push у `main` і розгортає
`build/pages/` на GitHub Pages (Settings → Pages → Source: GitHub Actions) за адресою
<https://marketkernel.github.io/html-password-manager/>. Файли відкриваються так само, як в
однофайловій версії; нещодавні файли, налаштування й запам’ятовані дескриптори належать цій
адресі, окремо від тих, що має копія, відкрита з диска.

Кожне розгортання змінює назву кешу в `sw.js`, тож браузер сам підхоплює нову версію; відкрите
вікно переходить на неї під час наступного перезавантаження. У цьому ж і компроміс: встановлений
PWA запускає те, що туди поклало останнє розгортання, тоді як завантажений файл лишається тією
версією, якою він є. Щоб мати версію, зафіксовану на диску, візьміть `password-manager-<tag>.html`
з релізу й звірте його з `SHA256SUMS.txt`.

`npm run test:browser` відкриває також `build/pages/`: service worker бере сторінку під свій
контроль, Chrome визнає маніфест придатним для встановлення, а коли сервер зупинено, сторінка
однаково завантажується й відкриває зразок бази.

## Обмеження

- Підтримуються KDBX 3.1 і 4.x; файли, зашифровані Twofish, і файли KeePass 1 (`.kdb`) — ні.
- Немає синхронізації, автонабору (auto-type) чи злиття змінених копій.
- Розширення працює лише в Chrome і не має підказок у полях, збереження пароля під час надсилання
  форми, сполучення клавіш, а запис може мати лише один сайт.
- Записувати файл на місце можуть лише браузери на основі Chromium.
