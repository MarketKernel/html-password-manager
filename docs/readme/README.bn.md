**Deterministic Password** পাসওয়ার্ড শুধু সংরক্ষণই করে না, গণনাও করে। একটি সাইটের পাসওয়ার্ড
আপনার মাস্টার পাসওয়ার্ড, সাইট, ব্যবহারকারীর নাম ও একটি সংস্করণ নম্বর থেকে Argon2id ও
HMAC-SHA-256 দিয়ে উদ্ভূত হয়। ডেটাবেস ফাইল হারিয়ে গেলে একই তথ্য যেকোনো কম্পিউটারে আবার একই
পাসওয়ার্ড দেয় — ফাইল হারানো আর ভয়ের কিছু নয়। কোনো সাইটের পাসওয়ার্ড বদলাতে সংস্করণটি বাড়িয়ে
দিন। এটি কীভাবে কাজ করে: "[উদ্ভূত পাসওয়ার্ড](#উদ্ভূত-পাসওয়ার্ড)"।

এটি একটি পূর্ণাঙ্গ KeePass পাসওয়ার্ড ম্যানেজারও: সাধারণ `.kdbx` ফাইল (KDBX 4, AES-256, Argon2id)
খোলে, সম্পাদনা করে ও সংরক্ষণ করে, তাই একই ডেটাবেস KeePassXC, KeePass বা KeeWeb-এ আগের মতোই
কাজ করে। উদ্ভূত পাসওয়ার্ড এন্ট্রিতে অন্য যেকোনো পাসওয়ার্ডের মতোই সংরক্ষিত হয়, এবং অন্য KeePass
অ্যাপও সেটি একইভাবে দেখায়।

সবকিছু অফলাইনে কাজ করে: কোনো অ্যাকাউন্ট নেই, ক্লাউড নেই, নেটওয়ার্ক অনুরোধ নেই। পুরো অ্যাপটি
একটি স্বতন্ত্র HTML ফাইল; ডেটাবেস পেজের মেমরিতে ডিক্রিপ্ট হয় এবং সরাসরি ডিস্কে ফিরে সংরক্ষিত
হয়, আর মাস্টার পাসওয়ার্ড কখনও পেজের বাইরে যায় না। একই পেজটি একটি
[Chrome এক্সটেনশন](#chrome-এক্সটেনশন)ও, যা পাশের ট্যাবে লগইন পূরণ করে —
**[Chrome Web Store থেকে ইনস্টল করুন](https://chromewebstore.google.com/detail/hiahfdknjchamepclnokcalkcjcfhahf)**।

**[অনলাইন সংস্করণ](https://password.marketkernel.com/)** — PWA (Progressive
Web App) হিসেবে একই পেজ: এটি সিস্টেমে ইনস্টল করা যায়, তারপর নিজস্ব উইন্ডো ও আইকনসহ আলাদা
অ্যাপ হিসেবে চলে এবং অফলাইনেও কাজ করে। কম্পিউটারে Chrome, Edge ও Arc-এ অ্যাড্রেস বারের
ইনস্টল বোতাম ব্যবহার করুন; Android-এ Chrome-এর ⋮ মেনু → অ্যাপ ইনস্টল করুন; iOS-এ Safari বা
Chrome-এ শেয়ার করুন → হোম স্ক্রিনে যোগ করুন। সেখানেও ডেটাবেস আপনার ডিস্কেই থাকে — দেখুন
"[GitHub Pages](#github-pages)"।

## কীভাবে ব্যবহার করবেন

1. `build/password-manager.html` বিল্ড করুন (দেখুন "[বিল্ড](#বিল্ড)") এবং ব্রাউজারে খুলুন —
   সরাসরি ডিস্ক থেকে খুললেও চলবে।
2. "ফাইল খুলুন" → একটি `.kdbx` ডেটাবেস বেছে নিন, অথবা সেটি উইন্ডোতে টেনে আনুন।
3. মাস্টার পাসওয়ার্ড লিখুন (আর ডেটাবেসে কী ফাইল থাকলে সেটিও বেছে নিন) → আনলক করুন।

Chrome, Edge ও Arc-এ ফাইলটি File System Access API দিয়ে খোলা হয়: পরিবর্তনগুলো একই ফাইলে
ফিরে লেখা হয় — স্বয়ংক্রিয় সংরক্ষণ চালু থাকলে প্রতিটি সম্পাদনার একটু পরেই — এবং পরের বার
এলে ফাইলটি আবার খোলার প্রস্তাব দেওয়া হয়; মনে রাখা হয় শুধু এর হ্যান্ডেল, কখনো এর বিষয়বস্তু
বা পাসওয়ার্ড নয়। Safari ও Firefox-এ ফাইলটি শুধু পড়ার জন্য খোলে, এবং সংরক্ষণ করলে ডেটাবেসের
একটি হালনাগাদ কপি ডাউনলোড হয় — ফোনেও তা-ই হয়: Android-এর Chrome-এ File System Access নেই,
আর iOS-এর প্রতিটি ব্রাউজার, Chrome সহ, Safari-র ইঞ্জিনে চলে। iOS-এ সংরক্ষণ বরং কপিটি শেয়ার
মেনুতে পাঠায় — দেখুন "[ফোনে](#ফোনে)"।

"নতুন ডেটাবেস" AES-256 ও Argon2id দিয়ে এনক্রিপ্ট করা একটি খালি KDBX 4 ডেটাবেস তৈরি করে
(64 MiB, 10 পাস — KeePassXC-এর ডিফল্ট, ব্রাউজারে প্রায় আধা সেকেন্ড)।

### ফোনে

900 পিক্সেল প্রস্থ পর্যন্ত — ফোনে, বা খাড়া করে ধরা ট্যাবলেটে — পেজটি একবারে একটি জিনিস দেখায়।
এন্ট্রির তালিকা পুরো স্ক্রিন জুড়ে থাকে; ট্যাপ করলে একটি এন্ট্রি নিজস্ব স্ক্রিনে খোলে, আর
টুলবারের ‹, সিস্টেমের ফিরে যাওয়ার বোতাম বা পেছনের দিকে সোয়াইপ তালিকায় ফিরিয়ে আনে। ফেরার পথে
সম্পাদনা রেখে দেওয়া হয়, যেমন কম্পিউটারে অন্য এন্ট্রি বেছে নিলে রাখা হয়; ফাঁকা রেখে দেওয়া
নতুন এন্ট্রি বাদ পড়ে যায়। ☰ গ্রুপ, ট্যাগ ও রিসাইকেল বিনকে তালিকার ওপর দিয়ে সরিয়ে আনে। মেনু,
জেনারেটর ও সেটিংস স্ক্রিনের নিচ থেকে উঠে আসে; ফিরে যাওয়া আগে এগুলো বন্ধ করে, আর ডায়ালগ
বাতিল করে। জেনারেটর, সেটিংস ও লক টুলবারের ⋯ মেনুতে আছে।

টাচ স্ক্রিনে রাইট ক্লিক নেই, টেনে আনাও নেই: গ্রুপের পাশের ⋯ সেই মেনু খোলে যা কম্পিউটারে
রাইট ক্লিকে খোলে, আর এর "গ্রুপে সরান…" টেনে আনার কাজটিই করে। এন্ট্রির মেনু হলো এন্ট্রির
স্ক্রিনে থাকা এর ⋯।

ফাইলটি শুধু পড়ার জন্য খোলে। iOS-এ সংরক্ষণ হালনাগাদ ডেটাবেসটি শেয়ার মেনুতে পাঠায়, যেখানে
"ফাইলে সংরক্ষণ করুন" সেটিকে মূল ফাইলের জায়গায় রাখতে পারে; মেনু বন্ধ করলে পরিবর্তনগুলো
অসংরক্ষিত থেকে যায়। Android-এর Chrome শুধু ছবি, শব্দ, ভিডিও ও টেক্সট শেয়ার করে, তাই সেখানে
সংরক্ষণ কপিটি ডাউনলোড করে।

এর চেয়ে চওড়া স্ক্রিনে, এবং ট্যাবলেটে, তিনটি প্যানেল কম্পিউটারের মতোই থাকে; যেকোনো আকারের
টাচ স্ক্রিনে বোতামগুলো বড় হয় এবং গ্রুপের পাশে ⋯ থাকে।

## Chrome এক্সটেনশন

**[Chrome Web Store থেকে ইনস্টল করুন](https://chromewebstore.google.com/detail/hiahfdknjchamepclnokcalkcjcfhahf)**

`npm run build` `build/extension/`-ও লেখে: Chrome এক্সটেনশন হিসেবে একই অ্যাপ, এবং Chrome Web
Store-এর জন্য এর `build/password-manager-extension-<version>.zip`। নিজের বিল্ড চালিয়ে দেখতে:
`chrome://extensions` → ডেভেলপার মোড (Developer mode) → আনপ্যাক করা এক্সটেনশন লোড করুন
(Load unpacked) → `build/extension`।

টুলবারের আইকন একটি ছোট পপআপ খোলে: ট্যাবের সাইটের এন্ট্রিগুলো, যেকোনোটিতে ক্লিক করলে সেটি
পূরণ হয়, এর ব্যবহারকারীর নাম, পাসওয়ার্ড বা এককালীন কোড কপি করার বোতাম, এবং পুরো ডেটাবেসে
অনুসন্ধান। এর নিচের **পূর্ণ মোড** অ্যাপটিকে Chrome-এর সাইড প্যানেলে, পেজের পাশে খোলে —
ফোনের লেআউটে, কারণ প্যানেল সরু — এবং সেখানে এটি ট্যাব বদলালেও থেকে যায়। সেখানে সবকিছু
ফাইলের মতোই কাজ করে; এক্সটেনশন যা যোগ করে তা হলো লগইন পূরণ:

- **পপআপ** শুধু মাস্টার পাসওয়ার্ড দিয়ে সেই ফাইলটি আনলক করে, যেটি প্যানেল শেষবার খুলেছিল:
  ফাইল ও কী ফাইল বেছে নেয় প্যানেল, এবং প্রতিটি পরিবর্তনও প্যানেলেই হয়। যে সাইটের কোনো এন্ট্রি
  নেই, সেখানে এর **নতুন পাসওয়ার্ড** প্যানেলটি জেনারেটরে খোলে, যেমন মেনুর পূরণ করুন করে।
- পেজের কনটেক্সট মেনুর **পূরণ করুন** (পেজে বা কোনো ঘরে রাইট ক্লিক) ট্যাবের সাইটের এন্ট্রির
  ব্যবহারকারীর নাম ও পাসওয়ার্ড পূরণ করে — অথবা সাইন-ইনের যে ধাপে এককালীন কোড চাওয়া হয়,
  সেখানে সেই কোড। সাইটের জন্য একটি এন্ট্রি থাকলে এটি সঙ্গে সঙ্গে পূরণ করে, প্যানেল খোলা থাকুক
  বা না থাকুক; কয়েকটি থাকলে, একটিও না থাকলে, বা ডেটাবেস লক থাকলে এটি প্যানেল খোলে — একটি
  বেছে নিতে, পাসওয়ার্ড তৈরি করতে, বা আনলক করতে — এবং সেখান থেকে কাজ চালিয়ে যায়। দুই ধাপের
  সাইন-ইন (Google, Microsoft) প্রথম ধাপে ব্যবহারকারীর নাম আর দ্বিতীয় ধাপে পাসওয়ার্ড নেয়:
  ট্যাবের জন্য বেছে নেওয়া এন্ট্রি মনে রাখা হয়। প্যানেলে কোনো এন্ট্রির **পূরণ করুন** বোতাম সেই
  এন্ট্রিটি ট্যাবে পূরণ করে।
- প্যানেল বন্ধ হলেও **ডেটাবেস খোলা থাকে**, যতক্ষণ না এটি লক হয়: সেটিংসে নির্ধারিত নিষ্ক্রিয়তার
  সময় পেরোলে, কম্পিউটারের স্ক্রিন লক হলে, প্যানেল থেকে, পপআপ থেকে, অথবা টুলবার আইকনের মেনুর
  **লক করুন** থেকে। আবার খুললে প্যানেল পাসওয়ার্ড ছাড়াই এটি হাতে তুলে নেয়, আর পপআপ সঙ্গে সঙ্গে
  এটি দেখায়।
- গ্রুপ প্যানেলের ওপরে **এই সাইটের জন্য** ট্যাবের সাইটের এন্ট্রিগুলো দেখায়, এবং তালিকা এটিতেই
  খোলে; এটি ট্যাবকে অনুসরণ করে।
- **পেজের জন্য নতুন পাসওয়ার্ড।** যে সাইটের কোনো এন্ট্রি নেই, সেখানে পূরণ করুন ট্যাবের সাইট ও
  পেজে লেখা ব্যবহারকারীর নাম নিয়ে উদ্ভূত v3 জেনারেটর খোলে। এর পূরণ করুন বোতাম পাসওয়ার্ডটি
  পূরণ করে — রেজিস্ট্রেশন ফর্মের দুটি ঘরেই — এবং এটিকে একটি সাধারণ এন্ট্রি হিসেবে রেখে দেয়।

কোনো এন্ট্রি তখনই ট্যাবের সঙ্গে মেলে, যখন এর ওয়েবসাইটে হুবহু ট্যাবের সাইটটি থাকে: দুটি
ঠিকানাই জেনারেটর 3-এর `siteOf()` দিয়ে যায় — স্কিম, পোর্ট, পাথ বা `www.` ছাড়া, IDN punycode-এ।
`google.com` `accounts.google.com`-এর সঙ্গে মেলে না, `mail.site.com`-ও `site.com`-এর সঙ্গে
মেলে না। `https://` সহ, বা স্কিম ছাড়া কোনো এন্ট্রি কখনো `http://` পেজে পূরণ হয় না: http দিয়ে
ব্যবহৃত সাইটের ওয়েবসাইটে `http://` থাকা দরকার। রিসাইকেল বিনের এন্ট্রিগুলো দেখানো হয় না, আর
অন্য সাইটের জন্য হাতে বেছে নেওয়া এন্ট্রি দুটি সাইটের নামসহ একটি সতর্কবার্তার পরেই পূরণ হয়।

**এটি কীভাবে তৈরি।** প্যানেলটি পেজটিই: `panel.html`, এর স্ক্রিপ্ট `panel.js`-এ, যেমন
Manifest V3 চায়। প্রতিটি আনলক ও সংরক্ষণে এটি ফাইল ও এর কী — `ProtectedValue`-তে পাসওয়ার্ড,
কী ফাইল — একটি offscreen ডকুমেন্টকে দেয়, যা এগুলো এবং এগুলো থেকে ডিক্রিপ্ট করা ডেটাবেসের
একটি শুধু-পড়ার কপি লক হওয়া পর্যন্ত মেমরিতে রাখে; লক করলে এটি বন্ধ হয়, আর কী-ও এর সঙ্গে
চলে যায়। কোথাও কিছু লেখা হয় না। মেনুগুলো service worker-এর কাছে থাকে। পূরণ করুন-এ ক্লিকের
পর প্যানেল কেবল কোনো কিছুর অপেক্ষা (await) করার আগেই খোলা যায়, তাই worker-কে সঙ্গে সঙ্গে জানতে
হয় সে পূরণ করতে পারবে কি না: offscreen ডকুমেন্ট যেভাবে পাঠায়, সেভাবে এটি এন্ট্রিগুলোর ওয়েবসাইট
রাখে — কোনো নাম নয়, কোনো পাসওয়ার্ড নয় — এবং offscreen ডকুমেন্ট এটিকে চালু রাখে। পপআপ
(`popup.html`, `popup.js`) কিছুই ডিক্রিপ্ট করে না: এটি offscreen ডকুমেন্টের কাছে ট্যাবের সঙ্গে
মেলা শিরোনাম ও ব্যবহারকারীর নাম চায়, তারপর ক্লিক করা একটি এন্ট্রি; লক থাকলে এটি সাম্প্রতিক
ফাইলটি পড়ে এবং পাসওয়ার্ডসহ সেটি খোলার জন্য সেই ডকুমেন্টকে দেয়।

**পেজে কী পৌঁছায়।**

- শুধু ক্লিকে যা চাওয়া হয়, এবং শুধু একটি এন্ট্রির মান। কোথাও কোনো content script চলে না:
  ক্লিকের সময় `chrome.scripting.executeScript` প্রথমে ট্যাবের প্রতিটি ফ্রেমকে জিজ্ঞেস করে সেটি
  কোথায় এবং তাতে কোন কোন লগইনের ঘর আছে, কোনো মান না পাঠিয়ে; তারপর শুধু এন্ট্রির সাইটের
  ফ্রেমগুলো মান পায়, আর ফাংশনটি লেখার আগে নিজের ঠিকানা আবার যাচাই করে। একই পেজে অন্য সাইটের
  ফ্রেম কিছুই পায় না।
- শুধু সেই ঘরগুলো পূরণ হয় যা একজন মানুষ দেখতে পায়: দৃশ্যমান, সক্রিয়, লেখার যোগ্য, কিছুটা
  আকারের, উইন্ডোর ভেতরে। ফাঁদ হিসেবে লুকানো ঘর ফাঁকা থাকে।
- মানগুলো এক্সটেনশনের isolated world থেকে বসানো হয়, পেজ তার ইনপুটে যে setter বসায় তা এড়িয়ে,
  আর `input` ও `change` ইভেন্ট React, Vue বা Angular-কে জানিয়ে দেয়।
- মাস্টার পাসওয়ার্ড, অন্য এন্ট্রি এবং সাইটের তালিকা কখনো কোনো পেজে যায় না।

**অনুমতি।** সব সাইটের বদলে `activeTab`: আইকনে বা পূরণ করুন-এ ক্লিক এক্সটেনশনকে শুধু সেই
একটি ট্যাব দেয়। তাই প্যানেল পপআপ বা মেনু থেকে খোলে, কখনো Chrome-এর নিজস্ব সেটিং
(`openPanelOnActionClick`) দিয়ে নয়: ওভাবে খোলা প্যানেল কোনো ট্যাবই পায় না। যে ট্যাব দেওয়া
হয়নি, সেখানে প্যানেলের পূরণ করুন একবার এন্ট্রির সাইটের অনুমতি চায়
(`optional_host_permissions`)। ওপরের কাজগুলোর জন্য `contextMenus`, `scripting` ও `sidePanel`,
ডকুমেন্টের জন্য `offscreen`, স্ক্রিন লকের জন্য `idle`, প্যানেল বন্ধ থাকা অবস্থায় কপি করা গোপন
তথ্য মুছতে `clipboardWrite`। কোনো `externally_connectable` নেই: এক্সটেনশনের অংশগুলো
`chrome.runtime`-এর মাধ্যমে কথা বলে, এবং প্রত্যেকে শুধু এক্সটেনশনের নিজস্ব পেজ থেকে বার্তা নেয়।
এর পেজগুলোতে `connect-src 'none'` আছে, যেমন ফাইলে আছে; বিল্ড এটি যাচাই করে, এবং এটিও যে কোনো
পেজে ইনলাইন স্ক্রিপ্ট বা বাইরের ঠিকানা নেই।

ফাইলের সঙ্গে একটি পার্থক্য: আবার খোলার পর প্যানেল ডেটাবেসটি একই জায়গায় তখনই লেখে, যদি Chrome
তখনও অনুমতি দেয়; না হলে স্ট্যাটাস বার তা জানায়, এবং প্রথম সংরক্ষণে অনুমতি চাওয়া হয়।

## নিরাপত্তা

- **পেজ থেকে কিছুই বাইরে যায় না।** ফাইলের ভেতরের একটি Content-Security-Policy প্রতিটি নেটওয়ার্ক
  অনুরোধ, ফর্ম জমা ও বাইরের রিসোর্স নিষিদ্ধ করে; নীতিটি হারিয়ে গেলে বা কোনো বাহ্যিক রেফারেন্স
  ঢুকে পড়লে বিল্ড ব্যর্থ হয়। PWA-এর কপি আরও তিনটি জিনিস অনুমতি দেয়, সবই নিজের origin থেকে: manifest,
  service worker ও আইকন — `connect-src` `'none'`-ই থাকে।
- ফরম্যাটের কোড হলো [kdbxweb](https://github.com/keeweb/kdbxweb), যে লাইব্রেরির ওপর KeeWeb
  তৈরি; Argon2 হলো [hash-wasm](https://github.com/Daninet/hash-wasm)-এর WebAssembly, যা-ও ফাইলের
  ভেতরে এম্বেড করা।
- সুরক্ষিত ফিল্ডগুলো মেমরিতে XOR-মাস্ক করে রাখা হয় (kdbxweb-এর `ProtectedValue`) এবং দেখানোর
  আগ পর্যন্ত স্ক্রিনে ঢাকা থাকে। অনুসন্ধান কখনো সুরক্ষিত ফিল্ডে খোঁজে না।
- **যেকোনো ভাষায় পাসওয়ার্ড।** ব্রাউজার যখন কোনো ফিল্ডকে পাসওয়ার্ড বলে ধরে নেয়, macOS Secure
  Input চালু করে এবং জোর করে ল্যাটিন কীবোর্ড লেআউট বসায়, ফলে সিরিলিক মাস্টার পাসওয়ার্ড টাইপ
  করা যায় না। Chrome শুধু `type=password` নয়, হিউরিস্টিক দিয়ে `-webkit-text-security` স্টাইলের
  বা বিন্দুভরা মানের যেকোনো ফিল্ডকেও পাসওয়ার্ড ধরে নেয় — এবং একবার ধরলে তা-ই চালিয়ে যায়।
  এখানের গোপন ফিল্ডগুলো এমন কোনো ইঙ্গিত দেয় না: এগুলো স্বচ্ছ টেক্সটসহ সাধারণ টেক্সট ইনপুট, আর
  এগুলোর ওপর বিন্দুর একটি স্তর আঁকা হয় (monospace ফন্টে, যাতে কার্সার জায়গামতো থাকে)। একটি
  ব্যাজ দেখায় লুকানো টেক্সট সিরিলিকে (РУС) নাকি ল্যাটিনে (ENG) টাইপ হচ্ছে। এর মূল্য: Secure
  Input, যা অন্য অ্যাপ থেকে কীস্ট্রোকও লুকায়, কখনো চালু হয় না।
- কপি করা গোপন তথ্য 30 সেকেন্ড পরে এবং লক করলে ক্লিপবোর্ড থেকে মুছে যায়।
- 15 মিনিট নিষ্ক্রিয় থাকলে এবং `⌘L` চাপলে ডেটাবেস লক হয়। লক করলে ডিক্রিপ্ট করা ডেটাবেস মেমরি
  থেকে সরিয়ে ফেলা হয়; অসংরক্ষিত পরিবর্তন লেখা না গেলে লক পরিবর্তনগুলো ফেলে না দিয়ে অপেক্ষা করে।
- এন্ট্রির লিংক শুধু `http`, `https`, `ftp` ও `mailto`-এর জন্য খোলে, `noopener` সহ।
- পাসওয়ার্ড তৈরি হয় `crypto.getRandomValues` ও rejection sampling দিয়ে: প্রতিটি অক্ষরের সম্ভাবনা
  সমান।

## বৈশিষ্ট্য

- **গ্রুপ**: ভাঁজ করা যায় এমন গাছ, কনটেক্সট মেনু দিয়ে তৈরি, নাম বদলানো ও মোছা, টেনে এনে সরানো
  (এন্ট্রি ও গ্রুপ), আকার বদলানো ও লুকানো যায় এমন প্যানেল (`⌘\`)।
- **এন্ট্রি**: শিরোনাম, ব্যবহারকারীর নাম, পাসওয়ার্ড, ওয়েবসাইট, নোট, কাস্টম ফিল্ড (সাধারণ বা
  সুরক্ষিত), ট্যাগ, মেয়াদ শেষের তারিখ, সংযুক্তি। শিরোনাম, ব্যবহারকারীর নাম, ওয়েবসাইট ও তারিখ
  অনুযায়ী সাজানো।
- **এককালীন কোড** (TOTP): একটি `otp` ফিল্ড থেকে (`otpauth://` URL বা শুধু secret, যেভাবে
  KeePassXC ও KeeWeb রাখে), KeePass-এর `TimeOtp-*` ফিল্ড থেকে, বা TrayTOTP-এর `TOTP Seed`
  থেকে। SHA-1, SHA-256, SHA-512; কাউন্টডাউনসহ কোড হালনাগাদ হয়। এডিটরের **+ এককালীন কোড** সাইটের
  QR কোডের পাশে দেখানো সেটআপ কী (বা একটি `otpauth://` লিংক) নেয় এবং সঙ্গে সঙ্গে কোড দেখায়, যাতে
  সাইটে তা নিশ্চিত করা যায়; শুধু কী দিলে সেটি `otpauth://` লিংক হিসেবে সংরক্ষিত হয় — যে রূপটি
  KeePassXC পড়ে।
- **সম্পাদনা** একটি খসড়ার ওপর চলে: সংরক্ষণ আগে আগের অবস্থাটি এন্ট্রির ইতিহাসে রাখে, যেমন
  KeePass করে; বাতিল খসড়াটি ফেলে দেয়। আগের সংস্করণগুলো দেখা ও পুনরুদ্ধার করা যায়।
- **রিসাইকেল বিন**: মুছলে বিনে চলে যায়; সেখান থেকে — পুনরুদ্ধার বা স্থায়ীভাবে মোছা।
- **অনুসন্ধান** শিরোনাম, ব্যবহারকারীর নাম, ওয়েবসাইট, নোট, ট্যাগ, কাস্টম ফিল্ড ও সংযুক্তির নাম
  জুড়ে; অনুসন্ধানের প্রতিটি শব্দ মিলতে হবে।
- **পাসওয়ার্ড জেনারেটর** (ছক্কা, `⌘G`) এর তালিকায় বেছে নেওয়া ধরনের পাসওয়ার্ড তৈরি করে,
  সবচেয়ে নতুন উদ্ভূত পদ্ধতি সবার আগে; শেষ পছন্দটি মনে রাখা হয়:
  - **উদ্ভূত v3** — মাস্টার পাসওয়ার্ড, ব্যবহারকারীর নাম, সাইট ও একটি সংস্করণ থেকে গণনা করা হয়,
    তাই ফাইল ছাড়াই আবার গণনা করা যায় — দেখুন "[উদ্ভূত পাসওয়ার্ড](#উদ্ভূত-পাসওয়ার্ড)";
  - **উদ্ভূত v2** ও **উদ্ভূত v1** — দুটি পুরনো প্রোগ্রামের ক্যালকুলেটর (পুরনো 2 ও পুরনো 1),
    সেটিংস → "পুরনো পাসওয়ার্ড অ্যালগরিদম দেখান" চালু থাকলে তালিকায় আসে — দেখুন
    "[পুরনো অ্যালগরিদম](#পুরনো-অ্যালগরিদম)";
  - **এলোমেলো** — দৈর্ঘ্য, অক্ষর-সেট, দেখতে একই রকম অক্ষর, এনট্রপির অনুমান।

  টাইপ করা পাসওয়ার্ডের জন্য শক্তি-মাপক।
- **ডেটাবেস**: নাম বদলানো, মাস্টার পাসওয়ার্ড ও কী ফাইল পরিবর্তন, একটি কপি সংরক্ষণ।
- **ভাষা**: English, 中文, हिन्दी, Español, Français, العربية, বাংলা, Português, Русский,
  اردو, Bahasa Indonesia, Deutsch, 日本語, मराठी, తెలుగు, Türkçe — সবচেয়ে বেশি মানুষের বলা ষোলোটি
  ভাষা — এবং Українська। সেটিংসে বেছে নেওয়া যায়, অথবা ব্রাউজার থেকে নেওয়া হয়; আরবি ও উর্দুতে
  উইন্ডো ডান থেকে বাঁয়ে সাজানো হয়।
- **থিম**: সিস্টেম, হালকা, গাঢ় — সেটিংসে। ভাষা, থিম, প্যানেলের প্রস্থ, সাজানোর ক্রম, জেনারেটরের
  বিকল্প ও ভাঁজ করা গ্রুপ মনে রাখা হয়।

## উদ্ভূত পাসওয়ার্ড

জেনারেটরের **উদ্ভূত v3** এগুলো থেকে একটি পাসওয়ার্ড গণনা করে:

- ডেটাবেসের মাস্টার পাসওয়ার্ড (কী ফাইল থাকলে তা বাদ থাকে), অথবা সেখানে লেখা অন্য একটি,
- ব্যবহারকারীর নাম,
- সাইট — যে ডোমেইনে অ্যাকাউন্টটি আছে (`https://www.github.com/login` → `github.com`),
- সংস্করণ — 1, 2, … 2³² − 1 পর্যন্ত; "+1" একই অ্যাকাউন্টকে নতুন পাসওয়ার্ড দেয়।

এই চারটি থেকে 32 বাইট এনট্রপি তৈরি হয়। শর্তগুলো — দৈর্ঘ্য, অক্ষর-সেট, দেখতে একই রকম অক্ষর —
শুধু সেই বাইটগুলোকে অক্ষরের রূপ দেয়: এগুলো বদলালে এনট্রপি বদলায় না। **ব্যবহার করুন** ফলাফলটি
এন্ট্রিতে একটি সাধারণ সংরক্ষিত পাসওয়ার্ড হিসেবে বসায়। এটি কীভাবে তৈরি হলো তার কিছুই রাখা হয়
না: এন্ট্রিটি অন্য যেকোনো এন্ট্রির মতোই, এবং অন্য KeePass অ্যাপও একই পাসওয়ার্ড দেখায়। ফাইল
হারিয়ে গেলে, একই মাস্টার পাসওয়ার্ড, ব্যবহারকারীর নাম, সাইট, সংস্করণ ও শর্ত যেকোনো মেশিনে একই
পাসওয়ার্ড দেয়। ডিফল্ট হলো 20 অক্ষর, চারটি অক্ষর-সেটই, দেখতে একই রকম অক্ষর ছাড়া; অন্য শর্তে
তৈরি পাসওয়ার্ডের জন্য সেই শর্তগুলোও মনে রাখতে হবে।

জেনারেটর প্রথমে ব্যবহারকারীর নাম চায় — এন্ট্রি থেকে খুললে এন্ট্রিরটাই: সেখানে যা লেখা হয় তা
ফর্মেও দেখা যায় — তারপর সাইট; দুটিই আবশ্যক, এবং এগুলো থেকে পাওয়া পাসওয়ার্ড থাকে নিচে,
**ব্যবহার করুন**-এর ওপরে।

- ইমেইল ঠিকানা হলে ব্যবহারকারীর নাম নিজেই তার সাইট বলে দেয়: `test@site.com` থেকে `site.com`
  বসে যায়, আর এন্ট্রির ওয়েবসাইট যেমন আছে তেমনই থাকে — সেটি `mail.site.com` হতেই পারে। তবে একই
  ঠিকানা দিয়ে অনেক সাইটে সাইন ইন করা হয়, এবং জেনারেটর ঘরের নিচে সে কথা জানায়: `test@gmail.com`
  দিয়ে GitHub-এর জন্য, বসানো `gmail.com`-এর জায়গায় `github.com` লিখুন।
- অন্য যেকোনো ব্যবহারকারীর নামের জন্য সাইট লিখতে হয়, আর এন্ট্রি থেকে খুললে যা লেখা হয় সেটিই
  এর ওয়েবসাইটও হয়ে যায়। শুরুতে এন্ট্রির বিদ্যমান ওয়েবসাইট বসানো থাকে।

সাইট হিসেবে যা লেখা হয়, তার স্কিম, পাথ, পোর্ট ও শুরুর `www.`-এর কোনো গুরুত্ব নেই; সাবডোমেইনের
আছে — `login.github.com` ও `github.com` দুটি আলাদা সাইট। যে সাইট URL নয় ("আমার ব্যাংক"), তা যেমন
আছে তেমনই ব্যবহৃত হয়। টুলবার থেকে জেনারেটর একইভাবে কাজ করে, নিজস্ব ঘরসহ, এবং ফলাফল কপি করে।

জেনারেটর যতবার খোলে, "ডেটাবেসের মাস্টার পাসওয়ার্ড ব্যবহার করুন"-এ ততবার টিক দেওয়া থাকে। অন্য
মাস্টার পাসওয়ার্ড থেকে তৈরি করতে টিক সরান — সেটি সেখানেই লেখা হয় এবং কোথাও রাখা হয় না — অন্য
ডেটাবেসে, বা মাস্টার পাসওয়ার্ড বদলানোর আগে তৈরি পাসওয়ার্ড ফিরে পেতে। মাস্টার পাসওয়ার্ড বদলালে
ফাইলের পাসওয়ার্ডগুলো যেমন আছে তেমনই থাকে; শুধু তারপর থেকে জেনারেটর যা গণনা করে তা আলাদা হয়।

### অ্যালগরিদম: জেনারেটর 3

নিচের সবকিছু স্থির: কোনো ধ্রুবক বদলালে এটি দিয়ে তৈরি প্রতিটি পাসওয়ার্ড আর কখনো গণনা করা যাবে
না। ভবিষ্যতের কোনো জেনারেটর তালিকায় নতুন ধরন হিসেবে আসবে এবং এটিকে যেমন আছে তেমনই রাখবে। কোড
হলো `src/core/derived.ts`; `npm test` এটিকে নির্দিষ্ট ভেক্টরের সঙ্গে, এবং এই বর্ণনা থেকে Node-এর
নিজস্ব `crypto` দিয়ে লেখা একটি স্বাধীন বাস্তবায়নের সঙ্গে মিলিয়ে দেখে। মৌলিক উপাদানগুলো প্রচলিত —
SHA-256, HMAC-SHA-256, Argon2id — তাই অ্যালগরিদমটি যেকোনো ভাষায় আবার তৈরি করা যায়।

এটি দুই ধাপে চলে: গোপন তথ্যগুলো 32 বাইট এনট্রপিতে পরিণত হয়, তারপর শর্তগুলো সেই বাইট থেকে
অক্ষর কেটে বের করে।

**ধাপ 1 — এনট্রপি।**

1. *ইনপুট স্বাভাবিকীকরণ।* সব স্ট্রিং UTF-8।
   - `site` — সাইট হিসেবে যা লেখা হয়েছে তার হোস্ট: টেক্সটটিকে WHATWG URL হিসেবে পার্স করা হয়
     (টেক্সটে `scheme://` না থাকলে সামনে `https://` বসানো হয়): ছোট হাতের অক্ষরে, IDN
     punycode-এ, পোর্ট ছাড়া, ব্যবহারকারীর নাম বা পাসওয়ার্ড ছাড়া, শুরুর `www.` বাদ দিয়ে; যে
     টেক্সট URL হিসেবে পার্স হয় না তা যেমন আছে তেমনই ব্যবহৃত হয়। তারপর দুই পাশের ফাঁকা জায়গা
     ছাঁটা, NFC-স্বাভাবিকীকরণ, ছোট হাতের অক্ষরে রূপান্তর।
   - `user` — ব্যবহারকারীর নাম, ছাঁটা ও NFC-স্বাভাবিকীকৃত; অক্ষরের ছোট-বড় যেমন আছে তেমনই থাকে।
   - `master` — মাস্টার পাসওয়ার্ড, NFC-স্বাভাবিকীকৃত, কিছুই ছাঁটা হয় না। এক অক্ষর হিসেবে টাইপ
     করা "é", বা "e" ও একটি সংযুক্ত অ্যাকসেন্ট — দুটিই একই পাসওয়ার্ড দেয়।
2. *সল্ট।*
   ```
   salt = SHA-256( "html-password-manager/derived/v3" ‖ 0x00
                   ‖ u32be(byte length of site) ‖ site
                   ‖ u32be(byte length of user) ‖ user
                   ‖ u32be(version) )
   ```
   দৈর্ঘ্যের উপসর্গগুলো `ab` + `c` ও `a` + `bc`-কে আলাদা রাখে; লেবেলটি এই বাইটগুলোকে একই
   ইনপুটের অন্য যেকোনো ব্যবহার থেকে আলাদা রাখে। `u32be` হলো 4-বাইটের big-endian পূর্ণসংখ্যা।
3. *প্রসারণ।*
   ```
   entropy = Argon2id(password = master, salt, memory = 64 MiB, passes = 3,
                      lanes = 1, version 0x13, output = 32 bytes)
   ```
   Argon2id মাস্টার পাসওয়ার্ডের প্রতিটি অনুমানে 64 MiB মেমরি খরচ করায়, আর এটিই GPU ও ASIC-কে
   ধীর করে দেয়। যেহেতু সাইট, ব্যবহারকারীর নাম ও সংস্করণ সল্টে থাকে, প্রতিটি অ্যাকাউন্টের সল্ট
   নিজস্ব: আগে থেকে কোনো টেবিল গণনা করে রাখা যায় না, এবং প্রতিটি অ্যাকাউন্টে আলাদাভাবে আক্রমণ
   করতে হয়।

**ধাপ 2 — রূপদান।** শর্তগুলো শুধু এখানেই ব্যবহৃত হয়, তাই এগুলো বদলায় পাসওয়ার্ড দেখতে কেমন,
এর পেছনের এনট্রপি নয়।

4. *এলোমেলো বাইটের একটি স্রোত*, যত লম্বা দরকার — লম্বা পাসওয়ার্ড ও তার এলোমেলোকরণের জন্য
   32 বাইট যথেষ্ট নয়:
   ```
   block(i) = HMAC-SHA-256(key = entropy, "hpm-v3-stream" ‖ u32be(i)),  i = 0, 1, 2, …
   ```
5. *n-এর চেয়ে ছোট একটি পক্ষপাতহীন সংখ্যা।* স্রোতের পরের 4 বাইটকে big-endian u32 `x` হিসেবে
   নিন। যদি `x ≥ 2³² − (2³² mod n)` হয়, সেটি বাদ দিয়ে পরেরটি নিন; অন্যথায় ফলাফল `x mod n`।
   (শুধু `x mod n` নিলে বর্ণমালার শুরুর দিকের অক্ষর বেশি আসত।)
6. *অক্ষর।* সেটগুলো, এই ক্রমে, প্রতিটি কেবল বেছে নেওয়া হলে:
   ```
   A–Z      ABCDEFGHIJKLMNOPQRSTUVWXYZ
   a–z      abcdefghijklmnopqrstuvwxyz
   0–9      0123456789
   symbols  !#$%&*+-=?@^_~.,:;()[]{}<>/|
   ```
   দেখতে একই রকম অক্ষর ছাড়া হলে, এগুলো থেকে `O 0 o I l 1 |` সরিয়ে ফেলা হয়। তারপর:
   ```
   chars = []
   for each chosen set:            chars.push(set[draw(|set|)])      # every set is present
   while |chars| < length:         chars.push(all[draw(|all|)])      # all = the sets joined
   for i = length − 1 down to 1:   j = draw(i + 1); swap chars[i], chars[j]   # Fisher–Yates
   password = chars joined
   ```
   দৈর্ঘ্য 4 থেকে 128। প্রথমে প্রতিটি সেট থেকে একটি করে অক্ষর নেওয়াই "একটি সংখ্যা আছে" ও "একটি
   চিহ্ন আছে" নিশ্চিত করে; এলোমেলোকরণ লুকিয়ে রাখে সেই অক্ষরগুলো কোথায় গেল।

**পরীক্ষার ভেক্টর।** মাস্টার পাসওয়ার্ড `Тестовый пароль`, সাইট `https://www.github.com/login`
(`github.com`), ব্যবহারকারীর নাম `me@example.com`, সংস্করণ 1, ডিফল্ট শর্ত
(20 অক্ষর, চারটি সেটই, দেখতে একই রকম অক্ষর ছাড়া):

```
password  A6qVXXF]7<%a)aa<x7*U
```

একই এনট্রপি 12 অক্ষরে ও চিহ্ন ছাড়া দেয় `yaM6VJaJFYUQ`; ডিফল্ট শর্তে সংস্করণ 2 দেয়
`3q_bwppbE8P2+ufKr:P6`।

### এটি কতটা শক্তিশালী

- একটি উদ্ভূত পাসওয়ার্ডে সর্বোচ্চ 256 বিট এনট্রপি থাকে (32 বাইট); দেখতে একই রকম অক্ষর ছাড়া
  চারটি সেট থেকে 20 অক্ষর প্রায় 128 বিট। বাস্তবে সীমা নির্ধারণ করে মাস্টার পাসওয়ার্ড।
- **যেকোনো উদ্ভূত-পাসওয়ার্ড পদ্ধতির দুর্বল দিক:** কোনো সাইট থেকে ফাঁস হওয়া পাসওয়ার্ড দিয়ে
  আক্রমণকারী অফলাইনে মাস্টার পাসওয়ার্ড অনুমান করতে পারে, কারণ সাইট ও ব্যবহারকারীর নাম জানা।
  প্রতিটি অনুমানে 64 MiB-এর ওপর একবার Argon2id চালাতে হয় — ব্রাউজারে প্রায় 0.15–0.4 সেকেন্ড,
  বিশেষায়িত হার্ডওয়্যারে আরও কম। ছোট বা প্রচলিত মাস্টার পাসওয়ার্ড খুঁজে পাওয়া যাবে; লম্বা
  পাসফ্রেজ যাবে না। এলোমেলো পাসওয়ার্ডের এই দুর্বলতা নেই, আর সে কারণেই জেনারেটরে দুটিই আছে।
- যতক্ষণ মাস্টার পাসওয়ার্ড টিকে থাকে, ফাঁস হওয়া একটি পাসওয়ার্ড অন্য সাইট বা সংস্করণ সম্পর্কে
  কিছুই প্রকাশ করে না: সেগুলো অন্য সল্ট থেকে আসে, তাই অন্য Argon2 রান থেকে।

ডেটাবেস খোলা থাকা অবস্থায় মাস্টার পাসওয়ার্ড মেমরিতে XOR-মাস্ক করে রাখা হয়, এখন পর্যন্ত গণনা
করা এনট্রপির সঙ্গে; লক করলে দুটিই মুছে ফেলা হয়।

## পুরনো অ্যালগরিদম

দুটি পুরনো Windows প্রোগ্রাম গোপন বাক্যাংশ থেকে পাসওয়ার্ড গণনা করত; জেনারেটরের **উদ্ভূত v1**
(পুরনো 1) ও **উদ্ভূত v2** (পুরনো 2) হুবহু সেগুলোরই পুনরাবৃত্তি করে, যাতে সেগুলো দিয়ে তৈরি
পাসওয়ার্ড ফিরে পাওয়া যায়। এগুলো ক্যালকুলেটর: এগুলোতে লেখা কিছুই সংরক্ষিত হয় না, জেনারেটর বন্ধ
হলে বাক্যাংশগুলো মুছে যায়, এবং **ব্যবহার করুন** ফলাফলটি এন্ট্রিতে একটি সাধারণ সংরক্ষিত পাসওয়ার্ড
হিসেবে বসায়। সেটিংস → "পুরনো পাসওয়ার্ড অ্যালগরিদম দেখান" এগুলোকে দৃশ্যমান করে।

এন্ট্রি থেকে খুললে দুটিই শনাক্তকারী প্রস্তাব করে: যে ব্যবহারকারীর নাম ইতিমধ্যে তার সাইট বলে দেয়
(`mail@site.com`) সেটি যেমন আছে তেমনই, অন্যথায় ব্যবহারকারীর নাম, `@` এবং `www.` ছাড়া সাইট
(`dmytro@github.com`); এটি বদলানো যায়। প্রতিটি বাক্যাংশের — মাস্টার কী ও মাধ্যমিক কী, প্রাথমিক
ও মাধ্যমিক গোপন বাক্যাংশ — নিজস্ব "ডেটাবেস লক না হওয়া পর্যন্ত মনে রাখুন" বাক্স আছে: টিক দেওয়া
বাক্যাংশ পেজের মেমরিতে XOR-মাস্ক করে রাখা হয় এবং পরের বার বসিয়ে দেওয়া হয়; প্রথম বাক্যাংশ রাখা
থাকলে কী সঙ্গে সঙ্গে গণনা হয়। দুটিই প্রথম বাক্যাংশ হিসেবে ডেটাবেসের নিজস্ব মাস্টার পাসওয়ার্ডও
নিতে পারে — যেটি দিয়ে এটি আনলক করা হয়েছে — পুরনো 1-এর মাস্টার কী বা পুরনো 2-এর প্রাথমিক গোপন
বাক্যাংশ হিসেবে ("ডেটাবেসের মাস্টার পাসওয়ার্ড ব্যবহার করুন", প্রতিটির জন্য সেটিংসে মনে রাখা হয়):
তখন সেই ঘর ও তার বাক্স নিষ্ক্রিয় থাকে। এর কিছুই ডিস্কে লেখা হয় না; লক করলে, ডেটাবেস বন্ধ করলে
বা পুরনো অ্যালগরিদম বন্ধ করলে সব ভুলে যাওয়া হয়। কোড হলো `src/core/legacy.ts`; `npm test` এটিকে
মূল .NET প্রোগ্রামগুলোর গণনা করা ভেক্টরের সঙ্গে মিলিয়ে দেখে।

**পুরনো 1** — মাস্টার কী, শনাক্তকারী, প্রাথমিক কী, মাধ্যমিক কী, ফলাফল:

```
short(bytes) = Base64(bytes) without "=", "/", "+", first 10 characters
primary key  = short(SHA-1 applied 1 000 000 times to UTF-8(master key ‖ identifier))
result       = short(SHA-1(UTF-8(primary key ‖ secondary key)))
```

প্রাথমিক কী শনাক্তকারীর সঙ্গে যুক্ত এবং আলাদা করে (কাগজে) রাখা যায়, তাই মাস্টার কী কোথাও টাইপ
করার দরকার নেই: প্রাথমিক কী সরাসরি লেখা যায়। মাধ্যমিক কী থাকায় চুরি যাওয়া নোট একা কোনো কাজে
আসে না।

**পুরনো 2** (Password.Generator 1.0) — প্রাথমিক সুরক্ষা: শনাক্তকারী, প্রাথমিক গোপন বাক্যাংশ,
কীর দৈর্ঘ্য, অক্ষর-সেট; মাধ্যমিক সুরক্ষা: কী, মাধ্যমিক গোপন বাক্যাংশ, পাসওয়ার্ডের সংস্করণ,
পাসওয়ার্ডের দৈর্ঘ্য, অক্ষর-সেট:

```
digest(a, b, v, n) = SHA-1 applied n times to UTF-8(a) ‖ UTF-8(b) ‖ (v > 0 ? u32le(v) : nothing)
key                = select(digest(identifier, primary phrase, 1, 100 000), key length + 2)
password           = select(digest(key, secondary phrase, version, 1), password length + 2)
```

`select` ডাইজেস্টকে পাঁচটি little-endian u32 হিসেবে পড়ে, প্রতিটির সর্বোচ্চ বিট সেট করে, সেটিকে
বর্ণমালার N ভিত্তিতে লেখে — `!#$%&'()+,-.` (বেছে নেওয়া হলে), সংখ্যা (সবসময়), A–Z, a–z (বেছে
নেওয়া হলে) — সবচেয়ে কম গুরুত্বপূর্ণ অঙ্ক আগে, প্রতিটি থেকে 5টি অক্ষর রাখে এবং দৈর্ঘ্য (1–18)
অনুযায়ী কাটে। প্রথম দুটি অক্ষর একটি স্বাক্ষর, প্রোগ্রাম যেটি দেখাত তার সঙ্গে চোখে মিলিয়ে নেওয়ার
জন্য; বাকিটা কী বা পাসওয়ার্ড। কীর সংস্করণ সবসময় 1: প্রোগ্রামে এর জন্য কোনো ঘর নেই। শনাক্তকারী
`1`, বাক্যাংশ `1`, দৈর্ঘ্য 10, সংখ্যা ও অক্ষর দিলে কী হয় `E8 8pgYm9fZha`।

দুটিই সংস্করণ 3-এর চেয়ে অনেক দুর্বল: বাক্যাংশের একটি অনুমানে আক্রমণকারীর খরচ হয় 64 MiB-এর ওপর
একটি Argon2id রানের বদলে কয়েকটি SHA-1 রান, আর পুরনো 1-এর ফলাফল 10 অক্ষরের, প্রায় 60 বিট।
এগুলো পুরনো পাসওয়ার্ড ফিরে পেতে ব্যবহার করুন, নতুন পাসওয়ার্ডের জন্য নয়।

## অনুবাদ

ইংরেজি টেক্সট কোডেই থাকে: `t('menu', 'Delete')`, `tn('status', '{count} entry',
'{count} entries', n)`, এবং টেমপ্লেটে `data-i18n="context"` / `data-i18n-attr="context"`।
প্রথম আর্গুমেন্টটি হলো প্রসঙ্গ (context) — ইন্টারফেসের যে অংশের স্ট্রিং, যাতে একই ইংরেজি শব্দ
দুই জায়গায় আলাদাভাবে অনুবাদ করা যায়। একটি অভিধান, `src/locales/<code>.json`, প্রসঙ্গ → ইংরেজি
টেক্সট → অনুবাদ ম্যাপ করে:

```json
{
  "menu": { "Delete": "Удалить" },
  "status": { "{count} entries": { "one": "{count} запись", "few": "{count} записи", "many": "{count} записей", "other": "{count} записи" } }
}
```

অভিধানে না থাকা স্ট্রিং ইংরেজিতে দেখানো হয়। সংখ্যাযুক্ত টেক্সটের ভাষার প্রতিটি বহুবচন শ্রেণির
(`Intl.PluralRules`) জন্য একটি করে রূপ থাকে, যার কী হলো ইংরেজি বহুবচন রূপ। `npm run i18n`
প্রতিটি ভাষার জন্য এখনও অনুবাদ না হওয়া এবং আর ব্যবহৃত না হওয়া স্ট্রিংগুলোর তালিকা দেয়;
`npm test` যাচাই করে যে প্রতিটি অনুবাদে ইংরেজি placeholder-গুলো আছে এবং সব বহুবচন রূপ আছে।

Chrome এক্সটেনশনের নিজের যা দেখায় — এর নাম ও বিবরণ, টুলবার বোতামের শিরোনাম — তা `chrome.i18n`-এর
মাধ্যমে প্যানেলের নয়, ব্রাউজারের ভাষা অনুসরণ করে। সেই টেক্সটগুলো হলো `src/extension/manifest.json`-এর
ইংরেজি টেক্সট, একই অভিধানগুলোতে `manifest` প্রসঙ্গে অনূদিত; বিল্ড সেগুলো
`_locales/<code>/messages.json`-এ লেখে এবং manifest-এ `__MSG_appName__` ও এ ধরনের মান বসায়।
Chrome-এর নিজস্ব কোড আছে এবং বাকিগুলো উপেক্ষা করে: `pt` হয় `pt_BR` ও `pt_PT`, `zh` হয়
`zh_CN`, আর উর্দুর কোনো কোড নেই, তাই সেখানে Chrome এক্সটেনশনের নাম ইংরেজিতে দেখায়। নাম 75
অক্ষরের বেশি বা বিবরণ 132 অক্ষরের বেশি হলে বিল্ড থেমে যায়।

এই README-ও অনূদিত: `docs/readme/README.<code>.md`, প্রতিটি ভাষার জন্য একটি, প্রতিটির ওপরে
ভাষার তালিকাসহ। এখানে কোনো পরিবর্তন করলে তা অনুবাদগুলোতেও করতে হবে।

```sh
npm run typecheck  # tsc --noEmit
npm test           # .kdbx ফাইল খোলা, সম্পাদনা ও সংরক্ষণ, জেনারেটর, TOTP, উদ্ভূত পাসওয়ার্ড, ট্যাব মেলানো, অভিধান
npm run test:browser  # headless Chrome-এ বিল্ড করা পেজ ও এক্সটেনশন
npm run i18n       # প্রতিটি অভিধানে যে স্ট্রিং নেই বা যেগুলোর আর দরকার নেই
npm run check      # typecheck, test, build ও test:browser পরপর
npm run shots -- shots/after  # build, তারপর প্রধান স্ক্রিনগুলোর স্ক্রিনশট shots/after-এ
```

`build.mjs` esbuild দিয়ে `src/app/main.ts`-কে একটি IIFE-তে বান্ডল করে এবং স্টাইল ও আইকনসহ
(একটি data URI) সেটিকে `src/app/template.html`-এ বসায়। Node-এর জন্য kdbxweb-এর বিকল্পগুলো
(`crypto`, `@xmldom/xmldom`) খালি stub দিয়ে প্রতিস্থাপিত হয় — ব্রাউজারে `crypto.subtle` ও
`DOMParser` আছে। ফলাফল `build/password-manager.html`, প্রায় 500 KB, যার এক-চতুর্থাংশ অভিধান।

একই রানে `build/pages/`-ও লেখা হয়: সেই পেজটিই ইনস্টলযোগ্য PWA হিসেবে — manifest লিংক ও service
worker নিবন্ধনসহ `index.html`, `manifest.webmanifest`, আইকনগুলো এবং `sw.js`, যা পেজটি ক্যাশ করে
যাতে এটি অফলাইনে খোলে। `build/password-manager.html` নিজে কোনো বাহ্যিক রেফারেন্স ছাড়া একটি
একক ফাইলই থাকে।

এবং `build/extension/`: `panel.html` হলো টেমপ্লেট, যার স্ক্রিপ্ট `panel.js`-এ — একই
`src/app/main.ts`, তবে `src/app/platform.ts`-এর জায়গায় (যার হুকগুলো ফাইলে কিছুই করে না)
`src/extension/extension.ts` নিয়ে — পাশে `popup.html` (পেজের স্টাইল ও `popup.css` সহ) ও
`popup.js`, `background.js`, `offscreen.html` ও `offscreen.js`, আইকনগুলো এবং `manifest.json`, যার
সংস্করণ `package.json`-এর। `build/password-manager-extension-<version>.zip`-এ একই ফাইলগুলো থাকে,
নির্দিষ্ট তারিখসহ: একই সোর্স থেকে একই বাইট আসে।

`tests/extension.mjs` DevTools প্রোটোকলের মাধ্যমে (পাইপের ওপর `Extensions.loadUnpacked`;
সংস্করণ 137 থেকে Chrome-এ `--load-extension` আর নেই) সেই এক্সটেনশনটি headless Chrome-এ লোড
করে এবং একটি স্থানীয় সার্ভারে পরীক্ষামূলক সাইটগুলোতে পূরণ করে: একটি সাধারণ ফর্ম, React-এর মতো
একটি ফর্ম, এককালীন কোডসহ তিন ধাপের একটি সাইন-ইন, সাইটের নিজস্ব ও অন্য সাইটের ফ্রেম, ফাঁদ হিসেবে
লুকানো ঘর, https এন্ট্রির জন্য একটি http পেজ, উদ্ভূত v3 পাসওয়ার্ড দিয়ে পূরণ করা একটি
রেজিস্ট্রেশন — প্যানেল বন্ধ অবস্থায়, এবং লকের পরে; আর পপআপ, যা আনলক করে, পূরণ করে, খোঁজে,
কপি করে ও লক করে। DevTools থেকে কনটেক্সট মেনুতে ক্লিক করা যায় না, তাই পরীক্ষাটি নিজেই worker-এর
`onClicked` চালায়; আসল ক্লিক ছাড়া Chrome কোনো `activeTab` দেয় না, তাই পরীক্ষাধীন কপিটি host
permission হিসেবে পরীক্ষামূলক সাইটগুলোতে, `*.test`-এ, পৌঁছাতে পারে। টুলবারের আইকনে DevTools
থেকে ক্লিক করা যায় (`Extensions.triggerAction`): আলাদা একটি Chrome, বিল্ড করা অবস্থার
এক্সটেনশনসহ, যাচাই করে যে ক্লিকটি পপআপকে ট্যাবটি দেয়। Headless Chrome 153 সেই ক্লিকে ক্র্যাশ
করে, এক্সটেনশন যা-ই হোক, এবং তখন যাচাইটি বাদ দেওয়া হয়; Chrome for Testing এটি চালায়
(`CHROME=/path/to/chrome-for-testing npm run test:browser`)।

`tests/fixtures/Database.kdbx` পরীক্ষার জন্য একটি নমুনা ডেটাবেস; এর পাসওয়ার্ড `Тестовый пароль`।

## সংস্করণ ও রিলিজ

সংস্করণ এক জায়গাতেই লেখা থাকে, `package.json`-এ। বিল্ড এটিকে পেজে (প্রবেশ স্ক্রিনের নিচের লাইন,
সেটিংসের নিচের অংশ), এক্সটেনশনের `manifest.json`-এ এবং PWA-এর ক্যাশের নামে বসায়। `v<version>`
ট্যাগযুক্ত কমিটের বিল্ড এটিকে যেমন আছে তেমনই দেখায়; অন্য যেকোনো বিল্ড এর কমিট যোগ করে,
`0.8.0+1a2b3c4`, যাতে GitHub Pages-এ `main` থেকে আসা পেজকে রিলিজ বলে ভুল না হয়। Chrome-এর
`version`-এ শুধু সংখ্যা থাকে, তাই সেখানে কমিট যায় `version_name`-এ।

```sh
npm version minor           # 0.7.2 -> 0.8.0: package.json, package-lock.json, একটি কমিট ও ট্যাগ v0.8.0
git push --follow-tags      # ট্যাগটি .github/workflows/release.yml চালু করে
```

ট্যাগ ও `package.json` না মিললে রিলিজ workflow থেমে যায়, তারপর
`password-manager-<tag>.html`, `password-manager-extension-<tag>.zip` ও `SHA256SUMS.txt` সংযুক্ত
করে।

## GitHub Pages

`.github/workflows/pages.yml` `main`-এ প্রতিটি push বিল্ড ও পরীক্ষা করে এবং `build/pages/`-কে
GitHub Pages-এ ডিপ্লয় করে (Settings → Pages → Source: GitHub Actions), এই ঠিকানায়:
<https://password.marketkernel.com/>। ফাইল একক ফাইলের মতোই খোলে; সাম্প্রতিক
ফাইল, সেটিংস ও মনে রাখা হ্যান্ডেলগুলো সেই ঠিকানার নিজস্ব, ডিস্ক থেকে খোলা কপির গুলো থেকে আলাদা।

প্রতিটি ডিপ্লয় `sw.js`-এ ক্যাশের নাম বদলায়, তাই ব্রাউজার নিজে থেকেই নতুন সংস্করণ নিয়ে নেয়; খোলা
উইন্ডো পরের রিলোডে সেটিতে চলে যায়। এটাই এর মূল্যও: ইনস্টল করা PWA শেষ ডিপ্লয় যা রেখেছে তা-ই
চালায়, অথচ ডাউনলোড করা ফাইল যে সংস্করণ সেটিই থেকে যায়। ডিস্কে স্থির একটি সংস্করণের জন্য কোনো
রিলিজ থেকে `password-manager-<tag>.html` নিন এবং `SHA256SUMS.txt`-এর সঙ্গে মিলিয়ে নিন।

`npm run test:browser` `build/pages/`-ও খোলে: service worker পেজটির দায়িত্ব নেয়, Chrome
manifest-কে ইনস্টলযোগ্য বলে পায়, এবং সার্ভার বন্ধ হওয়ার পরও পেজটি লোড হয় ও নমুনা ডেটাবেস আনলক
করে।

## সীমাবদ্ধতা

- KDBX 3.1 ও 4.x সমর্থিত; Twofish-এ এনক্রিপ্ট করা এবং KeePass 1 (`.kdb`) ফাইল সমর্থিত নয়।

- এক্সটেনশনটি শুধু Chrome-এর জন্য, এবং এতে ঘরে কোনো পরামর্শ নেই, ফর্ম পাঠানোর সময় পাসওয়ার্ড
  সংরক্ষণ নেই, কীবোর্ড শর্টকাট নেই, এবং প্রতি এন্ট্রিতে একটিই ওয়েবসাইট।
- শুধু Chromium-ভিত্তিক ব্রাউজার ফাইলটি একই জায়গায় লিখতে পারে।
