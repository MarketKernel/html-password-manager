**Deterministic Password** పాస్‌వర్డ్‌లను కేవలం నిల్వ చేయడమే కాదు, వాటిని లెక్కిస్తుంది. ఒక
సైట్ పాస్‌వర్డ్ మీ మాస్టర్ పాస్‌వర్డ్, సైట్, యూజర్‌నేమ్, వెర్షన్ సంఖ్య నుండి Argon2id,
HMAC-SHA-256 ద్వారా లెక్కించబడుతుంది. డేటాబేస్ ఫైల్ పోయినా, అవే వివరాలు ఏ కంప్యూటర్‌లోనైనా
మళ్లీ అవే పాస్‌వర్డ్‌లను ఇస్తాయి — ఫైల్ పోతుందనే భయం ఇక లేదు. ఒక సైట్ పాస్‌వర్డ్‌ను
మార్చడానికి వెర్షన్‌ను పెంచితే చాలు. ఇది ఎలా పనిచేస్తుందో
"[లెక్కించిన పాస్‌వర్డ్‌లు](#లెక్కించిన-పాస్వర్డ్లు)"లో చూడండి.

అదే సమయంలో ఇది పూర్తి స్థాయి KeePass పాస్‌వర్డ్ మేనేజర్ కూడా: సాధారణ `.kdbx` ఫైల్‌లను
(KDBX 4, AES-256, Argon2id) తెరుస్తుంది, ఎడిట్ చేస్తుంది, సేవ్ చేస్తుంది, కాబట్టి అదే డేటాబేస్
KeePassXC, KeePass లేదా KeeWebలో కూడా పనిచేస్తూనే ఉంటుంది. లెక్కించిన పాస్‌వర్డ్ ఎంట్రీలో
మిగతా పాస్‌వర్డ్‌లలాగే నిల్వ అవుతుంది, ఇతర KeePass యాప్‌లు కూడా దాన్ని అలాగే చూపిస్తాయి.

అంతా ఆఫ్‌లైన్‌లో పనిచేస్తుంది: ఖాతా లేదు, క్లౌడ్ లేదు, నెట్‌వర్క్ అభ్యర్థనలు లేవు. యాప్
మొత్తం ఒకే స్వతంత్ర HTML ఫైల్; డేటాబేస్ పేజీ మెమరీలోనే డీక్రిప్ట్ అయి నేరుగా డిస్క్‌కే తిరిగి
సేవ్ అవుతుంది, మాస్టర్ పాస్‌వర్డ్ పేజీని దాటి ఎక్కడికీ వెళ్లదు. ఇదే పేజీ ఒక
[Chrome ఎక్స్‌టెన్షన్](#chrome-ఎక్స్టెన్షన్) కూడా, అది పక్కనే ఉన్న ట్యాబ్‌లో లాగిన్‌లను నింపుతుంది —
**[Chrome Web Store నుండి ఇన్‌స్టాల్ చేయండి](https://chromewebstore.google.com/detail/hiahfdknjchamepclnokcalkcjcfhahf)**.

విండో, సొంత చిహ్నంతో ప్రత్యేక యాప్‌గా నడుస్తుంది, ఆఫ్‌లైన్‌లోనూ పనిచేస్తుంది. కంప్యూటర్‌లో,
Chrome, Edge, Arcలలో అడ్రస్ బార్‌లోని ఇన్‌స్టాల్ బటన్‌ను ఉపయోగించండి; Androidలో, Chrome ⋮
మెనూ → యాప్‌ను ఇన్‌స్టాల్ చేయండి (Install app); iOSలో, Safariలో గానీ Chromeలో గానీ, షేర్
(Share) → హోమ్ స్క్రీన్‌కు జోడించండి (Add to Home Screen). అక్కడ కూడా డేటాబేస్ మీ డిస్క్‌లోనే
ఉంటుంది — "[GitHub Pages](#github-pages)" చూడండి.

## ఎలా ఉపయోగించాలి

1. `build/password-manager.html`ను బిల్డ్ చేయండి ("[బిల్డ్](#బిల్డ్)" చూడండి), దాన్ని బ్రౌజర్‌లో
   తెరవండి — నేరుగా డిస్క్ నుండి తెరిచినా సరిపోతుంది.
2. "ఫైల్‌ను తెరవండి" → `.kdbx` డేటాబేస్‌ను ఎంచుకోండి, లేదా దాన్ని విండోలోకి లాగండి.
3. మాస్టర్ పాస్‌వర్డ్‌ను నమోదు చేయండి (డేటాబేస్‌కు కీ ఫైల్ ఉంటే, దాన్ని కూడా ఎంచుకోండి) →
   "అన్‌లాక్ చేయండి".

Chrome, Edge, Arcలలో ఫైల్ File System Access API ద్వారా తెరుచుకుంటుంది: మార్పులు అదే ఫైల్‌లోకి
తిరిగి రాయబడతాయి — ఆటోసేవ్ ఆన్‌లో ఉంటే, ప్రతి మార్పు జరిగిన కొద్ది క్షణాల్లోనే — తదుపరిసారి
వచ్చినప్పుడు ఆ ఫైల్ మళ్లీ సూచించబడుతుంది: దాని హ్యాండిల్ మాత్రమే గుర్తుంచుకోబడుతుంది, దాని
కంటెంట్ గానీ పాస్‌వర్డ్ గానీ ఎప్పుడూ కాదు. Safari, Firefoxలలో ఫైల్ చదవడానికి మాత్రమే
తెరుచుకుంటుంది, "సేవ్ చేయండి" డేటాబేస్ అప్‌డేట్ చేసిన కాపీని డౌన్‌లోడ్ చేస్తుంది — ఫోన్‌లలో
కూడా అంతే: Androidలోని Chromeలో File System Access లేదు, iOSలోని ప్రతి బ్రౌజర్, Chromeతో
సహా, Safari ఇంజిన్‌పైనే నడుస్తుంది. iOSలో అయితే "సేవ్ చేయండి" కాపీని షేర్ మెనూకు పంపుతుంది —
"[ఫోన్లో](#ఫోన్లో)" చూడండి.

"కొత్త డేటాబేస్" AES-256, Argon2idతో ఎన్‌క్రిప్ట్ చేసిన ఖాళీ KDBX 4 డేటాబేస్‌ను సృష్టిస్తుంది
(64 MiB, 10 పాస్‌లు — KeePassXC డిఫాల్ట్‌లు, బ్రౌజర్‌లో సుమారు అర సెకను).

### ఫోన్లో

900 పిక్సెల్‌ల వెడల్పు వరకు — ఫోన్‌లో, లేదా నిలువుగా పట్టుకున్న టాబ్లెట్‌లో — పేజీ ఒకసారికి
ఒకటే చూపిస్తుంది. ఎంట్రీల జాబితా స్క్రీన్ మొత్తం నిండుతుంది; ఒక ఎంట్రీని తాకితే అది దాని సొంత
స్క్రీన్‌పై తెరుచుకుంటుంది, టూల్‌బార్‌లోని ‹, సిస్టమ్ బ్యాక్ బటన్ లేదా వెనక్కి స్వైప్ చేయడం
జాబితాకు తిరిగి తీసుకువస్తాయి. వెనక్కి వెళ్లేటప్పుడు చేసిన మార్పు అలాగే ఉంటుంది, కంప్యూటర్‌లో
వేరే ఎంట్రీని ఎంచుకున్నప్పుడు ఉన్నట్లే; ఖాళీగా వదిలేసిన కొత్త ఎంట్రీ తీసివేయబడుతుంది. ☰
గ్రూప్‌లు, ట్యాగ్‌లు, రీసైకిల్ బిన్‌ను జాబితాపైకి జారుస్తుంది. మెనూలు, జనరేటర్, సెట్టింగ్‌లు
స్క్రీన్ కింది నుండి పైకి వస్తాయి; బ్యాక్ ముందుగా వాటిని మూసివేస్తుంది, డైలాగ్‌ను రద్దు
చేస్తుంది. జనరేటర్, సెట్టింగ్‌లు, లాక్ టూల్‌బార్‌లోని ⋯ మెనూలో ఉంటాయి.

టచ్ స్క్రీన్‌లో రైట్ క్లిక్ గానీ, లాగడం గానీ ఉండదు: గ్రూప్ పక్కన ఉన్న ⋯ కంప్యూటర్‌లో రైట్ క్లిక్
తెరిచే మెనూనే తెరుస్తుంది, అందులోని "గ్రూప్‌కు తరలించండి…" లాగడం చేసే పనినే చేస్తుంది. ఎంట్రీ
మెనూ అంటే ఆ ఎంట్రీ స్క్రీన్‌పై ఉన్న ⋯.

ఫైల్ చదవడానికి మాత్రమే తెరుచుకుంటుంది. iOSలో "సేవ్ చేయండి" అప్‌డేట్ చేసిన డేటాబేస్‌ను షేర్
మెనూకు పంపుతుంది, అక్కడ "ఫైల్స్‌కు సేవ్ చేయండి" దాన్ని అసలు ఫైల్ స్థానంలో ఉంచగలదు; మెనూను
మూసివేస్తే మార్పులు సేవ్ కాకుండానే ఉండిపోతాయి. Androidలోని Chrome చిత్రాలు, ఆడియో, వీడియో,
టెక్స్ట్‌ను మాత్రమే షేర్ చేస్తుంది, కాబట్టి అక్కడ "సేవ్ చేయండి" కాపీని డౌన్‌లోడ్ చేస్తుంది.

అంతకంటే వెడల్పైన స్క్రీన్‌లపై, టాబ్లెట్‌లో కూడా, మూడు ప్యానెల్‌లు కంప్యూటర్‌లో ఉన్నట్లే
ఉంటాయి; ఏ పరిమాణంలోని టచ్ స్క్రీన్‌కైనా పెద్ద బటన్‌లు, గ్రూప్‌ల పక్కన ⋯ వస్తాయి.

## Chrome ఎక్స్టెన్షన్

**[Chrome Web Store నుండి ఇన్‌స్టాల్ చేయండి](https://chromewebstore.google.com/detail/hiahfdknjchamepclnokcalkcjcfhahf)**

`npm run build` `build/extension/`ను కూడా రాస్తుంది: Chrome ఎక్స్‌టెన్షన్ రూపంలో అదే యాప్, అలాగే
Chrome Web Store కోసం దాని `build/password-manager-extension-<version>.zip`. మీ సొంత బిల్డ్‌ను
ప్రయత్నించడానికి: `chrome://extensions` → డెవలపర్ మోడ్ (Developer mode) → ప్యాక్ చేయనిదాన్ని
లోడ్ చేయండి (Load unpacked) → `build/extension`.

టూల్‌బార్ చిహ్నం ఒక చిన్న పాప్‌అప్‌ను తెరుస్తుంది: ట్యాబ్ సైట్ ఎంట్రీలు, వాటిలో ఒకదాన్ని
నింపడానికి దానిపై ఒక క్లిక్, దాని యూజర్‌నేమ్, పాస్‌వర్డ్ లేదా వన్-టైమ్ కోడ్‌ను కాపీ చేసే
బటన్‌లు, మొత్తం డేటాబేస్‌లో శోధన. దాని కింది భాగంలో ఉన్న **పూర్తి మోడ్** యాప్‌ను Chrome సైడ్
ప్యానెల్‌లో, పేజీ పక్కనే తెరుస్తుంది — ప్యానెల్ ఇరుకుగా ఉంటుంది కాబట్టి ఫోన్ లేఅవుట్‌లో — అక్కడ
అది ట్యాబ్‌లు మారినా అలాగే ఉంటుంది. అక్కడ ప్రతిదీ ఫైల్‌లో లాగే పనిచేస్తుంది; ఎక్స్‌టెన్షన్
అదనంగా ఇచ్చేది లాగిన్‌లను నింపడం:

- **పాప్‌అప్** ప్యానెల్ చివరిసారి తెరిచిన ఫైల్‌ను కేవలం మాస్టర్ పాస్‌వర్డ్‌తోనే అన్‌లాక్
  చేస్తుంది: ఫైల్‌లను, కీ ఫైల్‌లను ఎంచుకునేదీ, ప్రతి మార్పు చేసేదీ ప్యానెలే. ఎంట్రీ లేని సైట్‌లో,
  దాని **కొత్త పాస్‌వర్డ్** ప్యానెల్‌ను జనరేటర్ వద్ద తెరుస్తుంది, మెనూలోని "నింపండి" చేసినట్లే.
- పేజీ కాంటెక్స్ట్ మెనూలోని **నింపండి** (పేజీపై లేదా ఫీల్డ్‌లో రైట్ క్లిక్) ట్యాబ్ సైట్ ఎంట్రీ
  యొక్క యూజర్‌నేమ్, పాస్‌వర్డ్‌ను నింపుతుంది — లేదా సైన్-ఇన్‌లో వన్-టైమ్ కోడ్ అడిగే దశలో, దాని
  వన్-టైమ్ కోడ్‌ను. సైట్‌కు ఒకే ఎంట్రీ ఉంటే వెంటనే నింపుతుంది, ప్యానెల్ తెరిచి ఉన్నా
  లేకపోయినా; చాలా ఉంటే, ఏదీ లేకపోతే, లేదా డేటాబేస్ లాక్ అయి ఉంటే, ఒకదాన్ని ఎంచుకోవడానికి,
  పాస్‌వర్డ్ తయారు చేయడానికి, లేదా అన్‌లాక్ చేయడానికి ప్యానెల్‌ను తెరుస్తుంది — తర్వాత అక్కడి
  నుండి కొనసాగుతుంది. రెండు దశల సైన్-ఇన్ (Google, Microsoft) మొదటి దశలో యూజర్‌నేమ్‌ను, రెండో
  దశలో పాస్‌వర్డ్‌ను తీసుకుంటుంది: ట్యాబ్ కోసం ఎంచుకున్న ఎంట్రీ గుర్తుంచుకోబడుతుంది. ప్యానెల్‌లో
  ఎంట్రీ యొక్క **నింపండి** బటన్ ఆ ఎంట్రీని ట్యాబ్‌లో నింపుతుంది.
- ప్యానెల్ మూసినప్పుడు **డేటాబేస్ తెరిచే ఉంటుంది**, అది లాక్ అయ్యే వరకు: సెట్టింగ్‌లలోని
  నిష్క్రియ సమయం గడిచాక, కంప్యూటర్ స్క్రీన్ లాక్ అయినప్పుడు, ప్యానెల్ నుండి, పాప్‌అప్ నుండి, లేదా
  టూల్‌బార్ చిహ్నం మెనూలోని **లాక్ చేయండి** నుండి. మళ్లీ తెరిచినప్పుడు, ప్యానెల్ పాస్‌వర్డ్
  లేకుండానే దాన్ని అందుకుంటుంది, పాప్‌అప్ దాన్ని వెంటనే చూపిస్తుంది.
- గ్రూప్ ప్యానెల్ పైభాగంలో ఉండే **ఈ సైట్ కోసం** ట్యాబ్ సైట్ ఎంట్రీలను జాబితా చేస్తుంది, జాబితా
  దానితోనే తెరుచుకుంటుంది; ఇది ట్యాబ్‌ను అనుసరిస్తుంది.
- **పేజీ కోసం కొత్త పాస్‌వర్డ్.** ఎంట్రీ లేని సైట్‌లో, "నింపండి" ట్యాబ్ సైట్‌తో, పేజీలో టైప్
  చేసిన యూజర్‌నేమ్‌తో "లెక్కించిన v3" జనరేటర్‌ను తెరుస్తుంది. దాని "నింపండి" బటన్ పాస్‌వర్డ్‌ను
  నింపుతుంది — రిజిస్ట్రేషన్ ఫారమ్‌లోని రెండు ఫీల్డ్‌లలోనూ — దాన్ని సాధారణ ఎంట్రీగా ఉంచుతుంది.

ఒక ఎంట్రీ వెబ్‌సైట్ ట్యాబ్ సైట్‌ను సరిగ్గా సూచించినప్పుడే ఆ ఎంట్రీ ఆ ట్యాబ్‌కు సరిపోతుంది: రెండు
చిరునామాలూ జనరేటర్ 3 యొక్క `siteOf()` గుండా వెళ్తాయి — స్కీమ్, పోర్ట్, పాత్, `www.`
లేకుండా, IDN punycodeలో. `google.com` `accounts.google.com`కు సరిపోదు, అలాగే `mail.site.com`
`site.com`కు సరిపోదు. `https://` ఉన్న, లేదా స్కీమ్ లేని ఎంట్రీ `http://` పేజీలో ఎప్పుడూ
నింపబడదు: http ద్వారా ఉపయోగించే సైట్ వెబ్‌సైట్‌లో `http://` ఉండాలి. రీసైకిల్ బిన్‌లోని ఎంట్రీలు
సూచించబడవు, వేరే సైట్ కోసం చేతితో ఎంచుకున్న ఎంట్రీ రెండు సైట్‌ల పేర్లనూ చెప్పే హెచ్చరిక
తర్వాతే నింపబడుతుంది.

**ఇది ఎలా తయారైంది.** ప్యానెల్ అంటే పేజీయే: `panel.html`, దాని స్క్రిప్ట్ `panel.js`లో,
Manifest V3 కోరినట్లు. ప్రతి అన్‌లాక్, ప్రతి సేవ్‌లో అది ఫైల్‌ను, దాని కీని — `ProtectedValue`లో
పాస్‌వర్డ్, కీ ఫైల్ — ఒక offscreen డాక్యుమెంట్‌కు అప్పగిస్తుంది, అది వాటిని, వాటితో డీక్రిప్ట్
చేసిన డేటాబేస్ యొక్క చదవడానికి మాత్రమే ఉండే కాపీని లాక్ అయ్యే వరకు మెమరీలో ఉంచుతుంది; లాక్
చేస్తే అది మూసివేయబడుతుంది, కీ కూడా దానితో పాటే పోతుంది. ఎక్కడా ఏదీ రాయబడదు. మెనూలు
service workerలో ఉంటాయి. "నింపండి"పై క్లిక్ దేనికోసమైనా వేచి ఉండక ముందే మాత్రమే ప్యానెల్‌ను
తెరవగలదు, కాబట్టి worker తాను నింపగలదో లేదో వెంటనే తెలుసుకోవాలి: offscreen డాక్యుమెంట్
పంపుతున్న కొద్దీ అది ఎంట్రీల వెబ్‌సైట్‌లను ఉంచుకుంటుంది — పేర్లు కాదు, పాస్‌వర్డ్‌లు కాదు —
offscreen డాక్యుమెంట్ దాన్ని నడుస్తూ ఉంచుతుంది. పాప్‌అప్ (`popup.html`, `popup.js`) ఏదీ
డీక్రిప్ట్ చేయదు: ట్యాబ్‌కు సరిపోయే శీర్షికలను, యూజర్‌నేమ్‌లను offscreen డాక్యుమెంట్‌ను
అడుగుతుంది, ఆ తర్వాత క్లిక్ చేసిన ఒక్క ఎంట్రీని మాత్రమే; లాక్ అయి ఉంటే, ఇటీవలి ఫైల్‌ను చదివి,
తెరవడానికి దాన్ని పాస్‌వర్డ్‌తో పాటు ఆ డాక్యుమెంట్‌కు అప్పగిస్తుంది.

**పేజీకి ఏమి చేరుతుంది.**

- క్లిక్ అడిగినది మాత్రమే, అదీ ఒక్క ఎంట్రీ విలువలు మాత్రమే. ఎక్కడా content script నడవదు:
  క్లిక్ చేసినప్పుడు, `chrome.scripting.executeScript` ముందుగా ట్యాబ్‌లోని ప్రతి ఫ్రేమ్‌ను అది
  ఎక్కడ ఉందో, దానిలో ఏయే లాగిన్ ఫీల్డ్‌లు ఉన్నాయో అడుగుతుంది, ఏ విలువలనూ పంపకుండా; ఆ తర్వాత
  ఎంట్రీ సైట్ ఫ్రేమ్‌లకు మాత్రమే అవి అందుతాయి, టైప్ చేసే ముందు ఫంక్షన్ తన సొంత చిరునామాను
  మళ్లీ తనిఖీ చేస్తుంది. అదే పేజీలోని వేరే సైట్ ఫ్రేమ్‌కు ఏమీ అందదు.
- మనిషికి కనిపించే ఫీల్డ్‌లు మాత్రమే నింపబడతాయి: ప్రదర్శించబడినవి, ఎనేబుల్ అయినవి, రాయదగినవి,
  కొంత పరిమాణం ఉన్నవి, విండో లోపల ఉన్నవి. ఉచ్చుగా దాచిన ఫీల్డ్ ఖాళీగానే ఉంటుంది.
- విలువలు ఎక్స్‌టెన్షన్ యొక్క isolated world నుండి సెట్ చేయబడతాయి, పేజీ తన ఇన్‌పుట్‌లపై పెట్టే
  ఏ setterనైనా దాటి, `input`, `change` ఈవెంట్‌లు React, Vue లేదా Angularకు తెలియజేస్తాయి.
- మాస్టర్ పాస్‌వర్డ్, ఇతర ఎంట్రీలు, సైట్‌ల జాబితా ఎప్పుడూ పేజీకి వెళ్లవు.

**అనుమతులు.** ప్రతి సైట్‌కు కాకుండా `activeTab`: చిహ్నంపై లేదా "నింపండి"పై క్లిక్
ఎక్స్‌టెన్షన్‌కు ఆ ఒక్క ట్యాబ్‌ను ఇస్తుంది. అందుకే ప్యానెల్ పాప్‌అప్ నుండి లేదా మెనూ నుండి
తెరుచుకుంటుంది, Chrome సొంత సెట్టింగ్ (`openPanelOnActionClick`) ద్వారా ఎప్పుడూ కాదు: అలా
తెరిచిన ప్యానెల్‌కు ఏ ట్యాబ్ కూడా లభించదు. తనకు ఇవ్వని ట్యాబ్‌లో, ప్యానెల్‌లోని "నింపండి" ఎంట్రీ
సైట్ కోసం ఒకసారి అనుమతి అడుగుతుంది (`optional_host_permissions`). పైన చెప్పినవాటి కోసం
`contextMenus`, `scripting`, `sidePanel`, డాక్యుమెంట్ కోసం `offscreen`, స్క్రీన్ లాక్ కోసం
`idle`, ప్యానెల్ మూసి ఉన్నప్పుడు కాపీ చేసిన రహస్యాన్ని తుడిచివేయడానికి `clipboardWrite`.
`externally_connectable` లేదు: ఎక్స్‌టెన్షన్ భాగాలు `chrome.runtime` ద్వారా మాట్లాడుకుంటాయి,
ప్రతి భాగం ఎక్స్‌టెన్షన్ సొంత పేజీల నుండి మాత్రమే సందేశాలను స్వీకరిస్తుంది. దాని పేజీలకు,
ఫైల్‌కు ఉన్నట్లే, `connect-src 'none'` ఉంటుంది; బిల్డ్ దాన్ని, అలాగే ఏ పేజీలోనూ inline
స్క్రిప్ట్ గానీ బయటి చిరునామా గానీ లేదని తనిఖీ చేస్తుంది.

ఫైల్‌తో ఒక తేడా: మళ్లీ తెరిచినప్పుడు, Chrome ఇంకా అనుమతిస్తేనే ప్యానెల్ డేటాబేస్‌ను అదే
స్థానంలో రాస్తుంది; లేకపోతే స్టేటస్ బార్ ఆ విషయం చెబుతుంది, మొదటి "సేవ్ చేయండి" అనుమతి
అడుగుతుంది.

  అడిగే వరకు స్క్రీన్‌పై కూడా దాచబడి ఉంటాయి. శోధన రక్షిత ఫీల్డ్‌లలోకి ఎప్పుడూ చూడదు.
- **ఏ భాషలోనైనా పాస్‌వర్డ్‌లు.** బ్రౌజర్ ఒక ఫీల్డ్‌ను పాస్‌వర్డ్ ఫీల్డ్‌గా భావించినప్పుడు, macOS
  Secure Inputను ఆన్ చేసి లాటిన్ కీబోర్డ్ లేఅవుట్‌ను బలవంతంగా పెడుతుంది, దాంతో సిరిలిక్ మాస్టర్
  పాస్‌వర్డ్‌ను టైప్ చేయలేం. Chrome `type=password`ను మాత్రమే కాకుండా, హ్యూరిస్టిక్స్ ఆధారంగా,
  `-webkit-text-security`తో స్టైల్ చేసిన లేదా చుక్కలతో కూడిన విలువ ఉన్న ఏ ఫీల్డ్‌నైనా
  పాస్‌వర్డ్‌గా భావిస్తుంది — ఒకసారి అలా భావించాక అలాగే కొనసాగిస్తుంది. ఇక్కడి రహస్య ఫీల్డ్‌లు
  అలాంటి సూచన ఏదీ ఇవ్వవు: అవి పారదర్శక టెక్స్ట్‌తో ఉండే సాధారణ టెక్స్ట్ ఇన్‌పుట్‌లు, వాటిపై
  చుక్కల పొర గీయబడుతుంది (monospace ఫాంట్‌లో, కాబట్టి కర్సర్ తన స్థానంలోనే ఉంటుంది). దాచిన
  టెక్స్ట్ సిరిలిక్‌లో (РУС) టైప్ అవుతోందా లాటిన్‌లో (ENG) టైప్ అవుతోందా అనేది ఒక బ్యాడ్జ్
  చూపిస్తుంది. దీనికి మూల్యం: ఇతర యాప్‌ల నుండి కీస్ట్రోక్‌లను కూడా దాచే Secure Input ఎప్పుడూ
  ఆన్ కాదు.
- కాపీ చేసిన రహస్యం 30 సెకన్ల తర్వాత, అలాగే లాక్ చేసినప్పుడు క్లిప్‌బోర్డ్ నుండి
  తుడిచివేయబడుతుంది.
- 15 నిమిషాలు నిష్క్రియంగా ఉంటే, అలాగే `⌘L` నొక్కినప్పుడు డేటాబేస్ లాక్ అవుతుంది. లాక్ చేస్తే
  డీక్రిప్ట్ చేసిన డేటాబేస్ మెమరీ నుండి తొలగించబడుతుంది; రాయలేని సేవ్ చేయని మార్పులు ఉన్నప్పుడు,
  లాక్ ఆ మార్పులను పారేయకుండా వేచి ఉంటుంది.
- ఎంట్రీలలోని లింక్‌లు `http`, `https`, `ftp`, `mailto` కోసం మాత్రమే, `noopener`తో
  తెరుచుకుంటాయి.
- పాస్‌వర్డ్‌లు `crypto.getRandomValues`, rejection sampling ద్వారా తయారవుతాయి: ప్రతి అక్షరం
  వచ్చే అవకాశం సమానం.

  వారీగా క్రమీకరణ.

## లెక్కించిన పాస్వర్డ్లు

జనరేటర్‌లోని **లెక్కించిన v3** పాస్‌వర్డ్‌ను వీటి నుండి లెక్కిస్తుంది:

- డేటాబేస్ మాస్టర్ పాస్‌వర్డ్ (కీ ఫైల్ ఉన్నా, అది పరిగణనలోకి తీసుకోబడదు), లేదా అక్కడ టైప్
  చేసిన వేరే మాస్టర్ పాస్‌వర్డ్,
- యూజర్‌నేమ్,
- సైట్ — ఖాతా ఉన్న డొమైన్ (`https://www.github.com/login` → `github.com`),
- వెర్షన్ — 1, 2, … 2³² − 1 వరకు; "+1" అదే ఖాతాకు కొత్త పాస్‌వర్డ్‌ను ఇస్తుంది.

ఈ నాలుగూ కలిసి 32 బైట్‌ల ఎంట్రోపీని ఇస్తాయి. అవసరాలు — పొడవు, అక్షర సెట్‌లు, ఒకేలా
కనిపించేవి — ఆ బైట్‌లను అక్షరాలుగా మలచడానికి మాత్రమే: వాటిని మార్చినా ఎంట్రోపీ మారదు.
**ఉపయోగించండి** ఫలితాన్ని ఎంట్రీలో సాధారణంగా నిల్వ చేసిన పాస్‌వర్డ్‌గా ఉంచుతుంది. అది ఎలా
తయారైందనే సమాచారం ఏదీ ఉంచబడదు: ఆ ఎంట్రీ మిగతావాటిలాగే ఉంటుంది, ఇతర KeePass యాప్‌లు అదే
పాస్‌వర్డ్‌ను చూపిస్తాయి. ఫైల్ పోయినా, అదే మాస్టర్ పాస్‌వర్డ్, యూజర్‌నేమ్, సైట్, వెర్షన్,
అవసరాలు ఏ కంప్యూటర్‌లోనైనా అదే పాస్‌వర్డ్‌ను ఇస్తాయి. డిఫాల్ట్‌లు: 20 అక్షరాలు, నాలుగు అక్షర
సెట్‌లూ, ఒకేలా కనిపించే అక్షరాలు లేకుండా; వేరే అవసరాలతో చేసిన పాస్‌వర్డ్ కోసం వాటిని కూడా
గుర్తుంచుకోవాలి.

జనరేటర్ ముందుగా యూజర్‌నేమ్‌ను అడుగుతుంది — ఎంట్రీ నుండి తెరిస్తే, ఆ ఎంట్రీదే: అక్కడ టైప్
చేసినది ఫారమ్‌లో కూడా కనిపిస్తుంది — తర్వాత సైట్‌ను; రెండూ తప్పనిసరి, అవి ఇచ్చే పాస్‌వర్డ్
కింది భాగంలో, **ఉపయోగించండి** పైన ఉంటుంది.

  `test@gmail.com`తో GitHub కోసం, అది పెట్టిన `gmail.com` స్థానంలో `github.com` టైప్ చేయండి.
- ఇతర ఏ యూజర్‌నేమ్‌కైనా సైట్‌ను టైప్ చేయాలి, ఎంట్రీ నుండి తెరిస్తే టైప్ చేసినది దాని
  వెబ్‌సైట్‌గా కూడా మారుతుంది. మొదట ఎంట్రీకి ఇప్పటికే ఉన్న వెబ్‌సైట్ నింపబడి ఉంటుంది.

సైట్‌గా టైప్ చేసినదానిలో స్కీమ్, పాత్, పోర్ట్, మొదట్లో ఉండే `www.` పట్టించుకోబడవు; సబ్‌డొమైన్
మాత్రం ముఖ్యం — `login.github.com`, `github.com` రెండు వేర్వేరు సైట్‌లు. URL కాని సైట్
("నా బ్యాంక్") ఉన్నది ఉన్నట్లే ఉపయోగించబడుతుంది. టూల్‌బార్ నుండి తెరిచినప్పుడు కూడా జనరేటర్
ఇలాగే పనిచేస్తుంది, సొంత ఫీల్డ్‌లతో, ఫలితాన్ని కాపీ చేస్తుంది.

జనరేటర్ తెరిచిన ప్రతిసారీ "డేటాబేస్ మాస్టర్ పాస్‌వర్డ్‌ను ఉపయోగించండి" టిక్ చేసి ఉంటుంది.
వేరే మాస్టర్ పాస్‌వర్డ్ నుండి లెక్కించడానికి టిక్ తీసివేయండి — అది అక్కడే టైప్ చేయబడుతుంది,
ఎక్కడా నిల్వ కాదు — వేరే డేటాబేస్‌లో, లేదా మాస్టర్ పాస్‌వర్డ్ మార్చక ముందు చేసిన పాస్‌వర్డ్‌ను
తిరిగి పొందడానికి. మాస్టర్ పాస్‌వర్డ్‌ను మార్చినా ఫైల్‌లోని పాస్‌వర్డ్‌లు అలాగే ఉంటాయి;
అప్పటి నుండి జనరేటర్ లెక్కించేది మాత్రమే మారుతుంది.

### అల్గారిథమ్: జనరేటర్ 3

కింద ఉన్నదంతా స్థిరం: ఏ స్థిరాంకాన్ని మార్చినా, దానితో చేసిన ప్రతి పాస్‌వర్డ్‌ను మళ్లీ లెక్కించడం
అసాధ్యమవుతుంది. భవిష్యత్ జనరేటర్ జాబితాలో కొత్త రకంగా వస్తుంది, దీన్ని అలాగే వదిలేస్తుంది.
కోడ్ `src/core/derived.ts`లో ఉంది; `npm test` దాన్ని స్థిర వెక్టర్‌లతో, అలాగే ఈ వివరణ ఆధారంగా
Node సొంత `crypto`తో రాసిన స్వతంత్ర అమలుతో పోల్చి తనిఖీ చేస్తుంది. ప్రిమిటివ్‌లు ప్రామాణికమైనవి
— SHA-256, HMAC-SHA-256, Argon2id — కాబట్టి అల్గారిథమ్‌ను ఏ భాషలోనైనా మళ్లీ నిర్మించవచ్చు.

ఇది రెండు దశల్లో నడుస్తుంది: రహస్యాలు 32 బైట్‌ల ఎంట్రోపీగా మారతాయి, తర్వాత అవసరాలు ఆ బైట్‌ల
నుండి అక్షరాలను మలుస్తాయి.

**దశ 1 — ఎంట్రోపీ.**

1. *ఇన్‌పుట్‌లను సాధారణీకరించడం.* అన్ని స్ట్రింగ్‌లు UTF-8లో ఉంటాయి.
   - `site` — సైట్‌గా టైప్ చేసినదాని హోస్ట్: టెక్స్ట్‌ను WHATWG URLగా పార్స్ చేస్తారు
     (టెక్స్ట్‌లో `scheme://` లేకపోతే ముందు `https://` జోడిస్తారు): చిన్న అక్షరాలు, IDN
     punycodeలో, పోర్ట్ లేకుండా, యూజర్‌నేమ్ లేదా పాస్‌వర్డ్ లేకుండా, మొదట్లో ఉండే `www.`
     తీసివేయబడుతుంది; URLగా పార్స్ కాని టెక్స్ట్ ఉన్నది ఉన్నట్లే ఉపయోగించబడుతుంది. ఆ తర్వాత
     అంచుల్లోని ఖాళీలు తీసివేయబడతాయి, NFC-సాధారణీకరణ, చిన్న అక్షరాలకు మార్పు జరుగుతాయి.
   - `user` — యూజర్‌నేమ్, అంచుల్లోని ఖాళీలు తీసివేసి NFC-సాధారణీకరించినది; అక్షరాల కేస్ అలాగే
     ఉంటుంది.
   - `master` — మాస్టర్ పాస్‌వర్డ్, NFC-సాధారణీకరించినది, ఖాళీలు ఏవీ తీసివేయబడవు. ఒకే అక్షరంగా
     టైప్ చేసిన "é", "e" తర్వాత కలిపే యాస గుర్తుగా టైప్ చేసిన "é" ఒకే పాస్‌వర్డ్‌ను ఇస్తాయి.
2. *సాల్ట్.*
   ```
   salt = SHA-256( "html-password-manager/derived/v3" ‖ 0x00
                   ‖ u32be(byte length of site) ‖ site
                   ‖ u32be(byte length of user) ‖ user
                   ‖ u32be(version) )
   ```
   పొడవు ప్రిఫిక్స్‌లు `ab` + `c`ని, `a` + `bc`ని వేరుగా ఉంచుతాయి; లేబుల్ ఈ బైట్‌లను అవే
   ఇన్‌పుట్‌ల ఇతర ఏ ఉపయోగం నుండైనా వేరుగా ఉంచుతుంది. `u32be` అనేది 4-బైట్ big-endian పూర్ణాంకం.
3. *సాగదీయడం (stretching).*
   ```
   entropy = Argon2id(password = master, salt, memory = 64 MiB, passes = 3,
                      lanes = 1, version 0x13, output = 32 bytes)
   ```
   Argon2id మాస్టర్ పాస్‌వర్డ్ యొక్క ప్రతి ఊహకు 64 MiB మెమరీ ఖర్చయ్యేలా చేస్తుంది, ఇదే GPUలను,
   ASICలను నెమ్మదింపజేస్తుంది. సైట్, యూజర్‌నేమ్, వెర్షన్ సాల్ట్‌లో ఉన్నందున ప్రతి ఖాతాకు సొంత
   సాల్ట్ ఉంటుంది: ముందుగా ఏ పట్టికనూ లెక్కించలేరు, ప్రతి ఖాతాపై విడిగా దాడి చేయాల్సి ఉంటుంది.

**దశ 2 — రూపమివ్వడం.** అవసరాలు ఇక్కడ మాత్రమే ఉపయోగించబడతాయి, కాబట్టి అవి పాస్‌వర్డ్ ఎలా
కనిపిస్తుందో మారుస్తాయి, దాని వెనుక ఉన్న ఎంట్రోపీని కాదు.

4. *యాదృచ్ఛిక బైట్‌ల ప్రవాహం*, ఎంత కావాలంటే అంత పొడవు — పొడవైన పాస్‌వర్డ్‌కు, దాని షఫుల్‌కు
   32 బైట్‌లు సరిపోవు:
   ```
   block(i) = HMAC-SHA-256(key = entropy, "hpm-v3-stream" ‖ u32be(i)),  i = 0, 1, 2, …
   ```
5. *n కంటే తక్కువ ఉండే, పక్షపాతం లేని సంఖ్య.* ప్రవాహంలోని తదుపరి 4 బైట్‌లను big-endian u32
   `x`గా తీసుకోండి. `x ≥ 2³² − (2³² mod n)` అయితే, దాన్ని వదిలేసి తర్వాతిది తీసుకోండి;
   లేకపోతే ఫలితం `x mod n`. (కేవలం `x mod n` అయితే అక్షరమాల ప్రారంభంలోని అక్షరాలకే మొగ్గు
   ఉంటుంది.)
6. *అక్షరాలు.* సెట్‌లు, ఈ క్రమంలో, ఒక్కొక్కటి ఎంచుకుంటేనే:
   ```
   A–Z      ABCDEFGHIJKLMNOPQRSTUVWXYZ
   a–z      abcdefghijklmnopqrstuvwxyz
   0–9      0123456789
   symbols  !#$%&*+-=?@^_~.,:;()[]{}<>/|
   ```
   ఒకేలా కనిపించేవి లేకుండా అయితే, వాటి నుండి `O 0 o I l 1 |` తీసివేయబడతాయి. తర్వాత:
   ```
   chars = []
   for each chosen set:            chars.push(set[draw(|set|)])      # every set is present
   while |chars| < length:         chars.push(all[draw(|all|)])      # all = the sets joined
   for i = length − 1 down to 1:   j = draw(i + 1); swap chars[i], chars[j]   # Fisher–Yates
   password = chars joined
   ```
   పొడవు 4 నుండి 128 వరకు. ముందుగా ప్రతి సెట్ నుండి ఒక అక్షరం తీసుకోవడమే "అంకె ఉంది",
   "చిహ్నం ఉంది" అనేవాటికి హామీ ఇస్తుంది; ఆ అక్షరాలు ఎక్కడికి వెళ్లాయో షఫుల్ దాచిపెడుతుంది.

**టెస్ట్ వెక్టర్.** మాస్టర్ పాస్‌వర్డ్ `Тестовый пароль`, సైట్ `https://www.github.com/login`
(`github.com`), యూజర్‌నేమ్ `me@example.com`, వెర్షన్ 1, డిఫాల్ట్ అవసరాలు
(20 అక్షరాలు, నాలుగు సెట్‌లూ, ఒకేలా కనిపించేవి లేకుండా):

```
password  A6qVXXF]7<%a)aa<x7*U
```

అదే ఎంట్రోపీ 12 అక్షరాలతో, చిహ్నాలు లేకుండా `yaM6VJaJFYUQ`ను ఇస్తుంది; డిఫాల్ట్‌లతో వెర్షన్ 2
`3q_bwppbE8P2+ufKr:P6`ను ఇస్తుంది.

### ఇది ఎంత బలమైనది

- లెక్కించిన పాస్‌వర్డ్‌కు గరిష్ఠంగా 256 బిట్‌ల ఎంట్రోపీ ఉంటుంది (32 బైట్‌లు); ఒకేలా కనిపించేవి
  లేకుండా నాలుగు సెట్‌ల నుండి 20 అక్షరాలు అంటే సుమారు 128 బిట్‌లు. ఆచరణలో పరిమితి మాస్టర్
  పాస్‌వర్డే.
- **లెక్కించిన పాస్‌వర్డ్‌ల ఏ పద్ధతికైనా బలహీనమైన చోటు:** ఒక సైట్ నుండి లీక్ అయిన పాస్‌వర్డ్‌తో
  దాడి చేసేవారు మాస్టర్ పాస్‌వర్డ్‌ను ఆఫ్‌లైన్‌లో ఊహించగలరు, ఎందుకంటే సైట్, యూజర్‌నేమ్
  తెలిసినవే. ప్రతి ఊహకు 64 MiBపై ఒక Argon2id రన్ ఖర్చవుతుంది — బ్రౌజర్‌లో సుమారు 0.15–0.4 సె.,
  ప్రత్యేక హార్డ్‌వేర్‌పై ఇంకా తక్కువ. చిన్న లేదా సాధారణమైన మాస్టర్ పాస్‌వర్డ్ దొరికిపోతుంది;
  పొడవైన పాస్‌ఫ్రేజ్ దొరకదు. యాదృచ్ఛిక పాస్‌వర్డ్‌లకు ఈ బలహీనత లేదు, అందుకే జనరేటర్‌లో రెండూ
  ఉన్నాయి.
- మాస్టర్ పాస్‌వర్డ్ నిలబడినంత కాలం, లీక్ అయిన పాస్‌వర్డ్ ఇతర సైట్‌లు లేదా వెర్షన్‌ల గురించి
  ఏమీ బయటపెట్టదు: అవి వేరే సాల్ట్‌ల నుండి, అంటే వేరే Argon2 రన్‌ల నుండి వస్తాయి.

డేటాబేస్ తెరిచి ఉన్నంత సేపు మాస్టర్ పాస్‌వర్డ్ మెమరీలో XOR-మాస్క్ చేసి ఉంచబడుతుంది, ఇప్పటి
వరకు లెక్కించిన ఎంట్రోపీతో పాటు; లాక్ చేస్తే రెండూ తొలగించబడతాయి.

## పాత అల్గారిథమ్లు

రెండు పాత Windows ప్రోగ్రామ్‌లు రహస్య పదబంధాల నుండి పాస్‌వర్డ్‌లను లెక్కించేవి; జనరేటర్‌లోని
**లెక్కించిన v1** (లెగసీ 1), **లెక్కించిన v2** (లెగసీ 2) వాటిని యథాతథంగా పునరావృతం చేస్తాయి,
కాబట్టి వాటితో చేసిన పాస్‌వర్డ్‌లను తిరిగి పొందవచ్చు. ఇవి కాలిక్యులేటర్‌లు: వాటిలో టైప్ చేసినది
ఏదీ సేవ్ కాదు, జనరేటర్ మూసినప్పుడు పదబంధాలు పోతాయి, **ఉపయోగించండి** ఫలితాన్ని ఎంట్రీలో
సాధారణంగా నిల్వ చేసిన పాస్‌వర్డ్‌గా ఉంచుతుంది. సెట్టింగ్‌లు → "పాత పాస్‌వర్డ్ అల్గారిథమ్‌లను
చూపండి" వాటిని కనిపించేలా చేస్తుంది.

ఎంట్రీ నుండి తెరిచినప్పుడు, రెండూ ఐడెంటిఫైయర్‌ను సూచిస్తాయి: ఇప్పటికే తన సైట్‌ను సూచించే
యూజర్‌నేమ్ (`mail@site.com`) అయితే అలాగే, లేకపోతే యూజర్‌నేమ్, `@`, `www.` లేని సైట్
(`dmytro@github.com`); దీన్ని మార్చవచ్చు. ప్రతి పదబంధానికీ — మాస్టర్ కీ, ద్వితీయ కీ, ప్రాథమిక
రహస్య పదబంధం, ద్వితీయ రహస్య పదబంధం — సొంత "డేటాబేస్ లాక్ అయ్యే వరకు గుర్తుంచుకోండి" బాక్స్
ఉంటుంది: టిక్ చేసినది పేజీ మెమరీలో XOR-మాస్క్ చేసి ఉంచబడుతుంది, తదుపరిసారి నింపబడుతుంది;
మొదటి పదబంధం ఉంచబడి ఉంటే, కీ వెంటనే లెక్కించబడుతుంది. రెండూ డేటాబేస్ సొంత మాస్టర్ పాస్‌వర్డ్‌ను
— దాన్ని అన్‌లాక్ చేసిన పాస్‌వర్డ్‌ను — తమ మొదటి పదబంధంగా కూడా తీసుకోగలవు: లెగసీ 1 మాస్టర్
కీగా, లెగసీ 2 ప్రాథమిక రహస్య పదబంధంగా ("డేటాబేస్ మాస్టర్ పాస్‌వర్డ్‌ను ఉపయోగించండి",
ఒక్కోదానికీ విడిగా సెట్టింగ్‌లలో గుర్తుంచుకోబడుతుంది): అప్పుడు ఆ ఫీల్డ్, దాని బాక్స్ ఆఫ్
అవుతాయి. ఇందులో ఏదీ డిస్క్‌కు రాయబడదు; లాక్ చేస్తే, డేటాబేస్‌ను మూసివేస్తే లేదా పాత
అల్గారిథమ్‌లను ఆఫ్ చేస్తే అవన్నీ మర్చిపోబడతాయి. కోడ్ `src/core/legacy.ts`లో ఉంది; `npm test`
దాన్ని అసలు .NET ప్రోగ్రామ్‌లు లెక్కించిన వెక్టర్‌లతో పోల్చి తనిఖీ చేస్తుంది.

**లెగసీ 1** — మాస్టర్ కీ, ఐడెంటిఫైయర్, ప్రాథమిక కీ, ద్వితీయ కీ, ఫలితం:

```
short(bytes) = Base64(bytes) without "=", "/", "+", first 10 characters
primary key  = short(SHA-1 applied 1 000 000 times to UTF-8(master key ‖ identifier))
result       = short(SHA-1(UTF-8(primary key ‖ secondary key)))
```

ప్రాథమిక కీ ఐడెంటిఫైయర్‌తో ముడిపడి ఉంటుంది, దాన్ని విడిగా (కాగితంపై) ఉంచవచ్చు, కాబట్టి
మాస్టర్ కీని ఎక్కడా టైప్ చేయాల్సిన అవసరం లేదు: ప్రాథమిక కీని నేరుగా నమోదు చేయవచ్చు. ద్వితీయ
కీ వల్ల దొంగిలించిన నోట్ ఒక్కటే దేనికీ పనికిరాదు.

**లెగసీ 2** (Password.Generator 1.0) — ప్రాథమిక రక్షణ: ఐడెంటిఫైయర్, ప్రాథమిక రహస్య పదబంధం,
కీ పొడవు, అక్షర సెట్‌లు; ద్వితీయ రక్షణ: కీ, ద్వితీయ రహస్య పదబంధం, పాస్‌వర్డ్ వెర్షన్,
పాస్‌వర్డ్ పొడవు, అక్షర సెట్‌లు:

```
digest(a, b, v, n) = SHA-1 applied n times to UTF-8(a) ‖ UTF-8(b) ‖ (v > 0 ? u32le(v) : nothing)
key                = select(digest(identifier, primary phrase, 1, 100 000), key length + 2)
password           = select(digest(key, secondary phrase, version, 1), password length + 2)
```

`select` డైజెస్ట్‌ను ఐదు little-endian u32లుగా చదువుతుంది, ఒక్కోదాని పై బిట్‌ను సెట్ చేస్తుంది,
దాన్ని అక్షరమాల యొక్క N ఆధారంలో (base N) రాస్తుంది — `!#$%&'()+,-.` (ఎంచుకుంటే), అంకెలు
(ఎల్లప్పుడూ), A–Z, a–z (ఎంచుకుంటే) — తక్కువ ప్రాముఖ్యత ఉన్న అంకె మొదట, ఒక్కోదాని నుండి 5
అక్షరాలను ఉంచి, పొడవుకు (1–18) కత్తిరిస్తుంది. మొదటి రెండు అక్షరాలు ప్రోగ్రామ్ చూపించినదానితో
కంటితో పోల్చడానికి ఒక సంతకం; మిగిలినది కీ లేదా పాస్‌వర్డ్. కీ వెర్షన్ ఎల్లప్పుడూ 1:
ప్రోగ్రామ్‌లో దానికి ఫీల్డ్ లేదు. ఐడెంటిఫైయర్ `1`, పదబంధం `1`, పొడవు 10, అంకెలు, అక్షరాలు కలిసి
కీ `E8 8pgYm9fZha`ను ఇస్తాయి.

ఈ రెండూ వెర్షన్ 3 కంటే చాలా బలహీనమైనవి: పదబంధాలపై ఒక ఊహకు దాడి చేసేవారికి 64 MiBపై ఒక
Argon2id రన్‌కు బదులు కొన్ని SHA-1 రన్‌లు మాత్రమే ఖర్చవుతాయి, లెగసీ 1 ఫలితం 10 అక్షరాలు,
సుమారు 60 బిట్‌లు. పాత పాస్‌వర్డ్‌లను తిరిగి పొందడానికి వీటిని ఉపయోగించండి, కొత్తవాటికి కాదు.

## అనువాదాలు

ఇంగ్లీష్ టెక్స్ట్ కోడ్‌లోనే ఉంటుంది: `t('menu', 'Delete')`, `tn('status', '{count} entry',
'{count} entries', n)`, అలాగే టెంప్లేట్‌లో `data-i18n="context"` / `data-i18n-attr="context"`.
మొదటి ఆర్గ్యుమెంట్ కాంటెక్స్ట్ — స్ట్రింగ్ చెందిన ఇంటర్‌ఫేస్ భాగం, కాబట్టి ఒకే ఇంగ్లీష్ పదాన్ని
రెండు చోట్ల వేర్వేరుగా అనువదించవచ్చు. `src/locales/<code>.json` అనే నిఘంటువు కాంటెక్స్ట్ →
ఇంగ్లీష్ టెక్స్ట్ → అనువాదం అనే మ్యాపింగ్‌ను కలిగి ఉంటుంది:

```json
{
  "menu": { "Delete": "Удалить" },
  "status": { "{count} entries": { "one": "{count} запись", "few": "{count} записи", "many": "{count} записей", "other": "{count} записи" } }
}
```

నిఘంటువులో లేని స్ట్రింగ్ ఇంగ్లీష్‌లో చూపబడుతుంది. సంఖ్య ఉన్న టెక్స్ట్‌కు భాషలోని ప్రతి బహువచన
వర్గానికీ (`Intl.PluralRules`) ఒక రూపం ఉంటుంది, ఇంగ్లీష్ బహువచన రూపమే దాని కీ. `npm run i18n`
ప్రతి భాషకూ ఇంకా అనువదించని స్ట్రింగ్‌లను, ఇక ఉపయోగంలో లేనివాటిని జాబితా చేస్తుంది; `npm test`
ప్రతి అనువాదం ఇంగ్లీష్ ప్లేస్‌హోల్డర్‌లను నిలుపుకుందో, అన్ని బహువచన రూపాలూ ఉన్నాయో తనిఖీ
చేస్తుంది.

Chrome ఎక్స్‌టెన్షన్ గురించి తాను స్వయంగా చూపించేది — దాని పేరు, వివరణ, టూల్‌బార్ బటన్
శీర్షిక — ప్యానెల్ భాషను కాకుండా, `chrome.i18n` ద్వారా బ్రౌజర్ భాషను అనుసరిస్తుంది. ఆ
టెక్స్ట్‌లు `src/extension/manifest.json`లోని ఇంగ్లీష్ టెక్స్ట్‌లు, అవే నిఘంటువులలో `manifest`
కాంటెక్స్ట్ కింద అనువదించబడతాయి; బిల్డ్ వాటిని `_locales/<code>/messages.json`కు రాసి, మానిఫెస్ట్‌లో
`__MSG_appName__` వంటివాటిని ఉంచుతుంది. Chromeకు సొంత కోడ్‌లు ఉన్నాయి, మిగతావాటిని అది
పట్టించుకోదు: `pt` `pt_BR`, `pt_PT`గా మారుతుంది, `zh` `zh_CN`గా మారుతుంది, ఉర్దూకు కోడ్ లేదు,
కాబట్టి అక్కడ Chrome ఎక్స్‌టెన్షన్ పేరును ఇంగ్లీష్‌లో చూపిస్తుంది. పేరు 75 అక్షరాలు దాటినా,
వివరణ 132 దాటినా బిల్డ్ ఆగిపోతుంది.

ఈ README కూడా అనువదించబడింది: `docs/readme/README.<code>.md`, ప్రతి భాషకూ ఒకటి, ప్రతిదాని
పైభాగంలో భాషల జాబితాతో. ఇక్కడ చేసే మార్పు అనువాదాల్లో కూడా చేయాలి.

## బిల్డ్

```sh
./build.sh         # installs the dependencies if needed, then builds build/password-manager.html
npm install
npm run build      # -> build/password-manager.html
npm run watch      # rebuild on changes in src/
npm run typecheck  # tsc --noEmit
npm test           # opening, editing and saving .kdbx files, the generator, TOTP, derived passwords, matching tabs, the dictionaries
npm run test:browser  # the built page and the extension in headless Chrome
npm run i18n       # strings each dictionary lacks or no longer needs
npm run check      # typecheck, test, build and test:browser in a row
npm run shots -- shots/after  # build, then screenshots of the main screens into shots/after
```

`build.mjs` `src/app/main.ts`ను esbuildతో IIFEగా బండిల్ చేసి, దాన్ని స్టైల్‌లతో, చిహ్నంతో (data
URI) పాటు `src/app/template.html`లో ప్రతిక్షేపిస్తుంది. Node కోసం ఉన్న kdbxweb ఫాల్‌బ్యాక్‌లు
(`crypto`, `@xmldom/xmldom`) ఖాళీ స్టబ్‌లతో భర్తీ చేయబడతాయి — బ్రౌజర్‌లో `crypto.subtle`,
`DOMParser` ఉంటాయి. ఫలితం `build/password-manager.html`, సుమారు 500 KB, అందులో నాలుగో వంతు నిఘంటువులు.

అదే రన్ `build/pages/`ను కూడా రాస్తుంది: ఆ పేజీయే ఇన్‌స్టాల్ చేయదగిన PWAగా — manifest లింక్,
పేజీకి తన workerను రిజిస్టర్ చేసుకోమని చెప్పే `<meta name="service-worker">`తో `index.html`,
`manifest.webmanifest`, చిహ్నాలు, పేజీ ఆఫ్‌లైన్‌లో తెరుచుకునేలా దాన్ని cache చేసే `sw.js`.
`build/password-manager.html` మాత్రం బాహ్య రిఫరెన్స్‌లు లేని ఒకే ఫైల్‌గానే ఉంటుంది.

అలాగే `build/extension/`: `panel.html` అనేది తన స్క్రిప్ట్ `panel.js`లో ఉండే టెంప్లేట్ — అదే
`src/app/main.ts`, `src/app/platform.ts` స్థానంలో `src/extension/extension.ts`తో (ఫైల్‌లో
`platform.ts` హుక్‌లు ఏమీ చేయవు) — దాని పక్కన `popup.html` (పేజీ స్టైల్‌లతో, `popup.css`తో),
`popup.js`, `background.js`, `offscreen.html`, `offscreen.js`, చిహ్నాలు, `manifest.json` (దాని
వెర్షన్ `package.json`దే). `build/password-manager-extension-<version>.zip`లో అవే ఫైల్‌లు, స్థిర
తేదీలతో ఉంటాయి: అవే సోర్స్‌లు అవే బైట్‌లను ఇస్తాయి.

`tests/extension.mjs` ఆ ఎక్స్‌టెన్షన్‌ను DevTools ప్రోటోకాల్ ద్వారా headless Chromeలోకి లోడ్
చేస్తుంది (pipe ద్వారా `Extensions.loadUnpacked`; వెర్షన్ 137 నుండి Chromeలో `--load-extension`
లేదు), లోకల్ సర్వర్‌లోని టెస్ట్ సైట్‌లను నింపుతుంది: సాధారణ ఫారమ్, React లాంటి ఫారమ్, వన్-టైమ్
కోడ్‌తో మూడు దశల సైన్-ఇన్, సైట్ సొంత ఫ్రేమ్‌లు, వేరే సైట్ ఫ్రేమ్‌లు, ఉచ్చుగా దాచిన ఫీల్డ్‌లు,
https ఎంట్రీ కోసం http పేజీ, లెక్కించిన v3 పాస్‌వర్డ్‌తో నింపిన రిజిస్ట్రేషన్ — ప్యానెల్ మూసి
ఉండగా, లాక్ తర్వాత కూడా; అలాగే పాప్‌అప్, అది అన్‌లాక్ చేస్తుంది, నింపుతుంది, వెతుకుతుంది,
కాపీ చేస్తుంది, లాక్ చేస్తుంది. DevTools నుండి కాంటెక్స్ట్ మెనూపై క్లిక్ చేయలేం, కాబట్టి
టెస్ట్ worker యొక్క `onClicked`ను స్వయంగా ప్రేరేపిస్తుంది; నిజమైన క్లిక్ లేకుండా Chrome
`activeTab`ను ఇవ్వదు, కాబట్టి పరీక్షించే కాపీ టెస్ట్ సైట్‌లను, `*.test`ను, host permissionsగా
చేరుకోవచ్చు. టూల్‌బార్ చిహ్నాన్ని DevTools నుండి క్లిక్ చేయవచ్చు (`Extensions.triggerAction`):
బిల్డ్ అయిన రూపంలోని ఎక్స్‌టెన్షన్‌తో ప్రత్యేకంగా నడిచే ఒక Chrome, ఆ క్లిక్ పాప్‌అప్‌కు ట్యాబ్‌ను
ఇస్తుందో లేదో తనిఖీ చేస్తుంది. Headless Chrome 153 ఎక్స్‌టెన్షన్ ఏదైనా సరే ఆ క్లిక్‌పై క్రాష్
అవుతుంది, అప్పుడు ఆ తనిఖీ దాటవేయబడుతుంది; Chrome for Testing దాన్ని నడుపుతుంది
(`CHROME=/path/to/chrome-for-testing npm run test:browser`).

`tests/fixtures/Database.kdbx` పరీక్షల కోసం ఒక నమూనా డేటాబేస్; దాని పాస్‌వర్డ్ `Тестовый пароль`.

## వెర్షన్‌లు, రిలీజ్‌లు

వెర్షన్ ఒకే చోట రాయబడుతుంది: `package.json`లో. బిల్డ్ దాన్ని పేజీలో (అన్‌లాక్ స్క్రీన్ కింది
లైన్, సెట్టింగ్‌ల కింది భాగం), ఎక్స్‌టెన్షన్ `manifest.json`లో, PWA cache పేరులో ఉంచుతుంది.
`v<version>` ట్యాగ్ ఉన్న commit బిల్డ్ దాన్ని ఉన్నది ఉన్నట్లే చూపిస్తుంది; ఇతర ఏ బిల్డ్ అయినా
తన commitను జోడిస్తుంది, `0.8.0+1a2b3c4`, కాబట్టి GitHub Pagesలో `main` నుండి వచ్చిన పేజీని
రిలీజ్‌గా పొరబడరు. Chrome `version`లో సంఖ్యలు మాత్రమే ఉంటాయి, కాబట్టి అక్కడ commit
`version_name`లోకి వెళ్తుంది.

```sh
npm version minor           # 0.7.2 -> 0.8.0: package.json, package-lock.json, a commit and the tag v0.8.0
git push --follow-tags      # the tag starts .github/workflows/release.yml
```

ట్యాగ్, `package.json` సరిపోలకపోతే రిలీజ్ workflow ఆగిపోతుంది, లేకపోతే
`password-manager-<tag>.html`, `password-manager-extension-<tag>.zip`, `SHA256SUMS.txt`లను
జతచేస్తుంది.

## GitHub Pages

`.github/workflows/pages.yml` `main`కు వచ్చే ప్రతి pushను బిల్డ్ చేసి పరీక్షిస్తుంది,
`build/pages/`ను GitHub Pagesకు deploy చేస్తుంది (Settings → Pages → Source: GitHub Actions),
<https://password.marketkernel.com/> చిరునామాలో. ఫైల్‌లు ఒకే ఫైల్‌లో లాగే
తెరుచుకుంటాయి; ఇటీవలి ఫైల్‌లు, సెట్టింగ్‌లు, గుర్తుంచుకున్న హ్యాండిల్‌లు ఆ చిరునామాకు చెందుతాయి,
డిస్క్ నుండి తెరిచిన కాపీవాటికి వేరుగా.

ప్రతి deploy `sw.js`లోని cache పేరును మారుస్తుంది, కాబట్టి బ్రౌజర్ కొత్త workerను తానే
అందుకుంటుంది — కనెక్షన్ ఉన్నప్పుడు ప్రారంభించినప్పుడు, లేదా సెట్టింగ్‌లు → "అప్‌డేట్‌ల కోసం
తనిఖీ చేయండి" అడిగినప్పుడు. కొత్త worker తన సొంత cacheలోకి తన వెర్షన్‌ను డౌన్‌లోడ్ చేసుకుని
వేచి ఉంటుంది; నడుస్తున్న worker పాత పేజీనే అందిస్తూ ఉంటుంది, ఆఫ్‌లైన్‌లో కూడా. అప్పుడు
సెట్టింగ్‌లు, అన్‌లాక్ స్క్రీన్ చెబుతాయి "వెర్షన్ … సిద్ధంగా ఉంది. అప్‌డేట్ చేయండి": అప్‌డేట్
చేయండి డేటాబేస్‌ను లాక్ చేస్తుంది (సేవ్ చేస్తూ, లేదా అడుగుతూ, ఏ లాక్ అయినా చేసినట్లే), కొత్త
workerను లోపలికి అనుమతించి పేజీని రీలోడ్ చేస్తుంది. బటన్ లేకుండా, యాప్ యొక్క ప్రతి విండో
మూసిన తర్వాత కొత్త వెర్షన్ తనంతట తానే మొదలవుతుంది. ఇదే దీని మూల్యం కూడా: ఇన్‌స్టాల్ చేసిన PWA
చివరి deploy అక్కడ ఉంచినదాన్ని నడుపుతుంది, డౌన్‌లోడ్ చేసిన ఫైల్ మాత్రం తన వెర్షన్‌గానే
ఉంటుంది. డిస్క్‌పై స్థిరంగా ఉండే వెర్షన్ కోసం, రిలీజ్ నుండి `password-manager-<tag>.html`ను
తీసుకుని `SHA256SUMS.txt`తో పోల్చండి.

`npm run test:browser` `build/pages/`ను కూడా తెరుస్తుంది: service worker పేజీని తన అధీనంలోకి
తీసుకుంటుంది, Chrome manifestను ఇన్‌స్టాల్ చేయదగినదిగా గుర్తిస్తుంది, సర్వర్ ఆగిపోయాక కూడా పేజీ
లోడ్ అయి నమూనా డేటాబేస్‌ను అన్‌లాక్ చేస్తుంది; తర్వాత ఒక కొత్త deploy కనుగొనబడుతుంది, వేచి
ఉంటుంది, అప్‌డేట్ చేయండి దాన్ని లోపలికి అనుమతిస్తుంది.

## పరిమితులు

- KDBX 3.1, 4.xలకు సపోర్ట్ ఉంది; Twofishతో ఎన్‌క్రిప్ట్ చేసిన ఫైల్‌లకు, KeePass 1 (`.kdb`)
  ఫైల్‌లకు లేదు.
- సింక్, ఆటో-టైప్, మార్చిన కాపీలను విలీనం చేయడం లేవు.
- ఎక్స్‌టెన్షన్ Chrome కోసం మాత్రమే; దానిలో ఫీల్డ్‌లలో సూచనలు, ఫారమ్ పంపినప్పుడు పాస్‌వర్డ్‌ను
  సేవ్ చేయడం, కీబోర్డ్ షార్ట్‌కట్ లేవు, ఒక్కో ఎంట్రీకి ఒకే వెబ్‌సైట్.
- Chromium ఆధారిత బ్రౌజర్‌లు మాత్రమే ఫైల్‌ను అదే స్థానంలో రాయగలవు.
